## 1. 范围与目标

| 页面 | 路由 | 回答的问题 | 本方案 |
| --- | --- | --- | --- |
| 用例管理 | `/` | 评测集里有哪些用例，在默认配置下各自表现如何，哪些需要处理 | 重排 |
| 用例页 | `/case/{id}` | 这道题考什么，在默认配置下表现如何 | 重写 |
| 对话页 | `/case/{id}/conversations` | 各配置分别表现如何，是哪几段对话、各自怎么判的 | 新增，从现有用例页拆出 |
| 复核队列 | `/review` | 哪些对话需要人判 | 重排 |
| 复核页 | `/review/{answer_id}` | 这段对话该判什么结论 | 重排 |
| 配置管理 | `/configs` | 有哪些被测配置，哪个是默认配置，各叫什么名字 | 扩展，作为配套页面 |

不在本方案范围内的页面：执行记录、结果对比、判定质量。这三页只需同步配置名的写法，以及从本方案各页跳过去的链接。

**目标**

1. **每页只回答一个问题。** 主区只放回答这个问题所需的内容，其余内容下沉到下一层。
2. **分数默认只看默认配置。** 用例管理和用例页都只显示默认配置的分数。要看各配置的结果，进对话页。默认配置在配置管理里设定。
3. **对话按「配置 → 执行记录 → 采样」组织。** 页面上一律写「执行记录名 · 采样 #n」，不再出现含义不清的「第 n 次」。
4. **全站一套视觉语言。** 页头、摘要条、筛选胶囊、列表行、分数块、阅读区都用同一组部件，见 §3。
5. **改动收敛。** 只新增一张小表 `config_meta`，判定和评分口径都不变。

## 2. 信息架构

```
侧边栏：用例管理 · 配置管理 · 执行记录 · 复核 · 结果对比 · 判定质量
用例管理 /
└─ 用例页 /case/{id}                               结构 + 默认配置一行
   └─ 对话页 /case/{id}/conversations              配置栏 + 对话列表 + 阅读区
      └─ 复核页 /review/{answer_id}?from=conv      改判单段
复核 /review                                       队列：按用例分组的待处理对话
└─ 复核页 /review/{answer_id}?tab=…                逐段改判，提交后进入下一段
配置管理 /configs                                  默认、命名、分组、对比入口
```

### 2.1 对话的归属层级

层级与库里的字段一一对应：

```
被测配置  config_key = CONFIG_ATTRS（profile · model · skills_mode · skills_base · evalset_version）
└─ 执行记录  run_id（runs 表；可命名 runs.title；有执行时间；可能被标为「技能基底过期」，见 stale_runs）
   └─ 对话  answer_id = {run_id}/{uid}-{mode}-t{trial}
            uid：用例的变体（#0 种子、#1 口语 …）
            mode：natural / forced
            trial：本次执行内的第几次采样（runner --trials，默认 3）
```

- **一个配置可以有多次执行。** 同一个配置的重跑、补跑都会新增执行记录。
- **用例分的算法，本方案不改。** 先在每个变体内，对该配置**所有执行**里有确定分数的对话取平均；再对非诱导变体等权平均。这是现有 `question_scores` 和 `case_scores` 的做法。
- **n** 是参与平均的对话段数，等于「执行次数 × 采样次数 × 计分变体数」再减去待定和无效的段数。
- **「采样 #n」** 只在同一次执行内部有意义，所以页面上总是和执行记录名写在一起。

### 2.2 默认配置

按以下顺序确定：

1. 配置管理里设为默认的那个配置，前提是它在当前数据里还存在；
2. 否则取 `configs_of` 返回的第一个，与首页现在的行为一致。

用例管理和用例页都用默认配置计算分数。首页现有的 `config` 参数保留，用来临时查看其他配置：此时摘要条左端改写为「临时查看：配置名 · 回到默认」，但不改变默认配置本身。

### 2.3 配置名

按以下顺序取：

1. 配置管理里起的名字；
2. 否则由**差异属性**拼成，用 · 连接。

差异属性的取法：

- **候选属性**：模型（`models`）、努力程度（profile content 的 `reasoning_effort`）、技能方式、知识基底、评测集版本。不用 profile id：努力程度已经合进 profile id 里，直接显示是一长串字符。
- **共同属性不写进名称**：在当前范围内所有配置取值都相同的属性，提到表头或栏头作为「共同属性」。当前范围在对话页是这个用例的全部配置，在配置管理是全部配置。
- **兜底**：如果所有候选属性都相同、只有 profile 不同，就用 profile id。

## 3. 样式规范

### 3.1 原则

1. **线和底色分层，不靠卡片。** 页头和区块标题不套卡片。卡片只用于三类东西：可点击的单元（配置卡、维度块），需要和背景分开的工作区（列表 + 阅读区、评分表），以及摘要条。
2. **数字先于文字。** 分数用等宽字体和表格数字，左对齐成列；每个分数都配一根带及格线的细条，或者一个着色的分数块。
3. **颜色只表达结论和操作。** 结论用结论色，操作、当前项和待人处理的东西用强调色，流程状态用提示色，其余一律用中性色。
4. **同一种东西在各页长得一样。** 对话页的列表行和复核队列的行，用的是同一个分数块和同一套标题写法。用例页的摘要条和用例管理的摘要条，也是同一个部件。
5. **不靠动画传达状态。** 只在悬停和展开时有 150ms 的颜色或旋转过渡，没有位移动画。

### 3.2 Token

沿用 `scoring/static/tokens.css`，**不新增、不修改**。浅色和深色两套值由 `[data-theme]` 和 `prefers-color-scheme` 切换，这一部分已经在 feat/eval-gaps 上实现。

**颜色语义**（本方案统一了「待定」的颜色）：

| 含义 | Token | 用在 |
| --- | --- | --- |
| 通过；对、满足、成立、未采信 | `pass-soft` 底 / `pass-ink` 字 / `pass-solid` 实心 | 分数块、结论徽标、细条填充、已选中的结论按钮 |
| 失败；错、违反、采信、未提及 | `fail-*` | 同上 |
| 部分 | `partial-*` | 条目结论「部分」 |
| **待定**（会话分区间跨过及格线）、**未决**（机器弃权）、**待判** | `accent-soft` 底 + 1.5px `accent` 描边 + `accent-ink` 字 | 分数块、结论徽标、评分行左侧色条、待判芯片 |
| 无效、不判 | `neutral-*` | 分数块「—」、路径「不判」 |
| 异常 | `error-*` | 会话异常；「技能基底过期」标记 |
| 草稿、待重判、原型提示 | `notice-*` | 结论条的草稿描边、评分行「草稿」标签、待重判横幅 |
| 操作、当前项 | `accent`、`accent-soft`、`bg-selected` | 链接、主按钮、当前配置卡、选中行、焦点环 |
| 关键词命中 | `mark-hit` | 复核页里聚焦条目的关键词高亮 |
| 注入后的文字 | `mark-forbid` | 属性栏「知识注入」 |

v3 原型里，对话列表的待定分数块用的是 `partial` 赭黄色，和条目结论「部分」撞色；本方案改用强调色，与 `.rv-verdict[data-tone=undecided]` 一致。

### 3.3 字体与数字

| 层级 | 字号 / 行高 / 字重 | 用在 |
| --- | --- | --- |
| 页面标题 | 26 / 34 / 650 | 用例管理、用例页、复核队列、配置管理的 `h1`。标题后面的 `small` 为 15 / 500，颜色 `ink-2` |
| 工作页标题 | 20–22 / 28–30 / 650 | 对话页的 `h1`；复核页的 `h1` 用等宽字体写用例号 |
| 区块标题 | 16 / 24 / 650 | 「题面与期望」「评分表」 |
| 属性栏小标题 | 12 / 600 | 颜色 `ink-3`，字距 .02em |
| 正文 | 14 / 22 | 表格、条目文字 |
| 对话正文 | 14–14.5 / 23–24 | 提问气泡、助手回答 |
| 辅助文字 | 12–13 / 18–20 | 元信息行、计数、提示 |
| 大数 | 20–26，等宽，600 | 摘要条、维度块、结论条 |
| 表内数字 | 13–15，等宽，表格数字 | 分数、n、比例 |

字体族沿用 tokens 里的 `--font-sans` 和 `--font-mono`。所有数字都用 `font-variant-numeric: tabular-nums`。最小字号 11px，只用于分数块和标记里的小字。

### 3.4 间距、圆角、阴影

- **间距**：4 的倍数，即 `space-1` 到 `space-6`（4、8、12、16、24、32）。页面四周留 24px，窄屏时缩到 12–16px；区块之间 24–32px；列表行的内边距为 10px × 14–16px。
- **圆角**：标记和标签 3–4px；控件和分数块 `radius-md`（6px）；卡片、摘要条、工作区 `radius-lg`（10px）；筛选胶囊、计数和芯片 `radius-pill`。
- **阴影**：只有两档。`shadow-card` 用于分段控件中被选中的那一项；`shadow-sticky` 用于吸顶的结论条、下拉菜单和提示条。

### 3.5 布局

**外壳**：沿用 feat/eval-gaps 的竖直侧边栏（`.rv-app--side`）。

| 宽度 | 侧边栏 |
| --- | --- |
| > 900px | 210px |
| 641–900px | 176px |
| ≤ 640px | **收成顶栏**，本方案新增：品牌名和配色切换在第一行；导航在第二行，横向滚动；判定配置下拉收起，到判定质量页去切换 |

**内容宽度**：

| 页面 | 最大宽度 | 原因 |
| --- | --- | --- |
| 用例页 | 1200px（`.rv-cp`） | 阅读型页面，行不宜过长 |
| 用例管理、对话页、复核队列、复核页、配置管理 | 1440px（`.rv-cp--wide`） | 工作型页面，要多列并排 |

**各页的栅格**：

| 页面 | 栅格 | 宽度 < 1100px 时 |
| --- | --- | --- |
| 用例管理 | 摘要条（弹性格子）→ 维度块 `repeat(auto-fit, minmax(min(220px,100%),1fr))` → 筛选条 → 表格（左列固定，横向滚动） | 不变 |
| 用例页 | 主体 `minmax(0,1fr) 320px`，属性栏 `sticky` | 单列，属性栏排到下方 |
| 对话页 | 配置栏 290px（`sticky`）+ 对话区；对话区内为列表 340px + 阅读区 | 单列：配置栏 → 列表 → 阅读区 |
| 复核队列 | 单列；行为 `64px 1fr auto auto` | 待判芯片换到第二行 |
| 复核页 | 结论条（吸顶）→ 对话 `minmax(0,1fr)` + 评分表 `minmax(380px,440px)`（`sticky`） | 单列，评分表排到下方；宽度 ≤ 760px 时结论条不再吸顶 |

**横向溢出**：所有栅格列都写 `minmax(0, …)`，长文字用省略号截断，表格放进 `.rv-table-wrap` 横向滚动。原型在 390px 宽度下逐页检查过，六个页面都没有横向溢出。

| 结论按钮 | `.rv-picker--sm .rv-opt` | 每个按钮上写数字键、结论词和分值，选中后用对应的实心色 |
| 过期标记 | `.rv-rs-stale` | 小号的 `error-soft` 胶囊，写「技能基底过期」，空间不够时只写「过期」 |
| 提示条 | `.rv-cv-toast` | 页面底部居中，出现 1.8 秒；只用于操作反馈，不用来报错 |

### 3.7 状态

| 状态 | 表现 |
| --- | --- |
| 悬停 | 可点击的行或卡片：底色变为 `bg-page` 或 `bg-surface`，或者描边变为 `line-strong`。链接加下划线 |
| 当前或选中 | `aria-current`、`aria-selected` 或 `aria-pressed`：强调色描边或左侧 3px 强调色线，配 `accent-soft` 或 `bg-selected` 底色 |
| 焦点 | 2px `focus` 实线环，偏移 2px（沿用现有规则） |
| 禁用 | 透明度降低，不响应点击。例如「并排对照 0/2」「对比选中的 2 个配置」「提交」（没有草稿时） |
| 临时 | 分数后面跟「临时」小字：区间未定的对话被排除在平均之外 |
| 样本少 | n < 3 时，n 下面加虚线，悬停提示「样本少于 3 段，分数仅供参考」 |
| 过期 | 执行记录被标为技能基底过期时，在它出现的地方都加 `.rv-rs-stale` |
| 待重判 | 期望版本还没有判定：摘要条只保留配置名和 `rejudge` 命令，不再拿旧分数配新期望显示 |
| 评分行·待判 | 左侧强调色条，标签「待判」 |
| 评分行·草稿 | 左侧提示色条，标签「草稿」 |
| 评分行·人工 | 左侧淡强调色条，标签「人工」（强调色描边） |
| 评分行·机器 | 没有色条，标签「机器」 |
| 评分行·不判 | 整行淡显，例如 forced 会话的路径条目 |
| 空 | `.rv-empty`：先说为什么是空的，再给下一步，例如「清除筛选」 |

### 3.8 文案

- **对话的写法**：「#1 口语 · 采样 #2 · forced」。在列表中按执行记录分组时，行标题里省略执行记录名；按变体分组或在队列中时，写成「执行记录名 · 采样 #2」。不写「第 n 次」。
- **状态词分三层，不混用**：
  - **会话结论**：通过 / 失败 / **待定** / 无效 / 异常。现在 `_STATUS_LABELS` 里写的是「未决」，本方案改为「待定」，与队列标签「结论待定」一致。
  - **条目的机器结论**：结论词本身，或者**未决**（算子弃权）。
  - **条目在复核页上的状态**：待判 / 草稿 / 人工 / 机器 / 不判。
- **数字**：用例分、维度分、综合分保留一位小数；会话分写整数；区间写「34–67」；比例写百分比；「通过」一列写「11 / 12」。
- **元信息的顺序**：配置名 · 执行记录名 · 时间。悬停时显示 `run_id`。
- **链接文字**：用「去哪里 →」的写法，例如「去复核 →」「用例页 →」「在对话页中查看」。

### 3.9 键盘

| 页面 | 键 |
| --- | --- |
| 对话页 | ↑ ↓ 换段 · 空格 选入并排对照 · Enter 进入复核 |
| 复核队列 | ↑ ↓ 或 J K 换行 · Enter 打开 |
| 复核页 | J K（或 ↑ ↓）换条目 · 1–9 选结论 · N 输入分数 · Y 同意机器 · E 写理由 · T 手改总分 · [ 上一段 · ] 跳过 · Ctrl+Enter 提交 · Esc 离开输入框 |
| 用例页 | 权重编辑模式下，在滑杆上用 ← → 每次调 1% |

按键说明常驻在复核页评分表的底部。焦点在输入框里时，单字母键不生效。

### 3.10 深色模式与可访问性

- 全部颜色都取自 token，深色模式不需要另写样式。原型的深色截图已经检查过。
- 每个结论都同时有颜色、文字和符号；类型图形靠形状（方块 / 圆、实心 / 空心）区分，不只靠颜色。
- 列表用 `role=listbox` 和 `role=option`，配合 `aria-selected`；结论条 `aria-live=polite`；勾选框和图标按钮都带 `aria-label`。

### 4.2 区块

- **摘要条**：用 §3.6 的「摘要条」部件，从左到右依次是：
  - **默认配置**：配置名，上方小字写「来自 k 次执行」，下面是「在配置管理中更改」；
  - **综合分**：数字加「临时」标记；细条；下面写「n 个维度等权」；
  - **结论待定**：默认配置下的待定段数；下面写「全部配置共 n 段 · 去复核 →」；
  - **待重判**：段数，加一句原因；
  - **用例体检**：有标记的用例数；「只看这些 →」把用例表筛选为有体检标记的用例。

  取代现有的「综合分卡 + 三个统计磁贴」。
- **维度块**：每个维度一块，写维度名、用例数、维度分（附「临时」标记）和细条。点击切换「维度」筛选，可以多选。它取代综合分卡里逐维度的那几行。
- **筛选条**：搜索框匹配用例号和考点，可以输入多个词。筛选胶囊依次是维度、粒度、状态（只看有待定 / 只看有体检标记）、排序（待定多在前 / 用例分低在前 / 用例号）。最右边写计数和「清除筛选」。
- **用例表**：一行一个用例，点击整行进入用例页。列定义如下：

| 列 | 内容 | 来源 |
| --- | --- | --- |
| 用例 | 用例号（等宽字体，链接），下面一行写考点，过长截断 | `case_id`；考点取 spec 的标题，没有标题时取第一句提问的前 20 字 |
| 维度、粒度 | 文字 | spec |
| 变体、轮次 | 数字 | 成员数；spec 的 `turns` |
| 用例分 | 分数（等宽字体，不及格用失败色）+「临时 · n」+ 细条 | `case_scores`，按默认配置计算 |
| 通过 | 通过段数 / 计分段数 | 默认配置下非诱导变体的对话 |
| 待定 | 段数，用 `.rv-state[data-s=need]` 框起来；为 0 时写「—」 | 默认配置 |
| 稳定性、区分度、题组一致 | 百分比或数字，列头悬停显示定义 | `views.question_stats`。区分度本来就是跨配置的指标，列头注明「跨全部配置」 |
| 体检 | `.rv-flag` 标签 | `views.case_health` |

去掉现有的「难度」列：难度等于 1 − 通过率，与「通过」列重复，定义改写进「通过」列头的悬停说明。

### 4.3 URL 参数

参数沿用现有的 `dim`、`topic`、`granularity`、`sort`、`flag_only`、`page`、`config`，新增两个：`q`（搜索）和 `pending_only`（只看有待定）。`dim` 可以重复，表示多选。缺省值不写进 URL。

  1. 数字是这个用例在默认配置下的结果；
  2. 「待定」格的下一行写「全部配置共 n 段 →」；

### 5.2 题面与期望

时间线上依次是：提问气泡、改写行（选「全部」时，在气泡下面列出各变体改写了哪一句）、条目行（整行点击，在原位展开详情）。参考答案默认折叠。

**退化规则**（真实评测集里，单轮、单变体的用例占多数）：

| 情况 | 显示 |
| --- | --- |
| 单轮，或所有条目都没有标轮次 | 不画编号圆点和竖线，直接显示「提问 + 条目列表」。v20261024-1 的 14 个用例里有 11 个属于这种情况 |
| 多轮，但只有部分条目标了轮次 | 标了轮次的条目归到对应轮次下；没标的放在最后的「整段」块里 |
| 只有种子，没有改写变体 | 不显示分段控件 |
| 有不计分的改写方式（如诱导） | 按钮上标「不计分」。真实评测集里目前只有「口语」一种改写方式，原型里的「诱导」只是演示 policy 支持的能力 |

### 5.3 属性栏

从上到下依次是：权重分配、条件、知识注入、证据、备注、标签。

**权重的编辑模式**：

- **平时**：只显示环图和各条目的百分比，不能修改。
- **点「编辑权重」后**：整块铺上 `accent-soft` 底色，出现滑杆；数值可以双击直接输入，滑杆获得焦点后可以用 ← → 微调。按钮变为「保存为新期望」和「取消」。
- **保存后**：页头的期望版本切到新版本。新版本还没有判定，所以摘要条改为「期望版本 xxxx 还没有判定」加 `rejudge` 命令。

**字段来源**：属性栏里的字段**都不是运行结果**，全部来自用例 md 编译出的那一行（`md2case.py` 生成 `evalset/dist/*.jsonl`，导入后存在 `specs.spec_json` 里），并随页头所选的期望版本切换。

| 字段 | 用例 md 写法（CASE-STRUCTURE.md） | 编译后的字段 | 说明 |
| --- | --- | --- | --- |
| 权重分配 | 事实行尾 `【权重：N】`（§2.9） | `facts[].weight`；在页面上编辑后写入 `weight_percent` | 不写时按 1。在页面上编辑会生成新的期望版本，原 md 不变 |
| 条件 | `## 关键条件`，每行可带 `【对象】【轮次】【关键词】`（§2.6） | `conditions[]`：`slot / value / object / turn / keywords` | 用于审阅和变体泄露检查，不参与打分 |
| 知识注入 | `## 注入`，写 `@注入点/选项`（§2.7）；注入点定义在 `knowledge/*.yaml`（§3） | `injections[]`：`id / point / option / rev / file / key / value` | 「原文 → 注入后」就是 yaml 里的 `key` → 所选选项的 `value`。注入在某段对话里是否生效，看复核页的注入观测 |
| 证据 | `## 证据`（§2.11） | `evidence[]`：`id / doc{skill,file} / section / quote` | 事实行用 `【证据：Rn】` 引用；写 `【外部】` 表示资料外 |
| 备注 | `## 备注`（§2.14） | `note` | 写给审阅人看，不参与评测 |
| 标签 | frontmatter 的 `tags`，加上所引注入点的 `tags`，经 `mapping.yaml` 规范化（§4） | `tags[]`：`tag / from` | `from` 记录标签来自用例本身，还是来自某个注入点 |

唯一来自运行结果的是**用例体检**，由 `views.case_health` 计算，所以放在摘要条里，不放在属性栏里。

**配置栏**（`.rv-rs-rail`，吸顶）

- 顶部依次是排序（按用例分 / 按名称）、搜索框（可以输入多个词）和「共同属性」一行。
- 第一项是「全部配置」，然后是各个配置；默认配置置顶，并标 ★。
- 每个配置是一张配置卡（§3.6）。勾选两张后，「对比选中的 2 个配置 →」变为可用，跳转到 `/compare`，并限定在这个用例上。
- **只统计当前期望版本**：配置栏的分数和对话列表都只包含页头所选期望版本下的对话。其他期望版本的对话，在配置栏底部写「另有 n 段属于其他期望版本」，点击切换到那个期望版本。

**对话区**

- **执行记录下拉**：列出所选配置下的每次执行，写明执行名、时间和段数，过期的执行加标记。下拉里有三个快捷项：全部 / 每个配置只看最近一次 / 排除技能基底过期。
- **分组**：默认按执行记录分组，新的在前。组头写执行名、时间和段数；选「全部配置」时，组头再加配置名。
- **列表行**：写法见 §3.8。条目结论写在第三行，如「F1 部分 · E1 未判 · X1 未采信」。
- **被隐藏的变体**：诱导等不计分的变体默认不显示，被隐藏的组折叠成一行「#2 诱导 · 6 段未显示 · 显示」。
- **阅读区**：只读。右上角是「进入复核 →」，底部写键盘提示。
- **并排对照**：勾选两段后点「并排对照」，阅读区改为左右两栏，两栏的栏头写法与阅读区标题相同。
- **何时生效**：筛选下拉在关闭菜单时统一提交一次，不再每勾一个选项就刷新一次。

### 6.3 取数

- **配置栏**：用 `views.case_scores` 和 `question_scores` 按配置分组计算，同时返回 n、各变体的均分，以及每个配置的执行记录（`run_id`、命名、时间、是否过期）。数据只取 `answer_view_rows`，按页头所选的期望版本过滤（`current_judge_fp == judge_fp`）。
- **对话区**：
  - 按 `run` 参数过滤，按 `run_id` 分组；分组顺序按执行时间排，取 `runs.started_at`，没有时取 `imported_at`。
  - 条目判定用批量查询 `effective_rows_many`，每页 50 段。
  - 阅读区复用 `_review_ctx`；并排对照沿用现有的 `pair_data` 和 `pair_rows`。

**页头**

- 面包屑写队列标签和位置。从对话页进入时写「复核 / 从对话页进入 / 用例号 · 变体 · 采样」，并隐藏「跳过」。
- 标题是用例号（等宽字体），后面的 `small` 写「变体 · 采样 #n · mode」。
- 元信息行依次是：维度、主题、配置名、执行记录名和时间（过期的加标记）、期望版本、注入是否生效。它取代现有的 `runtag` 胶囊串。被测模型、努力程度和 profile id 在配置名里已经有了；profile id 和 run_id 改为悬停显示。

**结论条**（吸顶）

- 左边是大号分数或区间，加会话结论徽标。
- 中间是计算式，例如「F1 67% × 50 + E1 33% × ?：区间 34–67 跨过及格线 60」，下一行写还有哪些条目未判，条目编号可以点击。
- 有草稿时，结论条用提示色描边，中间写「~~已保存 34–67 待定~~ → **草稿预览** …」，主按钮变为可用。
- 右边依次是「手改总分 T」和「提交并下一段 Ctrl↵」。从对话页进入时，主按钮只写「提交」，提交后回到对话页。

**对话栏**

- 每轮一张卡片。卡片头写轮次、观测信息（技能是否加载、注入是否观测到、改写了哪一轮），右边是这一轮的**条目芯片**。
- 评分表里聚焦哪一条，对应的那一轮就用强调色描边，回答里命中该条关键词的文字用 `mark-hit` 高亮。关键词取条目的 `keywords`。
- 参考答案默认折叠，放在最后。

**评分表**（吸顶，自己滚动）

- 条目按判定顺序分节：前提 → 路径 → 禁止 → 必要 → 期望。每条一行，行的结构见 §3.6，状态见 §3.7。
- 机器结论行依次是：结论徽标（附分值）、来源（规则 / 模型）、算子名和理由；有 `trace_json` 时可以展开。
- 已有人工结论时，另起一行写人工结论、评审人和理由。
- 结论按钮的每个选项上都有数字键。「同意机器」会提交一条与机器取值相同的人工记录。
- 只有聚焦的那一行显示理由输入框。
- 表尾依次是：会话分的大号数字和计算式；作废的人工分数（期望或回答已变）；键盘说明。

**草稿与提交**：沿用现有接口，交互不变。

- 选值后先成为草稿，由 `POST /api/review/preview` 重算结论条。
- 提交用 `POST /api/reviews`，一次提交本段的全部草稿。
- 提交成功后进入队列的下一段；失败时在结论条下方显示错误横幅，草稿保留。
- 离开有草稿的页面时，浏览器会提示。

**与现有 `review.html` 的差异**（只改模板、样式和脚本，不改接口）：

| 项 | 现在 | v1.0 |
| --- | --- | --- |
| 被测信息 | 一串 `runtag` 胶囊，含「第 n 次」 | 一行元信息：配置名 · 执行记录名 · 时间；标题里写「采样 #n」 |
| 结论 | `.rv-concl` 卡片随页面滚走 | 吸顶的结论条，带草稿预览和主按钮 |
| 条目与对话的对应 | 轮次头部只有 `rv-turn-items` 占位 | 每轮都有条目芯片，点击可以聚焦对应条目；聚焦后那一轮描边，关键词高亮 |
| 评分行状态 | `rv-state` 文字 | 左侧色条加状态标签（待判 / 草稿 / 人工 / 机器 / 不判） |
| 上一段 / 跳过 | 只能用键盘 | 页头有按钮，也可以用键盘 |
| 去用例 | 「用例详情 →」 | 「用例页」和「在对话页中查看」 |

## 12. 已定与留到后续

**已定**

1. 用例管理和用例页只显示默认配置的结果；各配置的结果和对话都放在对话页。
2. 默认配置在配置管理里设定，全局唯一；没有设定时，回退到 `configs_of` 的第一个。
3. 配置名优先用命名，其次由差异属性拼成；「努力」取自 profile content，页面上不显示 profile id。
4. 对话一律按「配置 → 执行记录 → 采样」组织，写法是「执行记录名 · 采样 #n」。
5. 对话页只统计当前期望版本下的对话。
6. 诱导等不计分的变体默认隐藏，被隐藏的组折叠成一行。
7. 权重平时只读，点「编辑权重」后才能修改；保存后显示「待重判」，不再拿旧分数配新权重显示。
8. 会话状态 undecided 的显示词由「未决」改为「待定」；条目的机器弃权仍写「未决」。
9. 待定统一用强调色描边，不再用赭黄色。
10. 复核页的结论条吸顶；条目芯片和评分行双向聚焦。
11. 宽度 ≤ 640px 时，侧边栏收成顶栏。
12. 用例表去掉「难度」列。

**留到后续**

- 对话页、复核队列的筛选改为局部刷新，不再整页刷新。
- 配置超过 30 个时，配置栏按差异属性折叠分组。
- 复核页的「手改总分」改为弹出面板，现在是键盘 `T` 加行内输入。

## 13. 原型说明（`13-界面原型.html`）

| 页面 | 可以操作 |
| --- | --- |
| 用例管理 | 点维度块筛选；搜索（可以输入多个词）；维度、粒度、状态、排序下拉；「只看这些 →」只看有体检标记的用例；「去复核 →」进入复核队列，筛选为默认配置；点 ec-0201 这一行进入用例页（其他行弹出提示） |
| 用例页 | 分段控件；条目展开；「编辑权重」后拖动滑杆或双击输入，再保存或取消（保存后摘要条显示「待重判」）；「对话与各配置结果 →」 |
| 对话页 | 配置栏的选中、搜索、排序和对比勾选；执行记录下拉及三个快捷项；分组；其他筛选；「显示」被隐藏的变体；单击一行查看；并排对照；「进入复核 →」；键盘 ↑ ↓、空格、Enter |
| 复核队列 | 标签（只有「结论待定」有数据）；配置、用例、分组、排序筛选；「开始复核 →」；点一行的「复核 →」（ec-0201 的行可以打开，其他用例弹出提示）；键盘 J、K、Enter |
| 复核页 | 点条目芯片或评分行来聚焦，对应的那一轮描边，关键词高亮；点结论按钮或按 1–4 形成草稿，结论条显示草稿预览；Y 同意机器；E 写理由；Ctrl+Enter 提交后进入下一段，队列计数随之减少；[ 和 ] 换段；「在对话页中查看」 |
| 配置管理 | 搜索；分组；设为默认（用例管理和用例页随之切换）；命名；勾选两个配置去对比 |

**示例数据**

- **用例**：14 个，用例号、维度、粒度、变体数与 v20261024-1 一致。考点是概括的说法；除 ec-0201 外，各用例的分数都是示例值，随默认配置平移。
- **配置**：8 个被测配置，即 2 个模型 × 3 档努力程度（知识基底 base-1024），另加 2 个用旧基底 base-1020 的配置。
- **执行记录**：11 次执行，每次 × 3 个变体 × 3 次采样，共 99 段对话。
- **复核队列**：ec-0201 的待定对话来自同一份数据；其余用例的 7 段只用来展示队列，不能打开。
- **算子**：现在的 `operators.yaml` 里，禁止和前提两类条目没有算子，只能人工判。原型假定模型算子 `llm-forbid` 和 `llm-precond` 已经接入，用来展示「模型」来源的样子。

**原型没有演示的内容**

- 复核页：N 键输入分数、手改总分、作废的人工分数；
- 单轮、单变体用例的退化显示；
- 对话页的分页；
- 「另有 n 段属于其他期望版本」的切换。

这些内容按正文实施。
