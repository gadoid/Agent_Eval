# Agent_Eval 评测业务过程文档

版本：v3.3（2026-10-29）——v3.2 的修订见 [01-业务过程总览.md](01-业务过程总览.md) 第 11 节；计分与权重按 [17-条目计分与权重改造方案.md](17-条目计分与权重改造方案.md) 执行（已实施）。**开工前先看 01 第 2 节的两项阻断前置条件。**

本目录定义 Agent_Eval 项目自动化评测的**业务过程**：从 markdown 用例到可分析结果，各环节做什么、产出什么、门禁在哪里、谁负责。

- 用例**怎么写**（段落、语法、字段语义）不在本目录重复定义，以 [CASE-STRUCTURE.md](CASE-STRUCTURE.md)（版本 2026-10-22）为唯一规范。
- 本目录回答的是**过程**问题：编写、校验、编译、准入、规划、执行、注入、请求、采集、装配、判定、反馈。

## 与既有资产的关系

本设计基于两份输入重构：

1. **CASE-STRUCTURE.md（2026-10-22）**：用例结构 v2——knowledge 注入点、前提、期望/禁止事实、路径、证据、变体改写，以及「md 唯一数据源、编译后执行器不再解析、随行字段原样带出」四条原则。
2. **昨日验证项目（evalcase，2026-10-21）**：`md2case.py` 编译器 + `skill-eval-runner` 执行器（dsh-cli / web-ui 双适配器、natural/forced 干预、四类探针、results.jsonl / run.json 契约、scoring.py 离线打分），已在真实 ElineAI 链路上完成现场验证（field-verify-eline / web 系列 run）。

沿用与变更的逐项对照见 [01-业务过程总览.md](01-业务过程总览.md) 第 8 节。

## 术语

术语含义一律以 CASE-STRUCTURE.md 为准（用例/种子/变体、注入点/选项/rev、必要/期望/禁止事实、前提、路径、证据、维度）。执行侧术语沿用昨日项目：Episode（一段会话 = 用例 × 干预 × trial）、Profile、AgentAdapter、Intervention、Probe、EpisodeRecord、run.json。

本目录新增的口径术语：

| 术语 | 含义 | 定义处 |
|---|---|---|
| 前置条件 P0-1 / P0-2 | 隔离机制现场验证 / 生产可见 skill 盘点；完成前 ec 不运行 | 01 第 2 节 |
| 评测基底 | 盘点得到的生产可见 skill 根（Profile `skills_roots`），所有会话的 skill 副本来源 | 01 第 2 节；03 第 5.2 节 |
| 环境快照 | run 开始时工具自动计算的一组哈希（评测集、两侧 profile、基底、agent、观测到的模型、judge）；不是门禁，只用于解释数字变化 | 01 第 5 节 |
| 锚点 | `runner/anchors.txt` 中的固定 uid，全量 run 默认纳入，用作绊线 | 02 第 5 节；04 第 7 节 |
| 注入预演 | 规划期对基底只读预演 key 命中，found=0 提前跳过 | 03 第 3 节 |
| 前提成立率 | 前提成立会话 / 运行 ok 会话；forced 下解释为 ec 的注入生效率 | 04 第 6.1 节 |
| 主口径 | 各维度报告的 headline 指标；ec 在 prefill 前取 forced | 01 第 8 节 |
| natural 三分归因 | 未加载 / 误加载 / 加载但答错 | 04 第 6.3 节 |
| 规模分级 | 按 dist 用例数（< 50 / ≥ 50）决定统计、锚点、复核的强度 | 01 第 9 节 |
