# 使用手册

v1.0（2026-10-22）· 面向评测执行者的操作手册

本手册讲"怎么用"，设计与口径见同目录其他文档：业务过程（01）、用例结构（CASE-STRUCTURE.md）、执行链路细节（03 §7.1）。**当前结论性口径：执行链路驱动 ElineAI 客户端自带的改造版 dsh（0.2.0-rc.6），不脱离 ElineAI 服务链路发起会话；npm 通用 dsh 仅作应急备份。**

```text
md 用例 ──build──> evalset.jsonl ──run──> 会话执行（eline 自带 dsh）
   ^                                    │
   └────────── rev 联动降级 ←── 注入/改写 ←┘
                                        v
                          results.jsonl ──score/compare──> scoring.json / 对比报告
```

## 1. 环境与前置条件

| 依赖 | 要求 | 检查方式 |
|---|---|---|
| Node.js | ≥ 22.15（内置 zstd 解压） | `node -v` |
| Python | ≥ 3.10 | `python --version` |
| ElineAI 客户端 | 装在 `D:\eline-ai`（提供 eline.exe 与 app.asar 内的 dsh rc.6） | `ls D:/eline-ai/eline.exe` |
| 账号登录态 | `C:\Users\<你>\.eline\.credentials.yaml` 存在（deepseek-account，平台 elineai.21eline.com，真实计费） | 见下"重建"节 |
| 执行 profile | `~/.eline/profiles/evalheadless/`（模板备份在 `runner/profile-templates/evalheadless/`） | 同上 |

目录分工：

```text
D:\Agent_Eval\
  evalset\           用例与编译：cases/<主题>/*.md、knowledge/*.yaml、md2case.py、dist\
  runner\            执行器：src/、lib/、profile.default-roots.yaml、anchors.txt、out\<run>\
  scoring\           打分：scoring.py
  doc\               设计文档（本手册在此）
  tools\             链路诊断脚本（p0-1-verify.mjs、p0-2-inventory.mjs）
```

执行链路的全部配置在 `runner/profile.default-roots.yaml`（bin、DSH_HOME、asar 技能挂载、profile 名），改链路只改这一个文件：

```yaml
id: eline-glm53-defaultroots
dsh:
  bin: D:/eline-ai/eline.exe --expose-internals D:/eline-ai/resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-desktop-host/lib/cli.js
  profile: evalheadless
  home: C:/Users/jiaoshouxiang/.eline
  env:
    ELECTRON_RUN_AS_NODE: "1"
    DSH_BUNDLED_SKILL_DIR: "D:/eline-ai/resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-web-app/skills/trade-expert"
  timeout_ms: 600000
skills_mode: default-roots
skill_tool: skill
routing:
  进单资料审核: [trade-documents]
```

三个环境变量的作用：`ELECTRON_RUN_AS_NODE` 让 eline.exe 以 Node 模式执行 asar 内 CLI；`DSH_HOME` 指到 eline 的凭据与 profile home；`DSH_BUNDLED_SKILL_DIR` 把产品 21 个外贸 skill 从 asar 内挂载进来（产品单一事实源，零拷贝、随产品版本走）。


## 3. 用例编写与评测集构建

用例的写法规范（frontmatter、问题/对话/关键条件/必要事实/注入/变体等段落、状态流转）见 `doc/CASE-STRUCTURE.md`，本节只讲命令。所有命令在 `evalset/` 下运行：

```bash
cd D:/Agent_Eval/evalset

# 校验：行号报错、充分性/必要性检查、变体审核
python md2case.py check cases/order_intake
python md2case.py check cases/order_intake --docs <skill 根目录>   # 追加注入键与原文一致性校验

# 看单个用例的转换结果（调试用）
python md2case.py convert cases/order_intake/kr-0201.md

# 正式编译：产出 dist 下不可变版本文件；--prev 生成与上一版的自动 diff
python md2case.py build cases/order_intake -o dist/evalset-v20261022-1.jsonl \
  --version v20261022-1 --include structured,reviewed,admitted
#   （--include 默认只收 admitted；--no-linkage 跳过注入 rev 联动降级，仅调试用）

# 反向：结构化数据渲染成 md 交业务专家审阅（不覆盖已有文件，覆盖加 --force）
python md2case.py render generated.jsonl -o review/
```

要点：

- **状态门禁**：`build` 默认只收 `admitted`；扩 `--include` 时自己保证质量。
- **注入（注入J）**：改写点写在 `evalset/knowledge/*.yaml`（key + 反转/删除选项），用例里只引用 `@point`，不写死改写后的文本。
- **rev 联动**：knowledge 里的注入内容变了，引用它的 md 用例会被自动降级回 `structured` 并写 `status_note`，防止旧用例配新知识静默跑偏。`--no-linkage` 只是绕过检查，不会恢复状态。
- **dist 不可变**：同一版本号重编译会拒绝；要改内容就升版本号。

## 4. 执行 run

### 4.1 两种启动方式

```bash
# 正式 run：用 build 出的固定版本评测集（可续跑、可版本对比）
node lib/cli.js run --evalset ../evalset/dist/evalset-v20261022-1.jsonl \
  --profile profile.default-roots.yaml --out out/baseline-product --modes natural,forced --trials 2

# 试跑：直接指 markdown 目录或文件，现场编译一次性评测集（adhoc-<时间戳>，落 <out>/dist）
node lib/cli.js run --cases ../evalset/cases/order_intake --profile profile.default-roots.yaml \
  --out out/quick --modes natural --trials 1
```

`--cases` 方式不参与版本对比与 `--resume`，试跑、排查用；正式数据一律走 `build → --evalset`。

### 4.2 全部选项

| 选项 | 说明 |
|---|---|
| `--cases <路径>...` | md 目录/文件，可重复；与 `--evalset` 互斥 |
| `--modes natural,forced` | natural=原样发送看自然路由；forced=按 Profile routing 在第一轮前加 `/skill名` 强制注入。两者对比可分离"路由问题"与"知识问题" |
| `--trials N` | 每用例×干预的独立采样次数（默认 3；正式基线 ≥2） |
| `--concurrency N` | 并发会话数（默认 1） |
| `--dims / --only / --topic` | 筛选：维度 / 用例 id 或 uid（`kr-0201` 或 `kr-0201#1`）/ 业务主题 |
| `--anchors on\|off` | 锚点用例（`runner/anchors.txt`）并入开关；全量 run 默认并入 |
| `--dry-run` | 只打印计划（会话数、跳过项、成本估算、inventory 状态），不跑 dsh |
| `--resume` | 续跑：跳过已完成会话；环境快照（评测集/Profile/eline profile/skills 配置）任一变化即拒绝 |
| `--keep-workspace` | 保留每段会话的工作区（默认删，session 日志总是保留） |
| `--max-error-rate R` | error+timeout 占比超 R 退出码 2（默认 0.2），结果产出但标记不可直接采信 |
| `--adapter dsh-cli\|web-ui` | 默认 dsh-cli；web-ui 需 Profile 配 `web.home/web.port`（备通道，见 03 §7.2） |

### 4.3 操作约定

- **先 dry-run 再真跑**：计划里会打印 skills_mode、锚点、成本估算、inventory 过期提示。
- **trials 是独立采样不是重试**：没有"失败重跑"，重跑会高估能力。
- **一次 run 一个 Profile**：比较配置 = 跑两次再用 `scoring.py compare` 离线配对比较。
- **退出码**：0 完成；1 参数/配置/评测集错误；2 完成但错误率超标。
- **成本量级参考**（glm-5.3，natural，trials 1）：单轮会话约 40~250 秒/段；多轮（3 轮）约 5~7 分钟/段。全量 26 行 × 两干预 × trials 2 ≈ 100+ 段会话，跑前看 dry-run 的估算。

## 5. 结果与打分

### 5.1 输出目录结构

```text
out/<run>\
  results.jsonl   每段会话一行（EpisodeRecord，schema 3，用例编译行内嵌，自包含可直接打分）
  run.json        运行清单：评测集/Profile sha256、环境快照（eline_profile 指纹、skills 配置、
                  models_observed）、计划/执行/状态计数、跳过项、warnings
  scoring.json    打分输出（scoring.py score 生成）
  dist\           --cases 方式现场编译的一次性评测集
  .work\<序号>-<uid>-<干预>-t<trial>\
    overlay.patch.yml
    session\...\session-<uuid>\session.v4.jsonl.zstd   原始会话日志（含业务数据，注意存放）
```

results.jsonl 每行关键字段：`uid/mode/trial`（定位）、`status`（运行状态，**不等于答对**）、`turns[]`（每轮 input/output/skills/tools/usage）、`final_output`（最后一轮回答，默认打分对象）、`loaded_skills`、`case`（内嵌的编译行）、`injections_applied`。

## 6. 运维：环境重建与故障处理

### 6.1 ~/.eline 被清空/重装客户端后的重建（实测分钟级）

重装或首启客户端可能清掉 `~/.dsh`、`~/.eline/skills` 与 `~/.eline/profiles/evalheadless`（登录态 `.credentials.yaml` 通常幸存；整目录被手动删过一次，重建法相同）：

1. **登录态**：启动 ElineAI 客户端登录一次（恢复 `.credentials.yaml` 与 desktop profile）。
2. **重建 profile**（用 eline 自带链路跑 profile 命令）：
   ```bash
   ELECTRON_RUN_AS_NODE=1 DSH_HOME=C:/Users/jiaoshouxiang/.eline \
     D:/eline-ai/eline.exe --expose-internals \
     D:/eline-ai/resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-desktop-host/lib/cli.js \
     evalheadless --from-default-profile headless
   ```
3. **恢复评测配置**：把仓库备份的模板覆盖回去（含 glm-5.3/high 模型配置、产品外贸专家 persona、ask_user timed 60s）：
   ```bash
   cp -r D:/Agent_Eval/runner/profile-templates/evalheadless/. C:/Users/jiaoshouxiang/.eline/profiles/evalheadless/
   ```
   模板与运行时不一致时（如客户端升级），以 `~/.eline/profiles/desktop/cordis.yml` 里的 persona 段与 agent-default-model 段为准重新抄写，并更新仓库备份。
4. **验证**：`--cases` 跑一段小会话，确认 status=ok 且 `loaded_skills` 非空。
5. **注意**：不要在客户端运行时往 `~/.eline` 写东西；先退客户端再覆盖。

### 6.2 常见错误对照

| 症状 | 原因 | 处理 |
|---|---|---|
| `MISSING_CREDENTIAL` | `~/.eline` 无登录态 | 6.1 节第 1 步 |
| `ACCOUNT_SIGN_IN_REQUIRED` | 用了复制的 home/凭据绑定问题 | 凭据绑定真实 home，不可复制；直接用 `DSH_HOME=~/.eline` |
| "Expected 0 arguments but got 1" | evalheadless 加了 dsh-web-app bundle（web app 抢占参数） | bundles 只留 `dsh-base, dsh-headless`；skill 靠 `DSH_BUNDLED_SKILL_DIR`，persona 靠 patch |
| patch 报 "must be a top-level YAML array" | patch 文件被截断（如用 tail 切片） | 整条目写文件，别行号切片；参考仓库模板 |
| skill 复制为空/inventory 读不到 | 传了 msys 路径（`/tmp/...`）给 Node | 一律用 `C:/...` 风格路径（`cygpath -m` 转换） |
| asar 路径工具读不到 | asar 虚拟目录纯 Node 读不了 | 盘点/物化类操作须经 `ELECTRON_RUN_AS_NODE` 的 eline node 执行，或先导出实体目录 |
| 改了 runner 代码行为没变 | `lib/` 是旧构建 | `npm run build` 后再跑（src → lib 不会自动同步） |
| 个别会话 `STREAM_CLOSED` | 平台侧流断开 | 已按 error 正确归类；占比高时查网络/平台 |

### 6.3 客户端版本升级（rc.6 → rc.7）后要重验什么

1. asar 内 cli.js 路径与 `DSH_BUNDLED_SKILL_DIR` 路径是否变化（profile.default-roots.yaml）；
2. `node lib/cli.js inspect` 看 session 日志格式/事件类型是否变化（vendor 解析器是否需同步上游）；
3. `--cases` 小样本 E2E：status ok + `loaded_skills` 非空；
4. 版本号写进结论（"产品 runtime 0.2.0-rc.x"）。
