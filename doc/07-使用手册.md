# 使用手册

v1.1（2026-10-23）· 面向评测执行者的操作手册

本手册讲"怎么用"，设计与口径见同目录其他文档：业务过程（01）、用例结构（CASE-STRUCTURE.md）、执行链路细节（03 §7.1）。**第 2 节是从零到结论的全过程主线**，后续章节是各环节的展开细节与排障。**当前结论性口径：执行链路驱动 ElineAI 客户端自带的改造版 dsh（0.2.0-rc.6），不脱离 ElineAI 服务链路发起会话；npm 通用 dsh 仅作应急备份。**

```text
md 用例 ──build──> evalset.jsonl ──run──> 会话执行（eline 自带 dsh）
   ^                                    │
   └────────── rev 联动降级 ←── 注入/改写 ←┘
                                        v
            results.jsonl ──specs import/score/rejudge──> 评测库 archive/eval.db
                                                            │ export/serve/compare
                                                            v
                                              scoring.json / 复核页面 / 比较矩阵
```

## 1. 环境与前置条件

| 依赖 | 要求 | 检查方式 |
|---|---|---|
| Node.js | ≥ 22.15（内置 zstd 解压） | `node -v` |
| Python | ≥ 3.10 | `python --version` |
| ElineAI 客户端 | 装在 `D:\eline-ai`（提供 eline.exe 与 app.asar 内的 dsh rc.6） | `ls D:/eline-ai/eline.exe` |
| 账号登录态 | `C:\Users\<你>\.eline\.credentials.yaml` 存在（deepseek-account，平台 elineai.21eline.com，真实计费） | 见下"重建"节 |
| 执行 profile | `~/.eline/profiles/evalheadless/`（模板备份在 `runner/profile-templates/evalheadless/`） | 同上 |

目录分工：

```text
D:\Agent_Eval\
  evalset\           用例与编译：cases/<主题>/*.md、knowledge/*.yaml、md2case.py、dist\
  runner\            执行器：src/、lib/、profile.default-roots.yaml、profile.bundled-copy.yaml、
                     anchors.txt、out\<run>\
  scoring\           打分包（python -m scoring）：算子链、评测库 store、口径、比较轴、复核服务
  archive\           评测库 eval.db 与导出（判定/人工数据，含业务对话，不进仓库）
  .eval-skills\base\ 技能基底实体副本（bundled-copy 模式 skills_roots；产品内容拷贝，不进仓库）
  doc\               设计文档（本手册在此）
  tools\             链路诊断与导出脚本（p0-1-verify.mjs、p0-2-inventory.mjs、setup-dsh-local.mjs、
                     export-skills.mjs）
```

执行链路的全部配置在 `runner/profile.default-roots.yaml`（bin、DSH_HOME、asar 技能挂载、profile 名），改链路只改这一个文件：

```yaml
id: eline-glm53-defaultroots
dsh:
  bin: D:/eline-ai/eline.exe --expose-internals D:/eline-ai/resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-desktop-host/lib/cli.js
  profile: evalheadless
  home: C:/Users/jiaoshouxiang/.eline
  env:
    ELECTRON_RUN_AS_NODE: "1"
    DSH_BUNDLED_SKILL_DIR: "D:/eline-ai/resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-web-app/skills/trade-expert"
  timeout_ms: 600000
skills_mode: default-roots
skill_tool: skill
routing:
  进单资料审核: [trade-documents]
```

会话模型在 Profile 里以 `model` + `reasoning_effort` 成对声明（如 `model: glm-5.3` / `reasoning_effort: high`），
运行时经每会话 overlay 覆盖 dsh 的 `agent-default-model`（provider 缺省 `deepseek-account` 产品账号态，
可用 `model_provider` 改）；两者必须同时设置——只写一项会把 eline profile 层的另一项剥掉。
临时换模型用命令行 `--model`/`--reasoning-effort` 覆盖（见 4.2），生效值会追加进 profile id（如
`eline-glm53-defaultroots@glm-5.3-low`），保证比较轴可区分。实际生效与否以 run.json 的
`models_observed` 与会话日志 request/header 为准（reasoningEffort 也在其中实录）。

三个环境变量的作用：`ELECTRON_RUN_AS_NODE` 让 eline.exe 以 Node 模式执行 asar 内 CLI；`DSH_HOME` 指到 eline 的凭据与 profile home；`DSH_BUNDLED_SKILL_DIR` 把产品 21 个外贸 skill 从 asar 内挂载进来（产品单一事实源，零拷贝、随产品版本走）。

## 2. 全过程一览（从零到结论）

标准主线六步：**编译评测集 → 执行 run → 导入期望并判定 → 人工复核 → 比较/导出/备份 →（期望演进回路）**。每步命令都可重复执行；改了哪一步就重跑哪一步，评测库自动补缺。环境检查见第 1 节。

### 步骤 1 · 编译评测集（`evalset/` 下）

```bash
cd D:/Agent_Eval/evalset
python md2case.py check cases/order_intake        # 先过校验（--docs <skill 根目录> 追加注入一致性检查）
python md2case.py build cases/order_intake -o dist/evalset-v<ver>.jsonl \
  --version <ver> --include structured,reviewed,admitted    # 产出 dist 下不可变版本
```

### 步骤 2 · 执行 run（`runner/` 下）

```bash
cd D:/Agent_Eval/runner && npm install            # 首次

# a) 先看计划（不花 token）：会话数、跳过项、成本估算、inventory 状态
node lib/cli.js run --evalset ../evalset/dist/evalset-v<ver>.jsonl \
  --profile profile.default-roots.yaml --out out/<name> --dry-run

# b) 正式 run（小样本验证可加 --only kr-0201,kr-0204,mt-0201 --trials 1）
node lib/cli.js run --evalset ../evalset/dist/evalset-v<ver>.jsonl \
  --profile profile.default-roots.yaml --out out/<name> --modes natural,forced --trials 2
```

**评测集含 ec 维度（错误知识纠正/知识注入）时**，default-roots 会自动跳过 ec——改用 bundled-copy
Profile 跑（每段会话物化独立技能副本，注入只改副本；首次或客户端升级后先导出技能基底）：

```bash
ELECTRON_RUN_AS_NODE=1 D:/eline-ai/eline.exe ../tools/export-skills.mjs   # → .eval-skills/base（不进仓库）
node lib/cli.js run --evalset ../evalset/dist/evalset-v<ver>.jsonl \
  --profile profile.bundled-copy.yaml --out out/<name-ec> --modes natural --trials 2
```

两份 Profile 只差 `skills_mode`/`skills_roots`，链路配置相同；ec 的注入是否被 agent 采信属于
测量对象（见 7 节已知限制 3）。

### 步骤 3 · 导入期望并判定（仓库根下）

```bash
cd D:/Agent_Eval
python -m scoring specs import evalset/dist/evalset-v<ver>.jsonl   # 期望 → 当前期望（空库可省略本步）
python -m scoring score runner/out/<name>                          # ingest + 判定 + 物化会话结论
```

`score` 可对同一 run 重复执行（幂等只补缺）；多个 run 依次 `score` 即可全部入同一个评测库。
空库首次 `score` 会以执行时期望顶上当前期望，之后 import 的期望优先生效。

### 步骤 4 · 人工复核（模型算子接入前的主要工作量）

```bash
python -m scoring serve                           # 打开 http://127.0.0.1:8765
```

复核以**对话**为单位（doc/10）：`/review` 队列一行一段对话（五个标签：结论待定 / 有未判条目 /
模型抽检 / 人工≠机器 / 会话失败），点进 `/review/{对话}` 复核页——左侧对话全文（markdown 渲染、
不截断），右侧评分表按「前提 → 路径 → 禁止 → 必要 → 期望」分节，每行机器栏（结论与分、算子、
理由）+ 人工栏（快捷分值按钮、0–100 分数框、同意机器、理由）；结论条实时显示会话分或区间，
`Ctrl+Enter` 一次提交整段草稿（原子：一条不合法整批不写）。键盘 `J/K` 换条目、`1–9` 快捷分、
`N` 输入分数、`Y` 同意机器、`E` 理由、`T` 手改总分（必填理由）。复核完未决条目后对话出队、
分数即时更新；队列清零前均分与综合分均标"临时"。评审人姓名记在浏览器 localStorage。

### 步骤 5 · 比较、导出与备份

```bash
python -m scoring compare --axis profile --fix mode=natural    # 处理条件不一致会拒绝；--fix 固定 / --any 放行
python -m scoring export --out archive/export                  # 判定明细/改判/scoring.json/CSV
python -m scoring backup archive/eval-backup.db                # 定期备份评测库
```

常用比较轴：`profile`（两次 run 对比配置）、`mode`（natural vs forced 分离路由/知识问题）、
`skills_base`（知识修订验证）、`evalset_version`（期望修订前后口径，见步骤 6）、`trial`/`run`
（采样一致性）。比较按题目交集对齐，锚点用例作绊线。

### 步骤 6 · 期望演进回路（不重跑 agent）

```bash
# 修订用例/知识后升版本（evalset/ 下）
python md2case.py build cases/order_intake -o dist/evalset-v<新ver>.jsonl --version <新ver> ...
# 导入新期望 → 当前期望切换为新版，旧版期望保留在库中（仓库根下）
python -m scoring specs import evalset/dist/evalset-v<新ver>.jsonl
python -m scoring rejudge                         # 按新当前期望补判全部旧答案（只调算子，不跑 agent）
python -m scoring compare --axis evalset_version  # 新旧期望口径下的结论对比
python -m scoring specs set-current v<旧ver>      # 需要回看旧口径时随时切回（再 rejudge 即可）
```

题目身份 = uid + 输入指纹（**含 topic**）：只改判定内容（事实/前提/路径约束）不改输入时，旧/新
答案落在同一题下，rejudge 后即可对比；改了用户输入或 topic 则视为新题，旧答案保留在原题下。

## 3. 用例编写与评测集构建

用例的写法规范（frontmatter、问题/对话/关键条件/必要事实/注入/变体等段落、状态流转）见 `doc/CASE-STRUCTURE.md`，本节只讲命令。所有命令在 `evalset/` 下运行：

```bash
cd D:/Agent_Eval/evalset

# 校验：行号报错、充分性/必要性检查、变体审核
python md2case.py check cases/order_intake
python md2case.py check cases/order_intake --docs <skill 根目录>   # 追加注入键与原文一致性校验

# 看单个用例的转换结果（调试用）
python md2case.py convert cases/order_intake/kr-0201.md

# 正式编译：产出 dist 下不可变版本文件；--prev 生成与上一版的自动 diff
python md2case.py build cases/order_intake -o dist/evalset-v20261022-1.jsonl \
  --version v20261022-1 --include structured,reviewed,admitted
#   （--include 默认只收 admitted；--no-linkage 跳过注入 rev 联动降级，仅调试用）

# 反向：结构化数据渲染成 md 交业务专家审阅（不覆盖已有文件，覆盖加 --force）
python md2case.py render generated.jsonl -o review/
```

要点：

- **状态门禁**：`build` 默认只收 `admitted`；扩 `--include` 时自己保证质量。
- **注入（注入J）**：改写点写在 `evalset/knowledge/*.yaml`（key + 反转/删除选项），用例里只引用 `@point`，不写死改写后的文本。
- **rev 联动**：knowledge 里的注入内容变了，引用它的 md 用例会被自动降级回 `structured` 并写 `status_note`，防止旧用例配新知识静默跑偏。`--no-linkage` 只是绕过检查，不会恢复状态。
- **dist 不可变**：同一版本号重编译会拒绝；要改内容就升版本号。

## 4. 执行 run

### 4.1 两种启动方式

```bash
# 正式 run：用 build 出的固定版本评测集（可续跑、可版本对比）
node lib/cli.js run --evalset ../evalset/dist/evalset-v20261022-1.jsonl \
  --profile profile.default-roots.yaml --out out/baseline-product --modes natural,forced --trials 2

# 试跑：直接指 markdown 目录或文件，现场编译一次性评测集（adhoc-<时间戳>，落 <out>/dist）
node lib/cli.js run --cases ../evalset/cases/order_intake --profile profile.default-roots.yaml \
  --out out/quick --modes natural --trials 1
```

`--cases` 方式不参与版本对比与 `--resume`，试跑、排查用；正式数据一律走 `build → --evalset`。

### 4.2 全部选项

| 选项 | 说明 |
|---|---|
| `--cases <路径>...` | md 目录/文件，可重复；与 `--evalset` 互斥 |
| `--modes natural,forced` | natural=原样发送看自然路由；forced=按 Profile routing 在第一轮前加 `/skill名` 强制注入。两者对比可分离"路由问题"与"知识问题" |
| `--trials N` | 每用例×干预的独立采样次数（默认 3；正式基线 ≥2） |
| `--concurrency N` | 并发会话数（默认 1） |
| `--dims / --only / --topic` | 筛选：维度 / 用例 id 或 uid（`kr-0201` 或 `kr-0201#1`）/ 业务主题 |
| `--anchors on\|off` | 锚点用例（`runner/anchors.txt`）并入开关；全量 run 默认并入 |
| `--dry-run` | 只打印计划（会话数、跳过项、成本估算、inventory 状态），不跑 dsh |
| `--resume` | 续跑：跳过已完成会话；环境快照（评测集/Profile/eline profile/skills 配置）任一变化即拒绝 |
| `--keep-workspace` | 保留每段会话的工作区（默认删，session 日志总是保留） |
| `--max-error-rate R` | error+timeout 占比超 R 退出码 2（默认 0.2），结果产出但标记不可直接采信 |
| `--model <名>` | 覆盖会话模型（经每会话 overlay 覆盖 agent-default-model；需与 `--reasoning-effort` 同时给，生效 profile id 追加 `@模型-努力程度`，比较轴据此区分） |
| `--reasoning-effort <级别>` | 努力程度（low/medium/high 等，以平台实际支持为准；产品 rc.6 实测 overlay 覆盖生效） |
| `--adapter dsh-cli\|web-ui` | 默认 dsh-cli；web-ui 需 Profile 配 `web.home/web.port`（备通道，见 03 §7.2） |

### 4.3 操作约定

- **先 dry-run 再真跑**：计划里会打印 skills_mode、锚点、成本估算、inventory 过期提示。
- **trials 是独立采样不是重试**：没有"失败重跑"，重跑会高估能力。
- **一次 run 一个 Profile**：比较配置 = 跑两次，再用 `python -m scoring compare --axis …` 按题目交集离线比较。
- **退出码**：0 完成；1 参数/配置/评测集错误；2 完成但错误率超标。
- **成本量级参考**（glm-5.3，natural，trials 1）：单轮会话约 40~250 秒/段；多轮（3 轮）约 5~7 分钟/段。全量 26 行 × 两干预 × trials 2 ≈ 100+ 段会话，跑前看 dry-run 的估算。

## 5. 结果与打分

判定与人工数据自 09 方案起存入**评测库**（SQLite，默认 `archive/eval.db`，不进仓库）；
原始运行产物仍是不可变文件，判定明细/改判/报告可随时经 `export` 重新生成。

### 5.1 输出目录结构

```text
out/<run>\                原始层（执行器产出，不可变）
  results.jsonl   每段会话一行（EpisodeRecord，schema 3，用例编译行内嵌，自包含可直接打分）
  run.json        运行清单：评测集/Profile sha256、环境快照（eline_profile 指纹、skills 配置、
                  models_observed）、计划/执行/状态计数、跳过项、warnings
  dist\           --cases 方式现场编译的一次性评测集
  .work\<序号>-<uid>-<干预>-t<trial>\
    overlay.patch.yml
    session\...\session-<uuid>\session.v4.jsonl.zstd   原始会话日志（含业务数据，注意存放）

archive\                  评测库层（判定与人工数据的唯一事实来源；含业务对话，已 gitignore）
  eval.db         SQLite（WAL）：runs/questions/specs/answers/verdicts/reviews/
                  verdict_cache/conclusions，python -m scoring backup 定期备份
  export\         导出层：verdicts.jsonl / reviews.jsonl / scoring.json / episodes.csv / items.csv

（旧版 run 目录中的 verdicts.jsonl / review.jsonl / scoring.json 为历史产物，
 用 `import-legacy <run>` 一次性导入评测库。）
```

results.jsonl 每行关键字段：`uid/mode/trial`（定位）、`status`（运行状态，**不等于答对**）、`turns[]`（每轮 input/output/skills/tools/usage）、`final_output`（最后一轮回答，默认打分对象）、`loaded_skills`、`case`（内嵌的编译行）、`injections_applied`。

### 5.2 查看与排查

```bash
# 汇总各段会话状态
python -c "
import json
for l in open('out/demo/results.jsonl', encoding='utf-8'):
    r = json.loads(l); print(r['episode_id'], r['status'], r.get('loaded_skills'))"

# 导出某段会话的日志事件（工具调用、skill 注入、事件类型）
node lib/cli.js inspect out/demo/.work/0001-kr-0201-0-natural-t1
```

### 5.3 打分、重判、复核与对比

```bash
cd D:/Agent_Eval

# ① 导入评测集快照（成为当前快照；题目身份=uid+输入指纹，标准修订不改题目身份）。
#    P2 dist 首行为快照头，同名 .snapshot.json 带测法，导入自动读取。
#    空库可省略本步：首次 score 会以执行时期望作为当前期望（R5）
python -m scoring specs import evalset/dist/evalset-v<版本>.jsonl

# ② 判定 run（= ingest + 按当前标准执行算子链 + 物化会话结论；可重复执行，只补缺）
python -m scoring score runner/out/demo

# ③ 标准修订后重判旧答案（只调算子不跑 agent；未改动条目的人工改判继续生效）
python -m scoring rejudge            # 可 --question <qkey> / --run <run_id> 限定范围

# ④ 计分规则（scoring/rules.yaml）修改后只重算会话结论表（不调用任何算子；--policy 为弃用别名）
python -m scoring rescore

# ⑤ 比较（比较轴护栏 + 题目交集对齐 + 锚点绊线；未固定且未声明不限的属性不一致时拒绝）
python -m scoring compare --axis profile   # 只出通过矩阵 JSON；trial/run 默认不限
python -m scoring compare --axis skills_base --base v1 --target v2   # 分数对比：两侧综合分/维度分、
                                                                    #   单组件贡献（95% 区间）、逐题差异
python -m scoring compare --axis run --base r1 --target r2 --factors model,skills_base   # Shapley 分摊

# ⑥ 导出与备份（导出可重新 import-legacy；备份用 SQLite 原生接口）
python -m scoring export [--run demo] [--spec at-run|current] --out archive/export
python -m scoring backup archive/eval-backup.db

# ⑦ 复核服务（默认本机 8765，doc/10 v2 的四个页面：用例 / 复核 / 结果对比 / 判定质量。
#    复核以对话为单位：队列一行一段对话，复核页左对话右评分表，一次提交整段草稿；
#    POST /api/review/preview 预览不落库；旧路由 /queue /quality /question/{qkey} 301 到新页）
python -m scoring serve

# ⑧ 旧数据迁移：09 方案之前的 run 目录里 verdicts.jsonl/review.jsonl 一次性入库（幂等，
#    缺省同时导入全局判定缓存 scoring/verdict-cache.jsonl，--cache 可指定其他路径）
python -m scoring import-legacy runner/out/<旧run>
```

**旧评测库升级**：v1/v2 旧库直接打开（任何 scoring 命令）即自动迁移到 schema v3——重算全部
qkey（R11 后输入指纹含 topic）、回填注入/泄露预计算列与 started_at。旧 qkey 因 topic 差异分叉
出多个新 qkey 时，期望逐条按自身内容归位、当前期望指针跟随期望所在的新 qkey，其余分叉题保留
first_seen 不带当前期望。无 run.json 的 run，started_at 以首次导入时间落列（重导不刷新，run.json
真实值一旦出现即覆盖）。

**当前状态提醒**：模型算子（llm-fact / llm-forbid，方案 08 §9 第二批）尚未接入。在此之前：无关键词的必要/期望事实由 keyword 算子弃权后即"未决"，全部进入复核队列人工判定；通过率分母只含已判会话并标注"临时"，不能作为正式结论引用。判定口径本身（四级事实、按轮判分、两点求值、维度聚合、policy.yaml 参数）已实现并经对拍测试。

**百分制口径**（doc/10 §4 + doc/17）：每条计分条目打 0–100 分（结论词为快捷分值：对 100 · 部分 50 · 未提及 0 · 错 0 · 满足/成立 100 · 违反/不成立 0），按用例计分配置（scoring 块）的权重算会话分——**用途为计分且权重大于 0** 的条目才参与；【权重】没写就是 0%，计分权重合计 0 的用例评测记 `skipped`（单独计数，不计维度分与通过率）。否决与门控是默认规则、与用途无关：禁止事实被采信、路径违反、必要事实判「错」→ 按 `score.veto_mode`（zero 清零 / cap 封顶）处理，前提不成立 → 会话无效；会话分 ≥ 60 为通过。有未判条目时会话分是区间，区间跨过及格线即「未决」。`score` / `rescore` 的汇总输出带均分，`export` 的 episodes.csv / items.csv 带分数列。v9 起评测库从空库起步（旧库不再可打开，doc/17 决定 15）。

## 9. 配置重构后的工作方式（doc/14/15，v8 起）

评测的身份体系自 v8 起按「六份配置」运转（doc/14）：① 用例配置（md，题面+标准）
② 测法（evalset/method.yaml，随快照发布）③ 被测配置（runner profile → subject_fp
指纹）④ 判定配置（operators.yaml）⑤ 人工记录（reviews）⑥ 计分规则（scoring/rules.yaml；条目用途与权重在用例 md 的
scoring 配置里，doc/17）。**改了什么决定要做什么**：改题面/测法/被测 → 重跑；改标准 →
重判；改判定配置 → 重判；改条目用途/权重/计分规则 → 只重算（rescore，不调算子）。

### 快照与测法（P2 起）

```bash

# dist 首行写快照头，同名 .snapshot.json 落测法全文
```

### 执行：按测法跑，诊断执行不进正式分（P2 起）

### 条目计分配置：md 是唯一数据源，临时权重做实验（doc/17 §5）

- 用例页「计分配置」饼图：每条目一行滑杠（拖圆钮调权重，减少→未分配、有未分配才能增加，
  双击百分比值直接输入），行首胶囊切换**计分/参考**（仅拒答固定计分、不可切）；判定条目
  简要列表与详情卡的角标随胶囊实时同步；名义合计 ≠100 保存时统一归一。
  「保存到用例（md）」走保存管线：md 校验 → 落盘 → build 自动取号新版本（vYYYYMMDD-N）
  → 整批导入设为当前快照（覆盖此前的快照选择、清逐题偏离）→ 同步 rescore；只改用途/
  权重**不产生新标准、不需要 rejudge**，改条目文本则产生新标准并提示「待重判 N 段」。
- 「保存为临时权重」只写数据库 temp_weights（不动 md），只重算本用例；「转正」把临时
  值写进 md 再删临时；开关切换「评测使用 md / 临时权重」，两种口径的结论并存可比。
- 计分条目权重合计 0%（未分配）→ 该用例评测跳过（结论记 skipped，不计维度分/通过率），
  补齐权重或启用已分配的临时权重后自动恢复，不用重跑。
- CLI：`python -m scoring temp-weights list --case kr-0201` / `temp-weights set --case kr-0201 F1=60 E1=40`
  / `temp-weights use --case kr-0201 on|off` / `temp-weights clear --case kr-0201`。
- 规则/快照/链的命名在页面侧边栏「评测视角」三件套旁的 ✎（纯展示层，不进任何键）。

- 三件套旁 🔍 打开详情页（新标签）：`/detail/rules/<sha>`（规则全文 + 与库内任一
  其他规则 diff）、`/detail/chain/<sha>`（逐条目类型链组成 + 算子实例参数；历史链

  已落计分配置的用例）。三件套旁 `?` 展开帮助浮层：每样配置的编辑入口与改后要跑的命令。
- 计分口径可查：用例详情页显示当前口径（md 权重 / 临时权重）与 scoring_fp；
  临时权重与当前条目不一致时页面提示（已不存在的条目被忽略、新增计分条目按 0 计）。

### 计分规则与被测配置

- `scoring/rules.yaml`：及格线/分值映射/否决/聚合 + `operator_score: adopt|ignore`
  （ignore 时不采信模型算子给的显式分，只用 map 快捷分）。改后 `rescore`。
- 被测配置 = subject_fp 内容指纹（模型/努力/技能方式/基底/agent 版本）；profile 内容或
  agent 版本变了就是新配置（旧数据不混）。同一配置跨快照的分数自动合并。
- 结果对比：公平性护栏按 subject 指纹 + 快照轴；「标准对比」块选两个快照 diff 同答案
  在两份标准下的结论（验证标准修订效果；单侧未判的列入待补判）。
