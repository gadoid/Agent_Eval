# 10 复核服务改造方案：以对话为单位的百分制复核

v1（2026-10-23）· 基于 `main` 84c48b7

原型：[`10-复核服务原型.html`](10-复核服务原型.html)（浏览器直接打开，离线可用，数据为示例）。界面规范（色彩、字体、部件、交互）见设计系统「Agent_Eval 复核」。本文是落地方案：口径、数据、代码改动、接口、测试与分步实施。

## 0. 背景

09 方案落地后，复核服务按评测库取数、分页，功能齐全，但评审实际使用中有四类问题：

1. **复核单位不对。** 队列一个条目一张卡，同一段对话的回答在每张卡里重复出现（且截断到 400 字），评审人看不到全局，也看不到这条判了以后会话结论会怎样。
2. **评分体系只有通过/失败。** 讨论纪要 §5.2 要求「分数、综合分、组件贡献」三者都要有；现在只有条目结论词与会话通过率。
3. **页面职责混乱。** 「题目列表」实际列的是变体；比较页要手写 `fix=k=v`；质量页混合了判定可信度与用例本身的问题；模型判定接入后结论放在哪里没有位置。
4. **内容读不好。** 对话大量是 markdown，但队列与用户输入按纯文本显示；依赖缺失时 `md_filter` 静默退化。

另有两项来自 84c48b7 与讨论纪要的输入：run 级可指定被测模型与努力程度（profile id 带 `@模型-努力`）；ec 需要「注入是否生效」的逐会话观测来区分「agent 未采信」与「注入被遮蔽」。

## 3. 原型与页面

### 3.1 页面职责

| 页面 | 路由 | 回答的问题 | 取代 |
| --- | --- | --- | --- |
| 用例（首页） | `/` | 评测集里有什么，每个用例考什么、得多少分 | `/` 题目列表 |
| 用例详情 | `/case/{case_id}` | 这个用例的期望、变体、全部对话与分数 | `/question/{qkey}`、`/group/{case_id}` |
| 复核队列 | `/review` | 还有哪些对话要人判 | `/queue` |
| 复核页 | `/review/{answer_id}` | 这段对话该给几分 | 队列里的条目卡 |
| 结果对比 | `/compare` | 换了组件，变好还是变坏，各组件贡献多少 | `/compare` |
| 判定质量 | `/judging` | 机器判得准不准，能不能少看一点 | `/quality`（用例信号移到用例页） |

旧路由保留一个版本的 301 跳转：`/question/{qkey}` → `/case/{case_id}#{uid}`，`/group/{case_id}` → `/case/{case_id}`，`/queue?filter_name=x` → `/review?tab=x`，`/quality` → `/judging`。

### 3.2 公共

- 顶栏：四个视图 + 复核计数（结论待定的对话数）+ **判定配置**下拉（URL 参数 `chain`，缺省为启动配置）。
- 两个「模型」严格区分：**被测**（agent 的 `models_observed` + Profile `reasoning_effort`，显示在 RunTag）与**判定**（模型算子的模型，属于判定配置）。界面上单写「模型」时必须能从位置或标签看出指哪一个。
- 临时数字：有未决被排除时，平均分与综合分标「临时」。
- 页面不触发判定：缺判定时给出 `rejudge` 命令与复制按钮。

### 3.3 用例页与用例详情

- 用例页：综合分构成（维度分 × 权重，缺维度标「不完整」）+ 三个磁贴（结论待定对话、已确定对话、用例体检）+ 筛选（维度、主题、粒度、排序、只看有体检标记）+ 用例表（一行一个 `case_id`：变体数、对话数、结论待定、用例分、难度、区分度、稳定性、题组一致、体检标记）。
- 用例详情：CaseInfo（维度与控制字段：主题、粒度、可回答、对话方式、主口径、关键条件、注入、标签、体检）→ 期望（各轮输入、条目、权重、参考答案；历史期望下拉）→ 变体 → 对话列表（一行一段：会话结论、分数、RunTag、条目小结、复核链接）。旧题目视图「轮次为行、run 为列」的宽表在 3 列以上不可读，改为列表；需要逐轮对照时勾选两段并排查看。

### 3.4 复核（核心）

**队列** 一行一段对话，标签：结论待定（默认）· 有未判条目 · 模型抽检 · 人工≠机器 · 会话失败。每行：会话结论、用例与首句输入、RunTag、当前分数区间、待判条目按类型计数。结论待定按「区间离及格线最近、待判少的在前」排序。只计当前标签总数。

**复核页** 布局：面包屑 → 标题 → RunTag → 结论条 → 左对话、右评分表（吸附，自身滚动；窄屏上下堆叠）。

| 区域 | 内容 |
| --- | --- |
| 结论条 | 会话分（已定时为数，未定时为区间「42–88 分」，前提未判时「≤ 89 分」）+ 分数条（区间与及格线）+ 结论与原因（含触发的否决项）+「提交 N 项并下一段」「上一段」「跳过」 |
| 对话 | 每轮：用户输入、助手回答（markdown，不截断）、本轮观测（技能加载、反问、错误、ec 注入是否生效）；选中条目时关联轮次高亮、该条关键词高亮 |
| 评分表 | 按判定顺序分节（前提 → 路径 → 禁止 → 必要 → 期望），节标题写清怎样影响分数。每行：类型与编号、轮次、权重、行状态；期望文本；机器栏（结论与分、来源、算子@版本与判定模型、理由、判定轨迹）；人工栏（快捷分值按钮、0–100 分数框、同意机器、理由） |
| 总分区 | 会话分、来源（自动 / 人工给定）、逐项展开的计算式、否决项、「手改总分」（分数 + 必填理由，可改回自动） |

行状态：待判（机器未决且参与结论）· 待提交（本页草稿）· 人工（已有有效人工分，显示评审人、时间、理由）· 改判作废（期望或回答已变，原人工分失效）· 不计分（权重 0、前提不成立后的事实、forced 的路径）。

键盘：`J`/`K` 换条目 · `1`–`9` 快捷分 · `N` 输入分数 · `Y` 同意机器 · `E` 理由 · `T` 手改总分 · `Ctrl+Enter` 提交本段并进下一段 · `[`/`]` 上一段/跳过 · `Esc` 离开输入框。

交互规则：

- 选值即草稿，结论条立即显示服务端预览（不落库）的分数与结论；有草稿时离开页面浏览器提示。
- 一次提交本段全部草稿：同一事务内逐条校验、追加、重算一次结论；任一条不合法则整体不写入并指出哪条。
- 「同意机器」写一条与机器分相同的人工记录：不改变分数，但计入人机分差统计，是模型抽检的手段。
- 改判只追加，以最后一条为准；不提供撤销。
- ec 前提行显示注入观测；未观测到时提示「若判不成立，原因可能是注入被遮蔽」。

### 3.5 结果对比

「比较什么」（中文选项：知识库、被测配置、被测模型、干预模式、期望版本）· 基线 · 对照 · 更多条件（取代手写 `fix=`/`any=`；放行规则沿用 09 的比较轴）。结果依次为：变好/变差/不变各几题（按题目分变化是否超过 `compare_delta`，锚点绊线计入变差并标出）→ 两侧综合分构成（只取共有维度）→ 组件贡献（单组件：综合分与各维度差及 95% 区间）→ 多组件分摊（选一组构成全因子设计的 run，Shapley，缺组合时列出需补跑的组合）→ 逐题差异。

### 3.6 判定质量

算子 × 条目类型：人工复核数、平均分差、分差 ≤ 10 的占比（95% 区间）、分歧数（链到复核队列「人工≠机器」并带算子筛选）、建议（阈值提示，不自动生效）。另有：作废的人工分数、数据来源（评测库、判定配置列表与判定模型、口径摘要）。原质量页中关于用例本身的信号（变体泄露、注入 found>1、前提不成立、forced 前提成立率偏低）移到用例页的体检标记。

## 4. 打分口径

```
条目分 ──权重──▶ 会话分 ──trial 平均──▶ 题目分 ──用例平均──▶ 维度分 ──维度权重──▶ 综合分
                    │                                                     │
                 及格线 → 通过/失败                            配置之间的差 → 组件贡献
```

### 4.1 条目分

| 条目 | 计分 | 快捷分值（`policy.score.map`） |
| --- | --- | --- |
| 必要 F、期望 E | 按权重计分 | 对 100 · 部分 50 · 未提及 0 · 错 0 |
| 禁止 X | 否决项（`veto` 为 `weight` 时按权重计分） | 未采信 100 · 采信 0 |
| 路径 | 否决项（同上）；不适用 = 不计 | 满足 100 · 违反 0 |
| 拒答（不可回答题） | 即会话分 | 拒答 100 · 未拒答 0 |
| 前提 P | 门槛，不打分 | 成立 / 不成立 |

- 结论词是快捷分值；也可给 0–100 任意整数，结论词记为最接近的快捷值（「自定」）。
- **条目分 = 显式分数 ?? map[结论词]**。显式分数只来自模型算子输出或人工自定，因此改 `map` 只需 `rescore`，不需重判。

### 4.2 会话分

权重写在用例 md：`【权重：N】`，N ≥ 0、至多一位小数；未写按 `default_weight`（1）；0 = 只记录。组（满足其一）为一个计分单位：组分 = 组内最高分，组权重 = 组内最大权重。

```
自动会话分 = round(Σ 权重 × 条目分 / Σ 权重)
```

依次：前提（实际值）不成立 → `invalid`，不计分 → 否决项（`zero` 记 0 / `cap` 封顶 / `weight` 不特殊处理；必要事实「错」只看实际值，与 09 §3.1 一致）→ 人工会话分（有效时取代自动分）。通过 = 会话分 ≥ `pass_mark`。

**未判条目（两点求值改为 0/100）**：未判条目取最有利值（计分条目 100、前提成立、未采信、满足）与最不利值（0、不成立、采信、违反）各算一次，得到 `[score_min, score_max]`；最不利一次前提不成立时 `score_min` 为空（显示「≤ max」）。

| 情况 | 会话状态 |
| --- | --- |
| 前提实际不成立 | invalid |
| 有效人工会话分 | 按人工分与及格线 |
| `score_min` 为空（前提未判） | undecided |
| `score_min ≥ pass_mark` / `score_max < pass_mark` | pass / fail（已确定，未判条目可选复核） |
| 区间跨过及格线，含算子异常 | error |
| 区间跨过及格线 | undecided（`policy.undecided: fail` 时记 fail） |

**样例**（ec-0201，规则+模型，P1 人工「成立」）：F1 权重 2 模型 90、F2 权重 1 规则「对」100、E1 权重 0.5 模型 60、X1「未采信」、路径「满足」→ (180 + 100 + 30) / 3.5 = 88.6 → **89，pass**。F1 改为 30 → (60 + 100 + 30) / 3.5 = 54.3 → **54，fail**。X1「采信」→ 否决 → **0**。P1 未判 → **≤ 89，undecided**。

### 4.3 题目分、维度分、综合分

- **题目分**：同一 qkey、同一配置下已确定会话（pass/fail）的会话分平均；invalid、undecided、error 不计。全部 trial 无效的题目进用例体检、不进维度分。
- **维度分**：同一用例的各题目分平均为用例分，维度内用例分平均（`dimension_unit: case`；可改 `question`）。只取 `headline_mode` 的会话（ec 为 forced）。95% 区间：按用例自助法（B = 1000，固定种子）。
- **综合分**：`Σ 维度权重 × 维度分 / Σ 维度权重`（`policy.score.dimensions`，默认各 1）；缺维度按已有维度归一并标「不完整」，不完整的综合分不与完整的比较；比较时取两侧共有维度。任一维度临时，综合分临时。

**样例**：ec-0201 trial 89、54、invalid → 71.5；ec-0202 种子 (80+76)/2 = 78、V1 (70+74)/2 = 72 → 75；ec-0203 → 41；错误知识纠正 = (71.5 + 75 + 41) / 3 = **62.5**。四维度 78.2、70.0、85.0、62.5 等权 → 综合分 295.7 / 4 = **73.9**。

### 4.4 组件贡献

组件 = run 的可变条件：被测模型与努力程度、知识库（`skills_base`）、harness 配置（Profile 其余字段）、期望版本。

- **单组件**：两侧只差一个组件（比较轴即该组件，其余按 09 比较轴规则一致），在共有题目上分别算维度分与综合分，贡献 = 对照 − 基线；区间按用例配对自助法。
  样例：知识召回 +3.1、多轮 −1.2、同义 +0.4、ec +9.0 → 综合分 73.9 → 76.8，**+2.8**（= (3.1 − 1.2 + 0.4 + 9.0) / 4）。
- **多组件**：k 个两水平组件（k ≤ 3）的全因子设计，以各格综合分 v(S)（S = 处于「对照」水平的组件集合）计算 Shapley 值：
  `φ_i = Σ_{S ⊆ F∖{i}} |S|!(k−|S|−1)!/k! · [v(S∪{i}) − v(S)]`，Σφ_i = v(F) − v(∅)。缺任一格时不分摊，列出需补跑的组合。
  样例（模型 low/high × 知识库 v1/v2：66、70、71、78）：模型 (4 + 7)/2 = **+5.5**，知识库 (5 + 8)/2 = **+6.5**，合计 +12.0；交互 (78 − 71) − (70 − 66) = +3.0 单独说明。

### 4.5 policy.yaml

```yaml
schema: 2
undecided: exclude
headline_mode: {default: natural, 错误知识纠正: forced}
score:
  pass_mark: 60
  pass_rule: threshold       # threshold：会话分 ≥ 及格线 | strict：沿用 09 的全满足规则（对拍与历史对照用）
  default_weight: 1
  map: {对: 100, 部分: 50, 未提及: 0, 错: 0, 满足: 100, 违反: 0, 未采信: 100, 采信: 0, 拒答: 100, 未拒答: 0}
  veto: {forbidden_adopted: zero, path_violated: zero, required_wrong: zero, cap: 40}
  dimension_unit: case
  dimensions: {知识召回: 1, 多轮上下文召回: 1, 同义请求一致性: 1, 错误知识纠正: 1}
  compare_delta: 10
```

- `partial_as`、`veto_on_forbidden` 在 `schema: 2` 中移除（出现即报错并提示改写）；`schema: 1` 文件仍可读，按 `pass_rule: strict` 解释，保证旧口径可复现。
- `pass_rule: strict` 下仍计算分数，通过/失败与 09 完全一致——这是 `tests/test_scoring.py` 对拍继续成立的前提。

## 5. 数据

### 5.1 用例与编译行（D2）

- md：事实、禁止事实、路径条目可写 `【权重：N】`（`md2case.p_facts`、`p_path` 读取 `attrs["权重"]`；非数、负数、超过一位小数报错）；组成员权重不一致时警告（取最大）。
- 编译行：条目加 `weight`（缺省不写，读取方按 `default_weight`）。
- 指纹：`judge_fp_of` 的 facts、path 载荷加 `weight`（改权重 → judge_fp 变 → 需 `rejudge`；判定缓存保证不重复调模型）；`item_sha_of` 不加（人工分继续有效）。
- CASE-STRUCTURE.md 补「权重」一节；`md2case check` 打印每个用例的权重合计。

```sql
ALTER TABLE verdict_cache ADD COLUMN score REAL;
ALTER TABLE reviews       ADD COLUMN score REAL;          -- 仅自定分；点快捷值时为 NULL
-- reviews.item_id = '@total'：人工会话分，item_sha 存 judge_fp，answer_sha 存整段回答指纹，reason 必填
ALTER TABLE conclusions   ADD COLUMN score REAL;
ALTER TABLE conclusions   ADD COLUMN score_min REAL;
ALTER TABLE conclusions   ADD COLUMN score_max REAL;
ALTER TABLE conclusions   ADD COLUMN auto_score REAL;
ALTER TABLE conclusions   ADD COLUMN score_source TEXT;   -- auto / human
ALTER TABLE answers       ADD COLUMN injection_observed_json TEXT;  -- {"J1": true}，runner 未提供时 NULL
CREATE TABLE IF NOT EXISTS chains(
  chain_sha TEXT PRIMARY KEY, name TEXT, operators_json TEXT, judge_models_json TEXT, created_at TEXT);
CREATE INDEX IF NOT EXISTS idx_conclusions_answer ON conclusions(answer_id, judge_fp, chain_sha, policy_sha);
```

迁移 `_migrate_v4`：只加列与表，不改写已有数据；`chains` 由已有 `verdicts.chain_sha` 回填（名称留空、算子列表取当前 operators.yaml 中 chain_sha 相同者）。会话分在下一次 `rescore` 时按新 policy_sha 物化——结论表本就按 `policy_sha` 分键，旧口径结论保留可回看。serve 启动时若当前 policy_sha 无结论，页面提示 `python -m scoring rescore`。

### 6.2 operators.py / chain.py（D4）

- `judge_item`：算子返回 `score` 时校验 `0 ≤ score ≤ 100`，否则记 error；`value` 仍须在 scale 内（模型算子给分时同时给最接近的结论词）。
- `VerdictCache` 与 `DbCache` 读写 `score`。
- 判定行（`judge_episode` 输出）加 `machine.score`。规则算子不改。

### 6.3 policy.py（D1）

```python
@dataclass
class ScorePolicy:
    pass_mark: float = 60
    pass_rule: str = "threshold"          # threshold | strict
    default_weight: float = 1
    map: dict[str, float] = ...            # §4.5
    veto: dict[str, str] = ...             # forbidden_adopted / path_violated / required_wrong → zero|cap|weight
    cap: float = 40
    dimension_unit: str = "case"
    dimensions: dict[str, float] = ...
    compare_delta: float = 10

@dataclass
class Policy:
    undecided: str = "exclude"
    headline_mode: dict = ...
    score: ScorePolicy = field(default_factory=ScorePolicy)
```

- `policy_from_dict`：识别 `schema: 1/2`；校验 `score` 节（未知键、取值范围、map 覆盖全部 scale 取值、veto 枚举）。
- `EpisodeVerdict` 加：`score`、`score_min`、`score_max`、`auto_score`、`score_source`、`vetoes: list[str]`、`parts: list[dict]`（`{id, weight, score, counted}`，计算式与评分表用）。
- `session_conclusion` 拆为两步，保留现有分类与短路记录逻辑：
  1. `_classify(...)`（现有前半段：decided / undecided / errored、facts_live 等）不变；
  2. 新增 `session_score(items, decided, policy, forced, answerable, override) -> ScoreResult`：按 §4.2 计算 `(auto, score)` 的有利/不利两点，返回区间、否决项与 parts；
  3. 状态判定按 §4.2 表；`pass_rule: strict` 时状态仍由现有 `evaluate(fav)` 决定，分数照算。
- `override`：调用方传入有效人工会话分（`{score, reason, reviewer, at}` 或 None）。

### 6.5 views.py（D5）

- `session_rows(rows, policy)`：只留 headline 模式与已确定会话。
- `question_scores(rows)` → `{(qkey, axis_val): {mean, n}}`；`case_scores` 按 `dimension_unit` 聚合；`dimension_scores` 附自助法区间（`random.Random(seed)`，B = 1000，纯标准库）；`composite(dim_scores, weights)` 返回分数、是否完整、缺失维度。
- `compare_scores(rows, axis, base, target, fixes, anys)`：复用 `compare_axis` 的放行逻辑，返回两侧综合分与维度分、按题差异（方向、是否锚点绊线）、配对区间。

- `judge_agreement(store, chain_sha)`：按算子 × 条目类型的平均绝对分差、分差 ≤ 10 的占比（Wilson 区间）；取代 `human_machine_compare` 的一致率。

## 10. 风险与待定

| 项 | 说明 | 处理 |
| --- | --- | --- |
| 通过率口径变化 | `threshold` 下「3 条必要事实对 2 条」= 67 分即通过，旧规则为失败；历史通过率不可直接对比 | 结论按 policy_sha 分键，旧口径结论保留；对比页拒绝跨 policy 比较；需要时用 `strict` 复现 |
| 权重进 judge_fp | 改权重要 `rejudge`（规则算子即时，模型算子走缓存） | 文档写明；`md2case check` 提示权重变动的用例 |
| 人工会话分滥用 | 手改总分可绕过条目分 | 理由必填；判定质量页列出人工会话分与自动分差 > 20 的对话 |
| 同义请求一致性（sc）维度分 | 暂按会话分平均，题组一致性单列 | 待定：是否改为以一致性为分 |
| 诱导变体 | 计入用例分；题组一致性中不计 | 待定：是否从维度分剔除 |
| 维度权重 | 默认各 1 | 待评测负责人确定 |
