## 1. 背景与问题

09 方案落地后，复核服务按评测库取数、分页，功能齐全。实际使用中暴露四类问题：

1. **复核单位不对。** 队列一个条目一张卡，同一段对话的回答在每张卡里重复出现，且截断到 400 字（`serve.card_material` 的 `answer[:400]`）。评审人看不到这段对话的全貌，也不知道这一条判完会话结论会怎样。
2. **评分只有通过/失败。** 讨论纪要 §5.2 要求「分数、综合分、组件贡献」三者都要有；现在只有条目结论词（对/部分/未提及/错…）和会话通过率。
3. **页面职责混乱。** 「题目列表」实际列的是变体；「题组」才是用例；比较页要手写 `fix=k=v`；质量页混合了判定可信度与用例本身的问题；模型判定接入后结论放在哪里没有位置。
4. **内容读不好。** 对话大量是 markdown，但队列与用户输入按纯文本显示；`md_filter` 在依赖缺失时静默退化为纯文本；结论以颜色区分且混用（「禁止事实」类型标签用的是「错」的红色）。

另有两项输入：

- 84c48b7 起 run 级可指定被测模型与努力程度（Profile `model` + `reasoning_effort`；`--model` 覆盖时 profile id 追加 `@模型-努力`）。界面上必须把「被测模型」与「判定模型」分开。
- 讨论纪要 §4.1：ec 的「agent 未采信」与「注入被遮蔽」都表现为前提不成立，需要逐会话的注入观测来区分。

## 2. 目标与范围

| # | 目标 | 验收口径 |
| --- | --- | --- |
| G1 | 以对话为单位复核：一段对话一页，全部条目一张评分表，一次提交 | 原型复核页的交互全部可用；提交后结论与分数即时更新 |
| G2 | 百分制：条目分 → 会话分 → 题目分 → 维度分 → 综合分，附组件贡献 | §6 的每个样例在单元测试中按原数复现 |
| G3 | 四个页面各答一个问题：用例 / 复核 / 结果对比 / 判定质量 | §4 页面职责表 |
| G4 | 机器（规则、模型）与人工分开记、并列显示；可切换判定配置；人机分差可统计 | 判定质量页按算子 × 条目类型给出分差 |
| G5 | 全部对话内容按 markdown 渲染，高亮不破坏结构 | 表格、列表、代码块、引用正确显示并可高亮关键词 |
| G6 | 规模不退化 | 1 万答案 / 10 万判定的合成库上，用例页、复核队列、复核页 < 1 秒（沿用 09 §12） |

## 4. 信息架构

### 4.1 页面职责

| 页面 | 路由 | 回答的问题 | 取代 |
| --- | --- | --- | --- |
| 用例（首页） | `/` | 评测集里有什么，每个用例考什么、得多少分 | `/` 题目列表 |
| 用例详情 | `/case/{case_id}` | 这个用例的控制字段、期望、变体、全部对话与分数 | `/question/{qkey}`、`/group/{case_id}` |
| 复核队列 | `/review` | 还有哪些对话要人判 | `/queue` |
| 复核页 | `/review/{answer_id}` | 这段对话该给几分 | 队列里的条目卡 |
| 结果对比 | `/compare` | 换了组件，变好还是变坏；各组件贡献多少 | `/compare` |
| 判定质量 | `/judging` | 机器判得准不准，能不能少看一点 | `/quality`（用例相关信号移到用例页） |

旧路由保留一个版本的 301：`/question/{qkey}` → `/case/{case_id}#{uid}`；`/group/{case_id}` → `/case/{case_id}`；`/queue?filter_name=x` → `/review?tab=x`；`/quality` → `/judging`。

### 4.2 术语

用例（`case_id`，如 kr-0201）下有种子题与变体，每个是一道**题目**（`qkey`）；**对话**是一道题在一次 run、一个配置下的一次完整会话（`answer_id`）；**条目**是期望的一项（前提 P、必要 F、期望 E、禁止 X、路径、拒答）；**会话分 / 会话结论**是一段对话的分数与 通过/失败/无效/未决/异常。

## 5. 交互规范（对照原型）

### 5.1 公共

- 顶栏：服务名 · 四个视图（用例 / 复核 / 结果对比 / 判定质量）· 复核计数（结论待定的**对话**数）· **判定配置**下拉（URL 参数 `chain`，缺省为启动配置）。
- **两个「模型」严格区分**：被测（agent 的 `models_observed` + Profile `reasoning_effort`，显示在 RunTag，前缀「被测」）与判定（模型算子的模型，属于判定配置，显示在评分表机器栏与判定配置下拉）。
- 结论一律「符号 + 中文词 + 底色」：✓ 通过 · ✕ 失败 · – 无效 · ? 未决 · ! 异常；条目类型（必要/禁止…）用中性描边标签，不用结论色。
- 临时数字：有未决被排除时，平均分、综合分标「临时」。
- 页面不触发判定：缺判定时给出 `rejudge` 命令与复制按钮（局域网 http 下剪贴板不可用时退化为选中文字）。
- 评审人姓名记在 `localStorage` 并预填。

### 5.2 复核队列 `/review`

- 一行一段对话：会话结论徽标 · 用例/变体与首句用户输入 · RunTag · 当前分数区间（如「45–70 分」「≤ 89 分」）· 待判条目数与按类型计数。
- 标签：**结论待定**（默认：会话分区间跨过及格线或前提未判）· 有未判条目（结论已定、仍有未判）· **模型抽检**（模型算子判过、无人工的对话，固定种子随机抽样，比例 10%/20%/全部）· 人工≠机器 · 会话失败。
- 排序：结论待定按「区间离及格线近、待判少」在前。只计当前标签总数。
- 「待重判」不再是标签，改为顶部提示：N 段对话在当前判定配置下缺判定 + 命令。

### 5.3 复核页 `/review/{answer_id}`

布局：面包屑（复核 / 标签 / 第 N 段，共 M 段）→ 标题（uid、维度、主题、变体、用例详情链接）→ RunTag → **结论条** → 左**对话**、右**评分表**（吸附、自身滚动；窄于 1100px 上下堆叠）。

| 区域 | 内容 |
| --- | --- |
| 结论条 | 会话分（确定时为数；未定时为区间「42–88 分」；前提未判时「≤ 89 分」）· 分数条（区间与及格线）· 结论与原因（含触发的否决项）· 「提交 N 项并下一段」「上一段」「跳过」 |
| 对话 | 每轮：用户输入、助手回答（markdown，不截断、不折叠）、本轮观测（技能加载、反问次数、错误、ec 注入是否生效）。选中条目时关联轮次高亮、该条关键词高亮 |
| 评分表 | 按判定顺序分节：前提（门槛，不打分）→ 路径 → 禁止事实（否决项）→ 必要事实 → 期望事实；节标题写明对分数的影响。每行：类型与编号 · 轮次 · 组 · **权重** · 行状态；期望文本与关键词；**机器栏**（结论与分、来源 规则/模型、算子@版本与判定模型、理由、判定轨迹如 `keyword:abstain → llm-fact:hit`）；**人工栏**（快捷分值按钮 `对 100`…、0–100 分数框、同意机器、理由） |
| 总分区 | 会话分 / 100 · 来源（自动 / 人工给定）· 逐项展开的计算式 `Σ(权重×分)/Σ权重 = (2×90 + 1×100 + 0.5×60)/3.5` · 触发的否决项 · 「手改总分」（分数 + 必填理由；可改回自动） |

行状态：**待判**（机器未决且参与计分）· **待提交**（本页草稿）· **人工**（有效人工分，显示评审人、时间、理由，机器值保留对照）· **改判作废**（期望文本或回答变了，原人工分失效，按待判处理）· **不计分**（权重 0、前提不成立后的事实、forced 的路径）。ec 前提行显示注入观测；「未观测到」时提示「若判不成立，原因可能是注入被遮蔽」。

键盘：`J`/`K` 换条目 · `1`–`9` 快捷分 · `N` 输入分数 · `Y` 同意机器 · `E` 理由 · `T` 手改总分 · `Ctrl+Enter` 提交本段并进下一段 · `[`/`]` 上一段/跳过 · `Esc` 离开输入框。

规则：

- 选值即草稿，结论条立即显示服务端预览（不落库）的分数与结论；有草稿时离开页面浏览器提示。
- 一次提交本段全部草稿：同一事务内逐条校验、追加、重算一次结论；任一条不合法则整体不写入并指出哪条。
- **同意机器** = 写一条与机器分相同的人工记录：不改分数，计入人机分差统计，是模型抽检的手段。
- 不提供撤销：改判只追加，以最后一条有效记录为准。
- 提交失败在结论条下显示错误横幅，草稿保留，不用 `alert()`。

### 5.4 用例页与用例详情

- 用例页：综合分构成（维度分 × 权重，缺维度标「不完整」，临时标记）· 磁贴（结论待定对话、已确定对话、用例体检）· 筛选（维度、主题、粒度、排序、只看有体检标记，控件都有可见标签）· 用例表（一行一个 `case_id`：变体数、对话数、结论待定、用例分、难度、区分度、稳定性、题组一致、体检标记；列头 `title` 写定义）。
- 用例详情：控制字段（维度、主题、粒度、可回答、对话方式、主口径、关键条件、注入、标签、体检）→ 期望（各轮输入、条目、权重、参考答案；历史期望下拉切换）→ 变体 → 对话列表（一行一段：会话结论、分数、RunTag、条目小结、复核链接；按比较轴分组）。旧题目视图「轮次为行、run 为列」的宽表在 3 列以上不可读，改为列表；需要逐轮对照时勾选两段并排查看。
- 用例详情的信息分层（2026-10-24）：提问、判定条目、体检等必要信息始终全文显示；参考答案用 native `details` 折叠；页头密度切换（舒适/紧凑，localStorage 记忆）、变体选择（滑动指示条 + 面板淡入：默认只看首个变体并同步收敛下方对话，可切到任一变体或「全部」；`?variant=` 只决定初始焦点，无 JS 时服务端直接渲染选中变体）、对话筛选（全部/待定/异常，各状态计数随变体范围联动）、并排勾选计数（最多两段，满两段才能提交，切换变体时隐藏段自动退出）均为纯前端展示切换，不改动服务端语义。
- 用例体检标记（原质量页中关于用例本身的信号）：变体泄露嫌疑、注入 found>1、前提不成立、forced 前提成立率偏低。

### 5.5 结果对比 `/compare`

- 条件：「比较什么」（中文选项：知识库 skills_base、被测配置 profile、被测模型 model、干预模式 mode、期望版本 evalset_version）· 基线 · 对照（从已有取值下拉）· 更多条件（勾选放开的属性；取代手写 `fix=`/`any=`；放行规则沿用 09 比较轴）。
- 结果依次：变好 / 变差（含锚点绊线）/ 不变各几题 → 两侧综合分构成（只取共有维度）→ **组件贡献**（单组件：综合分与各维度差及 95% 区间）→ **多组件分摊**（选一组构成全因子设计的 run，Shapley；缺组合时列出需补跑的组合）→ 逐题差异（只列变化超过阈值的题，链到用例详情）→ 被拒或被排除的说明。

### 5.6 判定质量 `/judging`

- 主表：算子 × 条目类型 · 人工复核数（含「同意机器」）· 平均分差（|机器分 − 人工分|）· 分差 ≤ 10 的占比（95% 区间）· 分歧数（链到复核队列「人工≠机器」并带算子筛选）· 建议（阈值提示：区间下限 ≥ 90% 可转抽检、n < 30 样本不足；不自动生效）。
- 另有：作废的人工记录 · 人工会话分与自动分差 > 20 的对话 · 数据来源（评测库、判定配置列表与判定模型、口径摘要）。

## 6. 打分口径

```
条目分 ──权重──▶ 会话分 ──trial 平均──▶ 题目分 ──用例平均──▶ 维度分 ──维度权重──▶ 综合分
                    │                                                     │
                 及格线 → 通过/失败                            配置之间的差 → 组件贡献
```

### 6.1 条目分

| 条目 | 计分方式 | 快捷分值（`policy.score.map`） |
| --- | --- | --- |
| 必要 F、期望 E | 按权重计分 | 对 100 · 部分 50 · 未提及 0 · 错 0 |
| 禁止 X | 否决项（`veto` 为 `weight` 时按权重计分） | 未采信 100 · 采信 0 |
| 路径 | 否决项（同上）；不适用 = 不计 | 满足 100 · 违反 0 |
| 拒答（不可回答题） | 即会话分 | 拒答 100 · 未拒答 0 |
| 前提 P | 门槛，不打分 | 成立 / 不成立 |

**条目分 = 显式分 ?? map[结论词]**。显式分只来自模型算子输出或人工自定，所以改 `map` 只需 `rescore`、不需重判。自定分时结论词记为最接近的快捷值。

### 6.2 会话分

组（满足其一）为一个计分单位：组分 = 组内最高分，组权重 = 组内最大权重。

```
自动会话分 = round_half_up( Σ 权重 × 条目分 / Σ 权重 )      （没有计分条目时为 100）
```

依次：前提（实际值）不成立 → `invalid`，不计分 → 否决项：`zero` 记 0 / `cap` 不超过 `cap` / `weight` 作为普通条目计入（必要事实「错」只看实际值，与 09 §3.1 一致；路径违反只在 `zero` 时短路后续事实）→ 有效的人工会话分取代自动分。**通过** = 会话分 ≥ `pass_mark`。

**未判条目（两点求值）**：未判条目分别取最有利值（计分条目 100、前提成立、未采信、满足）与最不利值（0、不成立、采信、违反）各算一次，得到 `[score_min, score_max]`；最不利一次前提不成立时 `score_min` 为空（显示「≤ max」）。

| 情况 | 会话状态 |
| --- | --- |
| 前提实际不成立 | invalid |
| 有效人工会话分 | 按人工分与及格线 |
| `score_min` 为空（前提未判） | undecided |
| `score_min ≥ pass_mark` / `score_max < pass_mark` | pass / fail（结论已定，未判条目可选复核） |
| 区间跨过及格线，且未判中有算子异常 | error |
| 区间跨过及格线 | undecided（`policy.undecided: fail` 时记 fail） |

**确定的会话分**：区间收敛为一点（或有人工会话分）时记 `score`；结论已定但区间未收敛时 `score` 为空、只记区间。平均分只计有确定会话分的会话，其余计为被排除、平均分标「临时」。

**样例**（ec-0201：F1 权重 2、F2 权重 1、E1 权重 0.5；X1 禁止；路径必须加载 trade-documents）

| 输入 | 计算 | 结果 |
| --- | --- | --- |
| P1 成立；F1 模型 90；F2 规则「对」；E1 模型 60；X1 未采信；路径满足 | (2×90 + 1×100 + 0.5×60) / 3.5 = 88.6 | **89，pass** |
| 同上，F1 人工改为 30 | (60 + 100 + 30) / 3.5 = 54.3 | **54，fail** |
| 同上，X1「采信」 | 否决 forbidden_adopted = zero | **0，fail**（自动分 89） |
| 同上，P1 未判 | 最不利一次前提不成立 | **≤ 89，undecided** |
| P1 成立，E1 未判，其余同第一行 | (180+100+0)/3.5 = 80 ~ (180+100+50)/3.5 = 94 | **80–94，pass**（结论已定，无确定分） |
| 第二行 + 人工会话分 65（写理由） | 取代自动分 54 | **65，pass** |

### 6.3 题目分、维度分、综合分

- **题目分**：同一 qkey、同一配置下有确定会话分的会话的平均。全部 trial 无效的题目进用例体检、不进维度分。
- **维度分**：同一用例的各题目分平均为用例分（诱导变体 `exclude_rewrites: [诱导]` 不计入），维度内用例分平均（`dimension_unit: case`；可改 `question`）。只取 `headline_mode` 的会话（ec 为 forced）。sc 与其他维度相同，题组一致性单列。95% 区间：按用例自助法（B = 1000，固定种子）。
- **综合分**：`Σ 维度权重 × 维度分 / Σ 维度权重`（默认各 1）；缺维度按已有维度归一并标「不完整」，不完整的综合分不与完整的比较；任一维度临时则综合分临时。

样例：ec-0201 trial 89、54、invalid → 71.5；ec-0202 种子 (80+76)/2 = 78、V1 (70+74)/2 = 72 → 75；ec-0203 → 41；错误知识纠正 = (71.5 + 75 + 41) / 3 = **62.5**。四维度 78.2、70.0、85.0、62.5 → 综合分 295.7 / 4 = **73.9**。

### 6.4 组件贡献

组件 = run 的可变条件：被测模型与努力程度、知识库（`skills_base`）、harness 配置（Profile 其余字段）、期望版本。

- **单组件**：两侧只差一个组件（比较轴即该组件，其余按 09 比较轴规则一致），在共有题目上分别算维度分与综合分，贡献 = 对照 − 基线，区间按用例配对自助法。
  样例：知识召回 +3.1、多轮 −1.2、同义 +0.4、错误知识纠正 +9.0 → 综合分 73.9 → 76.8，**+2.8** = (3.1 − 1.2 + 0.4 + 9.0) / 4。
- **多组件**：k 个两水平组件（k ≤ 3）的全因子设计，以各格综合分 v(S)（S = 处于「对照」水平的组件集合）计算 Shapley 值
  `φ_i = Σ_{S ⊆ F∖{i}} |S|!(k−|S|−1)!/k! · [v(S∪{i}) − v(S)]`，Σφ_i = v(F) − v(∅)。缺任一格时不分摊，列出需补跑的组合。
  样例（被测努力 low/high × 知识库 v1/v2：66、70、71、78）：模型 (4 + 7)/2 = **+5.5**，知识库 (5 + 8)/2 = **+6.5**，合计 +12.0；交互 (78 − 71) − (70 − 66) = +3.0 单独说明。

## 7. 数据

### 7.1 用例与编译行

- md：必要/期望/禁止事实与路径可写 `【权重：N】`（N ≥ 0、至多一位小数）。
- 编译行：条目加 `weight`（**未写时不出现**，读取方按 `default_weight`）。这样现有评测集的判定指纹不变，不会触发全量重判。
- 指纹：`judge_fp_of` 的 facts 载荷在有 `weight` 时带上（path 本就整条进指纹）；`item_sha_of` 不变——改权重需 `rejudge`（判定缓存保证不重复调模型），已有人工分继续有效。
- 组内权重不一致：`md2case check` 警告，计分取最大。

### 7.2 评测库 schema v4

```sql
ALTER TABLE verdicts      ADD COLUMN score REAL;          -- 仅显式分（模型算子）；规则为 NULL，按 map 换算
ALTER TABLE verdict_cache ADD COLUMN score REAL;
ALTER TABLE reviews       ADD COLUMN score REAL;          -- 仅自定分；点快捷值时为 NULL
-- reviews.item_id = '@total'：人工会话分；item_sha 存 judge_fp，answer_sha 存整段回答指纹，reason 必填
ALTER TABLE conclusions   ADD COLUMN score REAL;          -- 确定的会话分，区间未收敛时 NULL
ALTER TABLE conclusions   ADD COLUMN score_min REAL;      -- 前提可能不成立时 NULL
ALTER TABLE conclusions   ADD COLUMN score_max REAL;
ALTER TABLE conclusions   ADD COLUMN auto_score REAL;
ALTER TABLE conclusions   ADD COLUMN score_source TEXT;   -- auto / human
ALTER TABLE answers       ADD COLUMN injection_observed_json TEXT;   -- {"J1": true}；runner 未提供时 NULL
CREATE TABLE IF NOT EXISTS chains(
  chain_sha TEXT PRIMARY KEY, name TEXT, operators_json TEXT, judge_models_json TEXT, created_at TEXT);
INSERT OR IGNORE INTO chains(chain_sha) SELECT DISTINCT chain_sha FROM verdicts;
```

- 迁移只加列与表，不改写已有数据。结论表本就按 `policy_sha` 分键：新 policy 的会话分在下一次 `rescore` 时物化，旧口径结论行保留可回看。
- serve 启动时若当前 policy_sha 下无结论，页面提示执行 `python -m scoring rescore`。
- 题目分、维度分、综合分、组件贡献都从 `conclusions` 现算，不落库。

### 8.1 evalset：md2case.py、mapping.yaml

### 8.4 scoring/policy.py

```python

    pass_mark: float = 60
    default_weight: float = 1
```

  - `FAVORABLE` / `UNFAVORABLE` 补 `expected`。

  - 否决原因取**最有利一次**的否决项：最有利一次的未判条目取有利值，否决只可能来自实际判定值。
  - 取整用四舍五入（`int(x + 0.5)`），不用 Python `round` 的银行家舍入（60.5 → 61）。
  - 人工会话分只在前提**实际**不成立时不生效。
