# 用例页重构方案：用例页 + 下一层的对话页

版本：v3.1（2026-10-27）· 基线：`feat/eval-gaps` d3c9310 · 状态：方案，待实施

可交互原型：[`13-用例页原型.html`](13-用例页原型.html)，离线单文件，用浏览器直接打开即可。设计系统里有三张对应的卡片：`CasePrototype`（可交互）、`CaseOverview`（第一层）、`CaseConversations`（第二层）。

**版本修订**

- **v1**：以 `main` c5d76e9 为基线，把对话拆成单独一页。
- **v2**：改以 `feat/eval-gaps` 为基线，保留该分支已有的能力：
  - 变体按钮组；
  - 条目详情；
  - 权重饼图编辑；
  - 并排对照；
  - 期望版本、执行记录可以命名。
- **v3**（本版），按评审意见做两处调整：
  1. **对话移到下一层**。不再用「概览 | 对话」两个并排的子标签，而是从用例页的「各配置表现」色块或「全部对话」按钮进入，面包屑写成「用例管理 / ec-0201 / 对话」，可以逐级返回。
  2. **视觉重新设计，减少框线和标签**：
     - 页头不再套卡片；
     - 结果收成一行指标条；
     - 题面与期望按轮次排成时间线，条目做成无边框的行；
     - 右侧改为属性栏，各段之间只用细线分隔；
     - 矩阵改成按分数着色的色块；
     - 对话页的筛选改成一排下拉，列表和阅读区左右分栏，类似邮件客户端。

## 1. 现状分析（feat/eval-gaps d3c9310）

`/case/{case_id}` 对应 `serve.py` 的 `case_detail`、模板 `case.html` 和脚本 `case.js`（425 行）。页面从上到下是五块：

| 顺序 | 块 | 内容 | 问题 |
| --- | --- | --- | --- |
| 1 | 页头 `.rv-case-hero` | 面包屑；用例号；维度、主题、粒度标签；主口径；变体数和对话数；用例体检 | 期望版本、被测配置、「去复核」都不在页头，要往下翻才能找到 |
| 2 | 概览卡 `.rv-caseinfo` | 维度、主题、粒度、变体数、可回答、对话方式、关键条件、知识注入、标签、用例体检 | ① 维度、粒度、体检和页头重复。② 「关键条件」把前提和路径又写了一遍，期望卡里也有。③ 条件槽位 `conditions`、证据 `evidence`、备注 `note` 都没有展示。④ 知识注入只写了注入点和选项，看不到原文和注入后的文字 |
| 3 | 期望卡 | 提问全文；条目简要列表（截到 36 字），点「详情」在列表下方统一展开；右侧是 240px 的权重饼图编辑器 | ① 条目没有按轮次归组，多轮用例看不出哪条属于哪一轮。② 详情总在列表底部展开，离被点的那一行很远。③ 饼图占了卡片右半边，把左边的提问和条目挤窄了 |
| 4 | 变体卡 | 变体按钮组；选中的变体显示说明面板（对话数、待定、分数、提问全文、「查看该变体对话 ↓」） | ① 选种子时，提问全文和期望卡里的那份重复。② 变体的分数不分配置，不同配置的分数混在一起平均 |
| 5 | 对话卡 | 「全部 / 待定 / 异常」筛选；勾选两段并排对照；按比较轴分组的对话列表；并排对照区 | ① 段数等于变体数 × 配置数 × 次数，很快就有几十行，把前四块挤得看不见。② 页面上没有被测配置选择，详情页的分数和首页按配置算的分数对不上。③ 每段对话都单独查一次 `store.conclusion` 和 `store.effective_rows`，查询次数随段数线性增长 |

另外有两个属于全站外壳的问题，不在本页范围内，这里一并列出：

- 侧边栏在窄屏下仍然固定占 176px，手机宽度时正文区只剩 200px 左右。建议宽度 ≤ 640px 时，侧边栏收成顶栏。
- 在合成数据下截全页长图时，侧边栏的背景只到首屏高度。这是 `height: 100vh` 加 `position: sticky` 的效果，在浏览器里正常滚动看不出问题，可以不改。

## 2. 目标

1. **两层结构**：
   - **用例（第一层）**：回答「这道题考什么、结果大致怎样」。
   - **对话（第二层）**：回答「是哪几段对话、各自怎么判的」，按需进入。
2. **第一层只有一个主区**：主区是题面与期望，右侧是属性栏；结果用顶部的指标条加底部的色块表达，不再出现一堆卡片。
3. **保留 `feat/eval-gaps` 已有的交互，只改位置和样式**：
   - 变体切换；
   - 条目详情；
   - 权重编辑；
   - 并排对照；
   - 命名。
4. **不改库表，不改判定和评分口径。**

## 3. 信息架构与路由

```
用例管理 /                      （首页，用例表）
└─ ec-0201 /case/{id}          第一层：用例
   └─ 对话 /case/{id}/conversations?variant=…&config=…   第二层：对话（色块或「全部对话」进入）
      └─ 复核页 /review/{answer_id}                      第三层：改判（已有）
```

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `GET /case/{case_id}` | 用例 | 参数：`judge_fp`（期望版本）、`variant`（提问切换的选中项，沿用现有参数）、`saved`（权重保存后的回显，沿用现有参数）。不再需要 `config` 参数，因为各配置的结果同时显示在指标条和色块里 |
| `GET /case/{case_id}/conversations` | 对话 | 参数见 §5.1。从色块进入时带上 `variant` 和 `config`；从「待定 · 查看」进入时带上 `status=undecided` |
| `GET /case/{case_id}/conversations/peek?answer_id=…` | 阅读区片段 | 只读对话的 HTML 片段。命名上避开已有的 `POST /api/case/preview` |
| `GET /case/{case_id}?axis=…` 或 `?pair=…`（旧链接） | — | 302 跳转到对话页，`axis` 换成 `group`，`pair` 原样带过去 |

页面上的入口：

- 用例页没有「对话」标签，进入对话页只有三个入口：
  - 色块：带上该格的变体和配置；
  - 「全部 N 段对话 →」；
  - 指标条里「待定」下方的「查看」。
- 对话页的面包屑、标题前的「←」按钮都回到用例页。从用例页返回首页，走面包屑「用例管理」。
- 「复核待定 N 段 →」放在对话页右上角，链到 `/review?tab=undecided&case={case_id}`。用例页上只在指标条的「待定」格里给一个「去复核」链接。

- **页头**：不套卡片。
  - 标题：用例号，后面用小字写主题。
  - 副标题：维度 · 粒度 · 主口径 · 对话方式和轮数 · 变体数 · 可回答，用圆点分隔。
  - 右侧：期望版本下拉加 ✎（重命名沿用 `rename.js`）。只有一份期望时，只显示版本名，不显示下拉。
- **指标条**（`.rv-cp-stats`）：一行，外面只有一层边框，格子之间用竖线分隔。
  格子数固定为五个，不随配置数量增加：
  - **当前配置**：一个下拉，默认取首页的配置；下面写该配置的用例分、「临时」标记、在全部配置中的名次（第 r / N），以及一根带及格线的细条。
  - **配置分布**：一条 0～100 的轴，每个配置画一个点，≥ 60 绿色、< 60 红色，同分的点向上叠放；虚线是及格线；当前配置的点放大并描边。悬停显示配置名和分数，点一下切换当前配置。下面两行小字写最低分和最高分的配置。
  - **当前配置通过**：通过段数 / 计分段数，并注明另有几段诱导对话不计分。
  - **待定（全部配置）**：段数，带「查看 · 去复核」。
  - **用例体检**：正常时显示绿点和「正常」。
- **主体**：`grid-template-columns: minmax(0, 1fr) 320px`，两栏之间留 32px。右侧属性栏 `position: sticky`。宽度 < 1100px 时属性栏排到题面下方。
- **各配置表现**：通栏，放在主体下方。

### 4.2 题面与期望（轮次时间线）

- **提问切换**：分段控件（`.rv-cp-seg`），选项是「全部 / #0 种子 / #1 口语 / #2 诱导 不计分」，取代现在的大号变体按钮组（`.rv-vtabs`）。切换逻辑沿用 `case.js`，URL 参数仍然是 `variant`。
  - **全部**：显示种子的提问，被改写的轮次下面用一行小字列出改写后的文字。
  - **单个变体**：提问换成该变体的版本，加强调边框和「#1 口语 改写」标记，不再列出其他改写。
- **轮次**：左侧是带编号的圆点，竖线把各轮串起来；计分轮的圆点用强调色。每轮依次是：
  - 「第 i 轮」加一行小字（前提轮 · 不计分 / 计分轮）；
  - 用户提问：白底气泡；
  - 改写行；
  - 条目行。
- **条目行**（`.rv-cp-item`）：没有边框，行与行之间只有一条细分隔线。整行可以点击展开，右侧的 › 展开后转为向下。每行从左到右是：
  - **类型标记**：类型和 id，前面一个小图形区分类型：
    - 必要：蓝色实心方块；
    - 期望：绿色实心方块；
    - 禁止：红色实心圆；
    - 前提：空心方块；
    - 路径：空心红圆。
  - 条目文字，收起时截成一行；
  - **右侧数值**：计分条目显示权重百分比；禁止和路径显示红字「否决」；前提显示灰字「门槛」。

  展开后显示全文和说明：计分规则、证据来源、关键词。同一时间只展开一条，点权重环图的扇区也会展开对应条目。
- **参考答案**：放在最后，默认折叠。

### 4.3 属性栏（右侧）

各段之间只用细线分隔，不加卡片。每段的标题是 12px 灰色字，右边可以带一个摘要。各段从上到下：

1. **权重分配**：
   - 左边是 84px 的环图，中心写「已分配 x%」；右边是 F1、E1、未分配三行，每行一根细滑杠加百分比。
   - 拖动圆钮、按方向键（±1%）、双击百分比都能修改，规则与现有饼图相同：减少的部分进「未分配」，只有未分配有余量时才能增加。
   - 有改动时，「保存为新期望」按钮变为可用，旁边提示「已修改，保存后需重判」。
   - 接口不变：`/api/case/weights`，`data-qkey`、`data-fp`。
   - 当前期望没有计分条目时，这一段不显示。
2. **条件**：槽位、取值，后面用小字写轮次。
3. **知识注入**：标题右侧写「J1 · 反转 · rev 1」。正文写注入点 · 文件名，下面依次是原文（删除线）和注入后的文字（禁止色底纹）。
4. **证据**：来源，下面是引用块。
5. **备注**：`|md` 渲染。
6. **标签**：浅底圆角小标签。

某段没有数据时，整段不显示。

### 4.4 各配置表现（配置表：行 = 配置，列 = 变体）

变体数量很少（种子加 2～4 个改写），被测配置会越来越多（`CONFIG_ATTRS` 的各种组合）。所以表格固定为「行 = 配置、列 = 变体」：配置增加时，表格只往下长，不会横向撑破。

| 部分 | 内容 |
| --- | --- |
| 共同属性 | 所有配置取值都相同的属性，提到表头写成一行：「共同属性：评测集 … · 技能模式 …」。其余属性就是差异属性，在表头注明（如「模型 · 努力 · 技能基底」） |
| 配置名 | 只写差异属性，用 · 连接（如 `qwen-max · high · base-1020`）；下面一行小字写执行记录的命名（悬停显示 run_id）。点击配置名，把它设为当前配置，指标条随之切换 |
| 用例分列 | 等宽数字，旁边标「临时」，下面是一根带及格线的细条，口径与指标条一致 |
| 变体列 | 每个变体一列，表头写「#1 口语」，悬停显示问句；诱导列带「不计分」标记，色块淡显 |
| 色块 | 紧凑格：均分加每段对话一个点；底色按及格线着色（≥ 60 浅绿、< 60 浅红）；悬停显示各段分数。点击进入对话页，并带上该格的变体和配置 |
| 行顺序 | 当前配置置顶，加 ★ 和强调底色；其余按用例分从高到低，可以切换成按名称排序。默认显示 6 行，其余收进「显示其余 n 个配置」 |
| 分组 | 可以按任一差异属性分组（按模型、按努力、按技能基底）。组头写组内配置数和平均用例分，组按平均分排序；分组时不再折叠 |
| 对比 | 每行有勾选框，最多勾两个；勾满两个后「对比选中的 2 个配置 →」变为可用，跳转到 `/compare?base=…&target=…`，并限定在这个用例上。两两对比、组件贡献交给结果对比页，用例页不重复做 |
| 非主口径 | 在色块的悬停提示里写「另有 natural n 段」，不计入均分 |
| 配置很多时 | 超过 30 个配置时，表头加一个搜索框，按配置名过滤 |

### 4.5 取数

不变，与 v2 相同：

- 只用 `rows(request)`，也就是 `answer_view_rows` 里已有的结论列；
- 不再逐段调用 `store.conclusion` 和 `store.effective_rows`；
- `weight_map`、`weight_facts`、`item_details`、`variant_cards` 搬到 `_case_ctx`。

## 5. 对话页（第二层）

### 5.1 URL 参数（缺省值不写进 URL）

| 参数 | 取值 | 缺省 | 说明 |
| --- | --- | --- | --- |
| `variant` | uid，可重复 | 全部非诱导变体 | 多选 |
| `config` | 配置 key，可重复 | 全部 | |
| `status` | `undecided` / `fail` / `pass` / `invalid` / `error`，可重复 | 全部 | 取代现有的「全部 / 待定 / 异常」chips |
| `human` | `1` | 不限 | 只看有人工改判的对话 |
| `mode` | `natural` / `forced` | 全部 | |
| `sort` | `pending` / `score` / `time` | `pending` | 待定在前 / 分数低在前 / 执行顺序 |
| `pair` | answer_id，最多两个 | 无 | 沿用现有参数；两个都有时，阅读区直接显示并排对照 |
| `sel` | answer_id | 列表第一段 | 阅读区当前显示的对话 |

列表固定按变体分组，不再提供分组切换，因为变体是这一层最常用的维度。要按配置或执行记录看，用筛选。

```
│ #2 诱导 · 不计分 · 2 段未显示  显示     │ 第 2 轮                    F1 对 E1 未判 X1 未采信 │
└─────────────────────────────────────┴──────────────────────────────────────────────────┘
```

- **筛选**：一排下拉（`<details>` 弹出复选菜单，每项带分面计数）。改过的下拉高亮显示；右侧显示「x / y 段」和「清除筛选」。
  - 「被测配置」下拉在配置多时：顶部有搜索框，可以输入多个词（如「qwen high」）；提供「全选 / 清空 / 只看当前配置」三个快捷项；选项按模型分组。下拉按钮上：全选时显示「全部 N 个」，选中不超过 2 个时列出配置名，否则显示「n 个」。
  - 列表行和阅读区标题里的配置名只写差异属性，与用例页一致。
- **列表**（`.rv-cv-list`）：
  - 按变体分组，组头固定在列表顶部；不显示的变体折叠成一行「n 段未显示 · 显示」。
  - 每行三列：
    - 勾选框，用于并排对照；
    - 分数块：通过用浅绿底，失败用浅红底，待定是空心框写区间；
    - 文字：「配置 · 第几次」（有人工改判时加「人工」标记）、执行记录名、条目判定的一行彩色文字（如「F1 对 · E1 未判 · X1 未采信」）。

  选中的行左侧加强调色竖线。
- **阅读区**（`.rv-cv-read`）：
  - 标题和元信息，右上角「进入复核 →」；
  - 结论条：分数加原因，原因取 `c_reason`；
  - 逐轮对话：每轮的标题行右侧写这一轮各条目的判定；用户消息放在灰底气泡里，助手消息经 markdown 渲染。
  - 阅读区只读，不能改判。
- **并排对照**：勾选两段后，「并排对照 2/2」变为可用。点击后阅读区分成左右两栏，逐轮对照，各自带结论条。列表保留，取消勾选可以换掉其中一段；按钮变成「退出对照」。
- **键盘**：`↑` / `↓` 切换，`空格` 勾选或取消对照，`Enter` 进入复核。焦点在输入控件里时，这些快捷键不生效。
- 宽度 < 1100px 时，列表在上、阅读区在下。

## 6. 代码改动清单（基于 feat/eval-gaps）

### 6.1 `scoring/serve.py`

- `case_detail` 拆成以下几部分：
  - `_case_ctx(request, case_id, judge_fp, config)`：公共取数，包括成员、spec、历史版本、配置、`case_rows`、体检、页头计数、权重与条目详情；
  - `case_page`：`GET /case/{case_id}`；
  - `case_conversations`：`GET /case/{case_id}/conversations`，包含现有的 `pair` 逻辑；
  - `case_peek`：`GET /case/{case_id}/conversations/peek`。
- 旧链接跳转：带 `axis` 或 `pair` 参数的 `/case/{id}` 跳转到对话页。`axis=profile` 对应 `group=config`，`axis=run_id` 对应 `group=run`，其他取值对应 `group=none`。
- `review_queue` 增加 `case` 参数，传给 `store.review_conversations(..., case_id=)`，与现有的 `run_id`、`dim`、`op` 过滤方式相同。
- 首页 `cases()` 的用例链接带上 `config`。
- `/api/case/weights`、`/api/run/rename`、`/api/chain/rename` 都不变。

### 6.2 `scoring/views.py`

- `case_matrix(case_rows, members, policy, configs)`：配置表的数据。
  - 每个配置调用一次 `question_scores` 和 `case_scores`，附上每段对话的点；
  - 另外返回各配置的用例分和名次（指标条和分布图用）；
  - 返回共同属性和差异属性的拆分：逐个检查 `CONFIG_ATTRS` 的属性，所有配置取值相同的归入共同属性，其余为差异属性；
  - 返回只由差异属性拼成的配置名。
- `spec_by_turn(spec, variants, policy)`：按轮组装提问、变体改写和条目，生成说明文字和标题汇总。纯函数。
- `case_health` 已经存在，直接复用。

### 6.3 `scoring/store.py`

- `effective_rows_many(answer_ids, chain_sha)`：批量查询，结果与逐条查询一致。
- `review_conversations` 增加 `case_id` 过滤。
- 库表不变。

## 11. 可交互原型说明（`13-用例页原型.html`）

| 区域 | 可以操作 |
| --- | --- |
| 用例 · 页头 | 期望版本下拉（原型不切换数据）、✎（弹出提示） |
| 用例 · 指标条 | 切换当前配置（下拉，或点分布图上的圆点）；「待定」格里的「查看」进入对话页并按待定筛选；「去复核」弹出提示 |
| 用例 · 题面与期望 | 分段控件切换提问；点条目行展开或收起，同时只展开一条 |
| 用例 · 权重分配 | 拖动圆钮、方向键 ±1%、双击百分比直接输入；左侧条目的百分比和中心的「已分配」同步更新；保存后期望版本下拉里多出一个新版本；点环图扇区展开对应条目 |
| 用例 · 各配置表现 | 点配置名设为当前配置；分组（按模型 / 努力 / 技能基底）；排序；「显示其余 2 个配置」；勾选两个配置后「对比」（弹出提示）；点色块进入对话页，并带上该格的变体和配置；「全部 48 段对话 →」 |
| 对话 | 面包屑或「←」返回用例页；下拉筛选，每项带分面计数；「显示」被隐藏的变体；单击一行在阅读区查看；勾选两段后点「并排对照」；键盘 ↑↓ 切换、空格勾选、Enter 进入复核（原型里只弹提示） |

示例数据：8 个被测配置（2 个模型 × 3 档努力 × 基底 base-1024，加上 2 个使用旧基底 base-1020 的配置），每个配置 × 3 个变体 × 2 次，共 48 段对话。F1 权重 67%，E1 权重 33%，命中否决项的会话分记 0。指标条、色块和对话页的数字都由同一份对话数据算出。

原型中的样式：
- 用例页和对话页的样式取自设计系统 `bundle.css` 的「用例页 v3」一节；
- 侧边栏外壳只在 `.rv-app--side` 下生效；
- 支持深色模式。
