# 用例页重构方案：概览与对话拆页

版本：v1（2026-10-27）· 基线：`main` c5d76e9（doc/10 步骤 2–4 已落地）· 状态：方案，待实施

原型：设计系统中的「用例概览（重排）」`CaseOverview` 和「用例的对话页」`CaseConversations` 两张页面卡片。卡片样式已并入设计系统的 `bundle.css`，标注为「用例页重排（doc/13）」。

## 1. 现状分析

`/case/{case_id}`（`scoring/serve.py` 的 `case_detail`，模板 `scoring/templates/case.html`）目前是四张卡片从上往下排：

| 顺序 | 卡片 | 内容 | 问题 |
| --- | --- | --- | --- |
| 1 | 信息（`.rv-caseinfo`） | 维度、主题、变体数、可回答、对话方式、关键条件、知识注入、标签 | ① 维度、主题在标题行里已经出现过一次。② 「关键条件」把前提和路径又写了一遍（期望卡里也有）。③ 编译行里真正的条件槽位 `conditions`（槽位、取值、轮次、关键词）没有展示。④ 知识注入只写了注入点和选项，看不到原文和注入后的文字（`key` / `value`）。 |
| 2 | 期望 | 先列出全部用户轮次，再平铺全部前提、路径、事实，最后是参考答案 | ① 事实带有 `turn` 字段，但页面没有按轮次分组；多轮用例里分不清哪条期望对应哪一轮。② 没有展示证据 `evidence` 和备注 `note`。③ 历史期望版本用一排文字链接切换。 |
| 3 | 变体 | 每个变体一行：uid、变体序号、改写方式 | ① 看不到变体改写后的问句，没法比较改写效果。② 「查看对话 ↓」链到本页自身，点了没有反应。 |
| 4 | 对话 | 全部对话按比较轴分组列出，每行显示结论、`RunTag`、分数、条目判定和「复核」按钮 | ① 变体数 × 配置数 × trial 数，很快就有几十行，把上面三张卡片挤得看不见。② 不同配置的对话混在一起，页面上没有用例分，也没有按配置汇总。③ 后端支持 `axis` 参数，但页面上没有切换控件；`axis_values` 算出来了却没用上。④ 分数条被 `if false` 关掉了，同一个分数在一行里显示了两次。⑤ 每段对话都要单独查一次 `store.conclusion` 和 `store.effective_rows`，查询次数随对话数线性增长。 |

另外两个问题：页面上没有「被测配置」选择，而首页的用例分是按配置分别计算的，所以从首页点进详情后，两边的数字对不上；手机宽度下顶栏的「判定配置」下拉会撑出横向滚动条（这是 `base.html` 的问题，不在本页范围，但一并列出）。

## 2. 目标

1. 用例详情拆成两页：
   - **概览**：回答「这道题考什么、结果怎样」。
   - **对话**：回答「是哪几段对话、各自怎么判的」。
2. 概览页不再是纵向堆叠，而是**定义（左）与结果（右）并排**，下面一个通栏矩阵把两者连起来。
3. 两页共用标题行和子导航；被测配置的选择在两页之间保持一致，并且和首页使用同一个 `config` 参数。
4. 不改库表，不改判定和评分口径。只新增一个 `views` 聚合函数、一个预览片段接口和一个前端脚本。

## 3. 信息架构与路由

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `GET /case/{case_id}` | 概览 | 参数：`config`（被测配置，缺省时取首页的默认配置）、`judge_fp`（期望版本） |
| `GET /case/{case_id}/conversations` | 对话 | 参数见 §5.1；由概览页的子标签和矩阵格子链入 |
| `GET /case/{case_id}/conversations/preview?answer_id=…` | 预览片段 | 返回只读对话的 HTML 片段，供对话页右栏加载 |
| `GET /case/{case_id}?axis=…`（旧链接） | — | 302 跳转到 `/case/{case_id}/conversations?group=…`，保留旧的分组语义 |

首页用例表里的用例号链接要带上当前的 `config`。复核页「用例详情 →」链接带上该对话的配置（`views.config_value` 拼成的 key）。

两页共用的头部（新增宏 `case_head`）：

- **面包屑**：`用例 / {case_id}`。
- **标题行**：用例号（等宽字体）、维度 `KindTag`，以及一行 `rv-meta`：主题 · 粒度 · 可回答 · 对话方式 · 主口径 · N 个变体。
- **右侧**：期望版本下拉（替换现在的文字链接；只有一份期望时不显示），主按钮「复核待定 N 段 →」（N 为 0 时不显示），按钮链到 `/review?tab=undecided&case={case_id}`。复核队列需要支持 `case` 筛选，见 §6.1。
- **子导航**：`.rv-tabs`，分「概览」和「对话 N」两个标签。概览页右侧放「被测配置」下拉；对话页右侧显示「显示 x / y 段 · 当前筛选 · 清除筛选」。

## 4. 概览页

### 4.1 布局

```
┌ 面包屑 / 标题行 ─────────────────────────────── 期望版本 ▾  [复核待定 1 段 →] ┐
├ [概览|对话 12] ──────────────────────────────────────────── 被测配置 ▾ ───┤
│ ┌ 题面与期望（按轮） 1.7fr ───────────┐ ┌ 结果（sticky） 1fr ──────────┐ │
│ │ 第 1 轮  用户输入 / 该轮变体改写      │ │ 用例分 85.8 · 分数条           │ │
│ │          前提 P1 · 路径             │ │ 对话计数 · 各配置分数条        │ │
│ │ 第 2 轮  用户输入 / 改写             │ │ 难度 区分度 稳定性 题组一致 体检 │ │
│ │          F1 权重2 · E1 权重1 · X1 否决│ ├ 条件与注入 ──────────────────┤ │
│ │ 整段     （turn 为空的条目）          │ │ 槽位表 · 注入原文→注入后       │ │
│ │ ▸ 参考答案                           │ ├ 证据与说明 ──────────────────┤ │
│ └─────────────────────────────────────┘ └──────────────────────────────┘ │
│ ┌ 变体 × 被测配置（通栏） ──────────────────────────────────────────────┐ │
│ │ 行：种子 / V1 口语 / V2 诱导(不计分)   列：各配置   格：均分·点·分数条  │ │
│ │ 表尾：各配置用例分                                                     │ │
│ └───────────────────────────────────────────────────────────────────────┘ │
```

- 宽度 ≥ 1100px：两栏，`grid-template-columns: minmax(0,1.7fr) minmax(300px,1fr)`；右栏 `position: sticky; top: 60px`。
- 宽度 < 1100px：单栏，顺序为结果 → 题面与期望 → 条件与注入 → 证据 → 矩阵。DOM 顺序就按这个写，宽屏时用 grid 区域把结果卡放到右上。这样窄屏和读屏软件都能先看到结论。
- 矩阵超宽时，在 `.rv-table-wrap` 内部横向滚动，第一列固定（`rv-sticky-col`）。

### 4.2 左栏：题面与期望（按轮）

数据来自当前期望的编译行 `spec`。每个用户轮次（`spec.turns[i]`，`role == 'user'`）生成一块 `.rv-turnspec`：

- **左侧标签**：「第 i 轮」，下面一行小字：
  - 这一轮只有前提条目时，写「前提轮 · 不计分」；
  - 这一轮有计分条目时，写「计分轮」；
  - 其余情况不写。
- **用户输入**：`|md` 渲染，放在灰底块里。
  - 变体改写挂在被改写的那一轮下面，显示改写方式 `KindTag` 加改写后的文字。属于 `exclude_rewrites` 的改写方式（目前是「诱导」）注明「不计入维度分与题组一致」。
  - 改写文字取自各变体编译行的 `turns[variant.turn-1]`。`variant.scope` 不是 `turn` 时（例如整段改写），改写放到最后的「整段」块里。
- **条目**：依次列出这一轮的前提、路径、事实（`turn == i`）。每条一行，三列：`KindTag + id` | 文本 + 灰字说明 | 权重。
  - **说明**：关键词、组、证据来源。证据为 `external` 时写「资料外」，否则写证据 id。否决条件按 `policy.score.veto` 生成，例如「被采信即否决（会话分记 0）」或「判"错"即否决」。
  - **权重**：权重为 0 时显示「只记录」。禁止事实和路径在 veto 为 `zero` 或 `cap` 时显示「否决」，为 `weight` 时显示权重。
- **整段**：`turn` 为空的条目和整段改写放在最后一块，左侧标签写「整段」。单轮用例只有这一块时，不写「整段」标签，直接把用户输入和条目放在一起。
- **卡片标题**：右侧一行汇总，写「N 轮 · 计分条目 k · 权重合计 W · 否决项：…」。这些数和评分口径一致，可以直接核对会话分的分母。
- **参考答案**：放在 `<details>` 里，默认展开。答案超过 400 字时默认折叠。

### 4.3 右栏

**结果卡**（按选中的被测配置计算）：

- 用例分（大号数字）、`n`、「临时」标记和分数条（带及格线）。数据来自 `views.case_scores(cfg_rows)[case_id]`，与首页同口径。
- **对话**：「N 段 · 通过 a · 失败 b · 待定 c · 无效 d · 不计分 e（诱导）」。待定显示为 `rv-state`，点击跳到对话页，并带上 `status=undecided`。
- **各配置**：每个配置一条小分数条，当前选中的配置加粗。点击切换 `config` 参数。只有一个配置时，不显示这一行。
- 难度、区分度（模型数为 1 时写「— 只有 1 个模型」）、稳定性、题组一致：取 `views.question_stats` 中种子题的值，与首页用例表同口径。每个指标的 `title` 写 doc/09 中的定义。
- **体检**：沿用首页的四种标记。计算逻辑从 `cases()` 中抽出来，改为函数 `views.case_flags(rows)`，两页共用。

**条件与注入卡**：

- 槽位表（`spec.conditions`）：每行写槽位、取值，后面用灰字写轮次和关键词。
- 注入（`spec.injections`）：每个注入写成三行：
  - `J1` · 注入点 · 选项，后面跟文件名和 rev；
  - 原文 `key`，加删除线；
  - 注入后的文字 `value`，用禁止色底纹标出。

**证据与说明卡**：

- 证据（`spec.evidence`）：写 id 和来源（`skill / file / section`），`quote` 用引用块展示。
- 备注（`spec.note`）：`|md` 渲染。
- 标签：`tags` 的 `tag` 字段。

以上三张卡片中，某项没有数据时就不显示该项；一张卡片的所有项都没有数据时，整张卡片不显示。

### 4.4 通栏：变体 × 被测配置矩阵

- **行**：用例的全部题目（种子 + 各变体），按 `variant_index` 排序。
  - 行头写「种子 #0」或「V1 口语 · 第 1 轮」，第二行用小灰字写这个变体被改写那一轮的问句（截断成一行）。
  - 诱导行加「不计分」标记，行头文字变灰。
- **列**：全部被测配置（`configs_of(case_rows)`）。当前选中的配置列加浅色底。
- **格**：取 `views.question_scores(cfg_rows)[qkey]`，与首页同口径，只计主口径会话。格内显示：
  - 平均分（等宽字体）；
  - 每段对话一个点，实心表示通过或失败，空心表示待定，灰色表示无效；
  - 分数条；
  - 一行小字，写各段对话的分数，例如「2 段 · 89 / 94」。有待定时写「1 段已定 · 1 段待定（67–100）」；有否决时，在分数后注明否决项。

  整个格子是一个链接，指向 `/case/{id}/conversations?variant={uid}&config={key}`。
- **表尾**：各配置的用例分（非诱导变体等权平均），与结果卡一致。
- **非主口径**：这一列有非主口径的会话（例如 ec 的 natural 会话）时，在格子小字里加一句「另有 natural 2 段」，并链到对话页的 `mode=natural` 筛选。矩阵本身不混算两种口径。

### 4.5 取数（不再逐段查询）

概览页只用 `rows(request)`（`store.answer_view_rows`）里已有的列：`c_status`、`c_score`、`c_score_min`、`c_score_max`、`c_reason`，以及 run 属性。不再对每段对话调用 `store.conclusion` 和 `store.effective_rows`。

点上的 `title`（例如「第 2 次 · 54 分」）也用这些列生成。

## 5. 对话页

### 5.1 URL 参数（都可分享，缺省值不写进 URL）

| 参数 | 取值 | 缺省 |
| --- | --- | --- |
| `group` | `variant` / `config` / `run` / `none` | `variant` |
| `sort` | `pending`（待定在前）/ `score`（分数低在前）/ `time`（run 时间） | `pending` |
| `variant` | uid，可重复 | 全部非诱导变体 |
| `config` | 配置 key，可重复 | 全部 |
| `status` | `undecided` / `fail` / `pass` / `invalid` / `error`，可重复 | 全部 |
| `mode` | `natural` / `forced` | 全部 |
| `flag` | `human`（有人工改判）/ `broken`（会话失败或算子异常） | 无 |
| `sel` | 选中的 answer_id | 列表第一段 |

### 5.2 布局

```
┌ 公共头部（子导航选中「对话」，右侧「显示 8 / 12 段 · 清除筛选」） ───────────────┐
│ ┌ 筛选 208px ┐ ┌ 对话列表 1fr ───────────────────┐ ┌ 预览 0.85fr（sticky） ┐ │
│ │ 分组 ▾     │ │ 种子 #0 · 4 段                   │ │ ec-0201#1 · 第 2 次   │ │
│ │ 排序 ▾     │ │ [通过] uid 第1次 RunTag 条目 89分 │ │ [进入复核 →]          │ │
│ │ 变体 ☑☑☐   │ │ …                               │ │ RunTag · 待定原因     │ │
│ │ 配置 ☑☑    │ │ V1 口语 · 4 段                   │ │ 第 1 轮 …（只读）     │ │
│ │ 结论 ☑☑☑☑  │ │ …                               │ │ 第 2 轮 …             │ │
│ │ 其他 ☐☐    │ │ V2 诱导 不计分 · 4 段 · 已折叠    │ │ ↑↓ 切换 · Enter 复核  │ │
│ └───────────┘ └─────────────────────────────────┘ └──────────────────────┘ │
```

- 宽度 ≥ 1180px 时三栏；1180px 以下，预览移到列表下方；800px 以下单栏，筛选栏不再 sticky。
- **筛选栏**：选项是复选框加计数。计数在当前其他筛选条件下计算，也就是常见的分面计数。
  - 改动任何一项都会更新 URL 并刷新列表。实现上是服务端渲染整页；可以用 `fetch` 替换列表区域，先不做。
  - 「结论」各项前面放一个和矩阵相同的点，作为图例。
- **列表**：沿用 `ConversationQueue` 的行结构，左列从 96px 收窄到 72px。每行包含：
  - 结论徽标；
  - uid · 第几次；
  - `RunTag`；
  - 条目 `ItemChip`；
  - 右侧的会话分和分数条。待定时显示区间条（`rv-scorebar-range`）和「待判 n」。

  每个分组前加小标题（`.rv-cq-group`），写组名和段数。被筛掉的组（例如诱导）折叠成一行「4 段 · 已折叠 · 展开」，点击「展开」等于勾选该变体。
- **预览**：点击一行（不是点 uid 链接）时，选中该行（`aria-selected`）、更新 `sel` 参数，并用 `fetch` 加载预览片段。
  - 片段内容：标题、「进入复核 →」、`RunTag`（加上技能模式、已应用的注入），以及结论说明（待定原因或否决原因，取 `conclusions.reason`）。
  - 下面是逐轮的只读对话（复用 `review.html` 的 `.rv-turn` 和 `.rv-msg` 结构，经 `|md` 渲染），每轮表头放该轮条目的判定 chip。
  - 预览不提供改判入口。
- **键盘**：`↑` / `↓` 切换选中行，`Enter` 进入复核页，`/` 聚焦筛选栏第一个控件。焦点在输入框里时，这些快捷键不生效。

### 5.3 取数

- 列表用 `rows(request)` 按筛选过滤。条目 chip 需要逐条的判定，改为**一次批量查询**：给 `store` 新增 `effective_rows_many(answer_ids, chain_sha)`，内部用 `IN (…)` 分批，每批 500 条，返回 `{answer_id: [eff]}`，替换现在的 N 次查询。
- 每页 50 段，超过时分页（沿用 `m.pager`）。分组小标题按当前页内的数据生成。
- 预览片段复用 `review_page` 的取数，抽成 `_review_ctx(answer_id)`，复核页和预览共用，只是渲染不同的模板。

## 6. 代码改动清单

### 6.1 `scoring/serve.py`

- `case_detail` 拆成三部分：
  - `_case_ctx(request, case_id, judge_fp, config)`：公共取数，包括成员、种子、spec、历史版本、配置列表、当前配置、`case_rows`、标题行数据和待定数；
  - `case_overview`（`GET /case/{case_id}`）；
  - `case_conversations`（`GET /case/{case_id}/conversations`）。
- 新增 `case_preview`（`GET /case/{case_id}/conversations/preview`），返回 `_case_preview.html` 片段。
- 旧参数 `?axis=` 跳转：`axis=profile` 映射到 `group=config`，`axis=run_id` 映射到 `group=run`，其他取值映射到 `group=none`。
- `cases()` 中的体检计算抽成 `views.case_flags`；用例表链接带上 `config`。
- `review_queue` 增加 `case` 参数，并传给 `store.review_conversations(..., case_id=)`。后者和现有的 `run_id`、`dim` 一样，在 SQL 里加一个过滤条件。这个参数供「复核待定 N 段 →」使用。
- `_review_ctx` 从 `review_page` 中抽出，供预览复用。

### 6.2 `scoring/views.py`

- `case_matrix(case_rows, members, policy, configs) -> {"rows": [...], "cols": [...], "foot": {...}}`：对每个配置调用 `question_scores` 和 `case_scores`，再附上每段对话的点（状态、分数、trial、answer_id）。
- `spec_by_turn(spec, variants, policy) -> list[block]`：
  - 按轮组装用户输入、变体改写和条目；
  - 生成每条的说明文字（证据来源、否决条件）；
  - 计算卡片标题的汇总（计分条目数、权重合计、否决项）。

  这个函数是纯函数，便于单测。
- `case_flags(rows) -> dict[case_id, list[str]]`：从 `serve.cases()` 搬过来，逻辑不变。

### 6.3 `scoring/store.py`

- `effective_rows_many(answer_ids, chain_sha)`：批量版本，结果与逐条调用一致（单测对拍）。
- `review_conversations` 增加 `case_id` 过滤。
- 库表不变。

## 7. 测试

## 9. 留到后续

- **勾选两段对话并排查看**（doc/10 §3 已规划）：在对话页的列表行上加复选框，选满两段后，预览区改为左右两栏逐轮对照。这需要按轮对齐，变体之间的轮数可能不同，所以另行设计。
- **对话页筛选不刷新整页**：先用整页刷新，确认可用后再改为局部替换。
- **矩阵切换为通过率**：首页目前以平均分为主，矩阵先保持一致；如果需要，再加「均分 / 通过率」切换。

## 10. 需要确认的点

1. **概览页的默认被测配置**：建议与首页一致（`configs_of` 的第一个）。也可以改为「对话最多的配置」。
2. **对话页是否默认隐藏诱导变体**：建议隐藏，因为诱导不计分，评审时通常先看计分的变体。
3. **参考答案的默认展开阈值**：建议 400 字。
