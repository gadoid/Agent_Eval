# 用例页重构方案：概览与对话拆页

版本：v2（2026-10-27）· 基线：`feat/eval-gaps` d3c9310 · 状态：方案，待实施

原型：设计系统里的两张页面卡片，「用例概览 v2」`CaseOverview` 和「用例的对话页 v2」`CaseConversations`。卡片样式已并入设计系统的 `bundle.css`，分两节：

- 「feat/eval-gaps 新增」：原样取自该分支的 `scoring/static/bundle.css`。其中侧边栏外壳只在 `.rv-app--side` 下生效。
- 「用例页重排（doc/13 v2）」：本方案新增的样式。

> v1 的基线是 `main` c5d76e9。`feat/eval-gaps` 在用例详情页上已经加了不少能力：
> - 竖直侧边栏和配色切换；
> - 页头和用例体检；
> - 变体按钮组（切换时不刷新页面）；
> - 条目简要列表和详情下钻；
> - 权重饼图在线编辑，保存后生成新期望；
> - 勾选两段对话逐轮并排对照；
> - 执行记录、判定配置、期望版本可以命名。
>
> v2 的做法是保留这些能力，只调整它们在页面上的位置，再把对话拆成单独一页。v1 中「留到后续」的并排查看，这个分支已经实现了，本版直接沿用。

## 1. 现状分析（feat/eval-gaps d3c9310）

`/case/{case_id}` 对应 `serve.py` 的 `case_detail`、模板 `case.html` 和脚本 `case.js`（425 行）。页面从上到下是五块：

| 顺序 | 块 | 内容 | 问题 |
| --- | --- | --- | --- |
| 1 | 页头 `.rv-case-hero` | 面包屑；用例号；维度、主题、粒度标签；主口径；变体数和对话数；用例体检 | 期望版本、被测配置、「去复核」都不在页头，要往下翻才能找到 |
| 2 | 概览卡 `.rv-caseinfo` | 维度、主题、粒度、变体数、可回答、对话方式、关键条件、知识注入、标签、用例体检 | ① 维度、粒度、体检和页头重复。② 「关键条件」把前提和路径又写了一遍，期望卡里也有。③ 条件槽位 `conditions`、证据 `evidence`、备注 `note` 都没有展示。④ 知识注入只写了注入点和选项，看不到原文和注入后的文字 |
| 3 | 期望卡 | 提问全文；条目简要列表（截到 36 字），点「详情」在列表下方统一展开；右侧是 240px 的权重饼图编辑器 | ① 条目没有按轮次归组，多轮用例看不出哪条属于哪一轮。② 详情总在列表底部展开，离被点的那一行很远。③ 饼图占了卡片右半边，把左边的提问和条目挤窄了 |
| 4 | 变体卡 | 变体按钮组；选中的变体显示说明面板（对话数、待定、分数、提问全文、「查看该变体对话 ↓」） | ① 选种子时，提问全文和期望卡里的那份重复。② 变体的分数不分配置，不同配置的分数混在一起平均 |
| 5 | 对话卡 | 「全部 / 待定 / 异常」筛选；勾选两段并排对照；按比较轴分组的对话列表；并排对照区 | ① 段数等于变体数 × 配置数 × 次数，很快就有几十行，把前四块挤得看不见。② 页面上没有被测配置选择，详情页的分数和首页按配置算的分数对不上。③ 每段对话都单独查一次 `store.conclusion` 和 `store.effective_rows`，查询次数随段数线性增长 |

另外有两个属于全站外壳的问题，不在本页范围内，这里一并列出：

- 侧边栏在窄屏下仍然固定占 176px，手机宽度时正文区只剩 200px 左右。建议宽度 ≤ 640px 时，侧边栏收成顶栏。
- 在合成数据下截全页长图时，侧边栏的背景只到首屏高度。这是 `height: 100vh` 加 `position: sticky` 的效果，在浏览器里正常滚动看不出问题，可以不改。

## 2. 目标

1. 用例详情拆成两页：
   - **概览**：回答「这道题考什么、结果怎样」。
   - **对话**：回答「是哪几段对话、各自怎么判的」。
2. 概览页改为左右两栏，**左边是定义，右边是结果和工具**，下方一个通栏矩阵把两者连起来。
3. `feat/eval-gaps` 已有的交互全部保留，只换位置：
   - 变体按钮组；
   - 条目详情；
   - 权重编辑；
   - 并排对照；
   - 期望版本、执行记录的命名。
4. 被测配置的选择在两页之间保持一致，与首页使用同一个 `config` 参数。
5. 不改库表，不改判定和评分口径。

## 3. 信息架构与路由

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `GET /case/{case_id}` | 概览 | 参数：`config`（被测配置）、`judge_fp`（期望版本）、`variant`（变体按钮组的选中项，沿用现有参数）、`saved`（权重保存后的回显，沿用现有参数） |
| `GET /case/{case_id}/conversations` | 对话 | 参数见 §5.1 |
| `GET /case/{case_id}/conversations/peek?answer_id=…` | 预览片段 | 只读对话的 HTML 片段，供对话页右栏加载。命名上避开已有的 `POST /api/case/preview`（新建用例表单的知识预检） |
| `GET /case/{case_id}?axis=…` 或 `?pair=…`（旧链接） | — | 302 跳转到对话页。`axis` 换成 `group`；`pair` 原样带过去，对话页直接打开并排对照 |

首页用例表里的用例号链接，以及复核页的「用例详情 →」链接，都要带上 `config`。

### 3.1 页头（两页共用，新增宏 `case_head`）

在现有的 `.rv-case-hero` 上扩展，把原来的概览卡并进来：

- **左侧**：
  - 面包屑；
  - 用例号和三个标签（维度、主题、粒度）；
  - 一行 `rv-meta`：主口径 · 可回答 · 对话方式 · N 变体 · N 对话 · 待定 n；
  - 用例体检：沿用现有的 `views.case_health`，正常时显示「✓ 正常」。
- **右侧**（新增 `.rv-case-hero-side`）：
  - 期望版本下拉。显示命名后的标签，没有命名时显示 `evalset_version`；后面跟 ✎ 按钮，重命名沿用 `rename.js`。只有一份期望时不显示下拉。现在期望卡里的「切换期望版本」chips 移除。
  - 主按钮「复核待定 N 段 →」。N 为 0 时不显示。按钮链到 `/review?tab=undecided&case={case_id}`。
- **底部子导航**（`.rv-case-subnav`，有分隔线）：
  - 左边是 `.rv-tabs`，分「概览」和「对话 N」两个标签；
  - 右边：概览页放「被测配置」下拉；对话页显示「显示 x / y 段 · 当前筛选 · 清除筛选」。
- **权重保存回显**：保存权重后的提示（现有的 `saved` notice，含 `rejudge` 命令）放在页头下方、两栏上方，不再放在期望卡里。

## 4. 概览页

### 4.1 布局

```
┌ 页头：面包屑 / ec-0201 [维度][主题][粒度] / 口径·计数 / 体检 ─────── 期望版本 ▾ ✎  [复核待定 1 段 →] ┐
│ [概览|对话 12] ─────────────────────────────────────────────────────────── 被测配置 ▾ ───────┤
├────────────────────────────────────────────────────────────────────────────────────────────┤
│ ┌ 题面与期望 1.7fr ───────────────────────────┐ ┌ 右栏（sticky）1fr ─────────────────────┐ │
│ │ [全部 3][#0 种子][#1 口语•][#2 诱导] 变体按钮组 │ │ 结果：用例分 85.8 · 各配置分数条 · 统计 · 体检 │ │
│ │ 第 1 轮  提问 / #1 口语改写                    │ ├ 权重分配：饼图 132px + 滑杠 + 保存 ───────┤ │
│ │          前提 P1 [详情] · 路径 否决 [详情]       │ ├ 条件与注入：槽位 · 原文→注入后 ──────────┤ │
│ │ 第 2 轮  提问 / #2 诱导改写（不计分）            │ ├ 证据与说明：引用 · 备注 · 标签 ──────────┤ │
│ │          F1 67% [收起] ▸ 行内详情               │ └───────────────────────────────────────┘ │
│ │          E1 33% [详情] · X1 否决 [详情]          │                                             │
│ │ ▸ 参考答案（rv-fold）                           │                                             │
│ └─────────────────────────────────────────────┘                                             │
│ ┌ 变体 × 被测配置（通栏）：行=变体，列=配置，格=均分·每段一个点·分数条，表尾=用例分 ──────────────┐ │
└────────────────────────────────────────────────────────────────────────────────────────────┘
```

- 宽度 ≥ 1100px 时两栏：`grid-template-columns: minmax(0, 1.7fr) minmax(300px, 1fr)`，右栏 `position: sticky; top: 12px`。侧边栏本身已经 sticky，所以右栏的 top 不用再算顶栏的高度。
- 宽度 < 1100px 时单栏，顺序为：结果 → 题面与期望 → 权重分配 → 条件与注入 → 证据 → 矩阵。

### 4.2 左栏：题面与期望（按轮）

- **变体按钮组**：把现有的 `.rv-vtabs` 从变体卡移到这里，样式用小号（`.rv-vtabs--sm`）。现有的变体说明面板（`.rv-vfocus`）去掉，其中的分数和对话数由矩阵承担。
  - 选**全部**（默认）：用户输入显示种子的提问；每一轮下面列出改写了这一轮的各个变体（`#1 口语：…`）。属于 `exclude_rewrites` 的改写注明「不计入维度分与题组一致」。
  - 选**单个变体**：用户输入换成该变体的提问，被改写的那一轮左侧加强调色（`[data-rewritten]`）；其他变体的改写不再显示。
  - 切换时不刷新页面，沿用 `case.js` 现有的变体选择逻辑，URL 参数仍然是 `variant`。条目跟着期望走，不随变体变化；变体的期望与种子不同时，在按钮上标一个 `≠`。
- **按轮分块**：每个用户轮次一块 `.rv-turnspec`。
  - 左侧标签：「第 i 轮」，下面小字写「前提轮 · 不计分」或「计分轮」。
  - `turn` 为空的条目和整段改写，放在最后的「整段」块；单轮用例不写这个标签。
- **条目行**：保留现有的简要行（`.rv-facts-brief .rv-item`），内容是 `KindTag` + 截断文本 + 权重百分比 chip（`.rv-wpct-chip`，与饼图联动）+「详情」。禁止事实和路径在权重位置显示「否决」。
  - 点「详情」时，**在该行正下方**展开 `.rv-item-inline`，按钮变成「收起」。展开内容是全文、`note`（现有的「按权重计分；判『错』→ 总分 0」）、证据来源和关键词。
  - 同一时间只展开一条。点饼图扇区也触发同一个展开，沿用 `case.js` 的联动逻辑，只是改了展开的位置。
- **卡片标题汇总**：「N 轮 · 计分条目 k · 权重已分配 x% · 否决项：…」。
- **参考答案**：沿用现有的 `.rv-fold`。

### 4.3 右栏

1. **结果卡**：按选中的被测配置计算。
   - 用例分：取 `views.case_scores(cfg_rows)`，大号数字加分数条。
   - 对话计数：「N 段 · 通过 · 失败 · 待定 · 不计分」。
   - 各配置分数条：只有一个配置时不显示。
   - 四项题目统计：难度、区分度、稳定性、题组一致。
   - 体检。
2. **权重分配卡**：把现有的 `#weight-editor` 原样移过来。
   - 饼图从 240px 缩到 132px，图例和滑杠放在饼图右边（`.rv-pie-mini`）。
   - 「保存为新期望」和版本标签输入框放在卡片底部。
   - `data-qkey`、`data-fp`、`data-save-url` 和 `/api/case/weights` 接口都不变。
   - 当前期望没有计分条目时，整张卡不显示。
3. **条件与注入卡**：
   - 槽位表（`spec.conditions`）：槽位 · 取值，后面跟轮次和关键词。
   - 每个注入写成三行：`J1` · 注入点 · 选项（文件 · rev）；原文 `key`，加删除线；注入后文字 `value`，用禁止色底纹。
   - 这张卡取代原来概览卡里的「关键条件」和「知识注入」两行。
4. **证据与说明卡**：证据的 `quote` 用引用块；备注 `note` 经 `|md` 渲染；标签。

以上卡片中，某项没有数据时就不显示该项；整张卡都没有数据时，整张卡不显示。

### 4.4 通栏：变体 × 被测配置矩阵

| 部分 | 内容 |
| --- | --- |
| 行 | 每个变体一行，按 `variant_index` 排序。行头写「#0 种子」「#1 口语 · 第 1 轮」，与变体按钮组的叫法一致；第二行用小字写改写后的问句。诱导行标「不计分」 |
| 列 | 被测配置（`configs_of(case_rows)`），当前选中的配置列加浅底 |
| 格 | 均分，取 `views.question_scores(cfg_rows)[qkey]`，只算主口径；每段对话一个点（实心表示通过或失败，空心表示待定）；分数条；一行小字写各段分数、待定区间、否决项。整个格子是链接，跳到对话页并带上 `variant` 和 `config` 筛选 |
| 表尾 | 各配置的用例分（非诱导变体等权平均） |
| 非主口径 | 格内小字提示「另有 natural n 段」，链到对话页的 `mode=natural` 筛选；不混进均分 |

### 4.5 取数

概览页只用 `rows(request)`，也就是 `store.answer_view_rows`。这个视图里已经有 `c_status`、`c_score`、`c_score_min`、`c_score_max` 和 `c_reason`，概览页不再逐段调用 `store.conclusion` 和 `store.effective_rows`。

现在 `case_detail` 中的这几块逻辑原样保留，只是搬到 `_case_ctx`：

- 权重计算：`weight_map`、`weight_facts`，包括 `weight_percent` 和相对权重两种口径；
- 条目详情：`item_details`；
- 变体卡数据：`variant_cards`。

## 5. 对话页

### 5.1 URL 参数（缺省值不写进 URL）

| 参数 | 取值 | 缺省 | 说明 |
| --- | --- | --- | --- |
| `group` | `variant` / `config` / `run` / `none` | `variant` | 取代旧的 `axis` |
| `sort` | `pending` / `score` / `time` | `pending` | 待定在前 / 分数低在前 / 执行时间 |
| `variant` | uid，可重复 | 全部非诱导变体 | 取代变体按钮组的 `variant` 参数，这一页改为多选 |
| `config` | 配置 key，可重复 | 全部 | |
| `status` | `undecided` / `fail` / `pass` / `invalid` / `error`，可重复 | 全部 | 取代现有的「全部 / 待定 / 异常」chips |
| `mode` | `natural` / `forced` | 全部 | |
| `flag` | `human` / `broken` | 无 | 有人工改判 / 会话失败或算子异常 |
| `pair` | answer_id，最多两个 | 无 | 沿用现有参数；两个都有时直接打开并排对照 |
| `sel` | answer_id | 列表第一段 | 预览中的对话 |

### 5.2 布局

```
┌ 页头（子导航选中「对话」，右侧「显示 8 / 12 段 · 清除筛选」） ─────────────────────────────────┐
│ ┌ 筛选 208px ┐ ┌ 对话列表 1fr ─────────────────────────┐ ┌ 预览 0.85fr（sticky） ──────────┐ │
│ │ 分组 ▾     │ │ 勾选两段对话可并排对照 · 已选 1/2 [并排] │ │ ec-0201#1 · 第 2 次 [进入复核 →] │ │
│ │ 排序 ▾     │ │ #0 种子 · 4 段                         │ │ RunTag · 待定原因                │ │
│ │ 变体 ☑☑☐   │ │ [通过] ☐ uid 第1次 RunTag 条目 89分     │ │ 第 1 轮 …（只读，该轮条目 chip）   │ │
│ │ 配置 ☑☑    │ │ #1 口语 · 4 段 …                       │ │ 第 2 轮 …                        │ │
│ │ 结论 ☑☑☑☑  │ │ #2 诱导 不计分 · 4 段 · 已折叠 · 展开    │ │ ↑↓ 切换 · Enter 复核             │ │
│ │ 其他 ☐☐    │ │                                       │ │                                  │ │
│ └───────────┘ └───────────────────────────────────────┘ └──────────────────────────────────┘ │
```

- 宽度 ≥ 1180px 时三栏；1180px 以下，预览移到列表下方；800px 以下单栏。
- **筛选栏**（`.rv-rail`、`.rv-facet`）：每个选项是复选框加分面计数；改动后更新 URL，整页刷新。「结论」各项前面放一个和矩阵相同的点，作为图例。
- **列表**：沿用现有的行结构和 `.rv-cq-group` / `.rv-cq-group-head` 分组标题；左列从 96px 收窄到 72px。
  - 标题前保留勾选框（`.rv-pair-pick`），执行记录显示命名后的名称（`run_label`，悬停显示 run_id）。
  - 右侧显示会话分和分数条，待定时显示区间条。
  - 被筛掉的组折叠成一行，点「展开」等于勾选该变体。
- **并排对照**：沿用现有的 `.rv-pairbar`、勾选逻辑和 `pair_rows` 逐轮对齐。
  - 选满两段后，点「并排查看」时 URL 带上 `pair`。对照区（`.rv-pair-grid`）占满列表和预览两栏的宽度，上方有「返回列表」。
  - 现有的「最多两段」「被筛掉的勾选自动清除」规则不变。
- **预览**：单击一行（不是点 uid 链接，也不是点勾选框）时，选中该行并更新 `sel`，用 `fetch` 加载 `peek` 片段。
  - 片段内容：标题、「进入复核 →」、`RunTag`（含技能模式和已应用的注入）、结论说明（`c_reason`）、逐轮的只读对话（复用 `.rv-turn` / `.rv-msg`，每轮表头放该轮条目的 chip）。
  - 预览里不能改判。
- **键盘**：`↑` / `↓` 切换选中，`Enter` 进入复核页，`空格` 勾选或取消并排，`/` 聚焦筛选栏。焦点在输入框里时，这些快捷键不生效。

### 5.3 取数

- 列表：`rows(request)` 按筛选条件过滤。条目 chip 改为一次批量查询：新增 `store.effective_rows_many(answer_ids, chain_sha)`，内部按每批 500 条用 `IN (…)` 查询。每页 50 段。
- 并排对照：沿用现有 `case_detail` 里构造 `pair_data` 和 `pair_rows` 的代码，原样搬过来。
- 预览片段：从 `review_page` 中抽出 `_review_ctx(answer_id)`，复核页和预览共用。

## 6. 代码改动清单（基于 feat/eval-gaps）

### 6.1 `scoring/serve.py`

- `case_detail` 拆成以下几部分：
  - `_case_ctx(request, case_id, judge_fp, config)`：公共取数，包括成员、spec、历史版本、配置、`case_rows`、体检、页头计数、权重与条目详情；
  - `case_overview`：`GET /case/{case_id}`；
