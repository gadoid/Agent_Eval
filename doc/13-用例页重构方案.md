# 用例页重构方案：用例页 → 结果页（配置与对话）＋ 配置管理

版本：v4.1（2026-10-27）· 基线：`feat/eval-gaps` d3c9310 · 状态：方案，待实施

可交互原型：[`13-用例页原型.html`](13-用例页原型.html)，离线单文件，用浏览器直接打开即可。设计系统里有四张卡片，内容都来自这一份原型：

- `CasePrototype`：可交互的完整原型；
- `CaseOverview`：用例页；
- `CaseConversations`：结果页；
- `ConfigManage`：配置管理页。

**修订记录**

- **v1**：以 `main` 为基线，把对话拆成单独一页。
- **v2**：改以 `feat/eval-gaps` 为基线，保留这个分支已有的能力：变体按钮组、条目详情、权重饼图编辑、并排对照、命名。
- **v3**：重做视觉；对话移到下一层。
- **v3.1**：处理被测配置较多的情况。
- **v4**（本版），按评审意见调整为：
  1. **用例页只放对话以外的结构，结果只显示默认配置**：去掉配置表和配置分布，换成一行「默认配置的结果」。
  2. **各配置的结果和对话一起放进下一层「结果」页**：左侧是配置栏，右侧是对话列表和阅读区。
  3. **配置管理是独立页面**：侧边栏已有这个入口。在这里设定默认配置、给配置命名、按属性分组查看，以及勾选两个配置去对比。
  4. **补上 v3.1 评估中发现的数据问题**：
     - 配置名改用模型和努力程度来写；
     - 结果页只统计当前期望版本下的对话；
     - 单轮、单变体的用例要退化显示；
     - 显示样本数 n；
     - 页面状态写进 URL；
     - 权重编辑做成单独的编辑模式。
- **v4.1**：结果页按「配置 → 执行记录 → 采样」组织对话。去掉含义不清的「第 n 次」：一个配置下可能有多次执行，每次执行里都有「第 n 次」采样，原写法会让人分不清是哪次执行。新增 §4.4，说明属性栏各字段的来源。

## 1. 现状分析（feat/eval-gaps d3c9310）

`/case/{case_id}` 对应 `serve.py` 的 `case_detail`、模板 `case.html` 和脚本 `case.js`（425 行）。页面从上到下是五块：

| 顺序 | 块 | 内容 | 问题 |
| --- | --- | --- | --- |
| 1 | 页头 `.rv-case-hero` | 面包屑；用例号；维度、主题、粒度标签；主口径；变体数和对话数；用例体检 | 期望版本、被测配置、「去复核」都不在页头，要往下翻才能找到 |
| 2 | 概览卡 `.rv-caseinfo` | 维度、主题、粒度、变体数、可回答、对话方式、关键条件、知识注入、标签、用例体检 | ① 维度、粒度、体检和页头重复。② 「关键条件」把前提和路径又写了一遍，期望卡里也有。③ 条件槽位 `conditions`、证据 `evidence`、备注 `note` 都没有展示。④ 知识注入只写了注入点和选项，看不到原文和注入后的文字 |
| 3 | 期望卡 | 提问全文；条目简要列表（截到 36 字），点「详情」在列表下方统一展开；右侧是 240px 的权重饼图编辑器 | ① 条目没有按轮次归组，多轮用例看不出哪条属于哪一轮。② 详情总在列表底部展开，离被点的那一行很远。③ 饼图占了卡片右半边，把左边的提问和条目挤窄了 |
| 4 | 变体卡 | 变体按钮组；选中的变体显示说明面板（对话数、待定、分数、提问全文、「查看该变体对话 ↓」） | ① 选种子时，提问全文和期望卡里的那份重复。② 变体的分数不分配置，不同配置的分数混在一起平均 |
| 5 | 对话卡 | 「全部 / 待定 / 异常」筛选；勾选两段并排对照；按比较轴分组的对话列表；并排对照区 | ① 段数等于变体数 × 配置数 × 次数，很快就有几十行，把前四块挤得看不见。② 页面上没有被测配置选择，详情页的分数和首页按配置算的分数对不上。③ 每段对话都单独查一次 `store.conclusion` 和 `store.effective_rows`，查询次数随段数线性增长 |

另外有两个属于全站外壳的问题，不在本页范围内，这里一并列出：

- 侧边栏在窄屏下仍然固定占 176px，手机宽度时正文区只剩 200px 左右。建议宽度 ≤ 640px 时，侧边栏收成顶栏。
- 在合成数据下截全页长图时，侧边栏的背景只到首屏高度。这是 `height: 100vh` 加 `position: sticky` 的效果，在浏览器里正常滚动看不出问题，可以不改。

## 2. 目标

1. **三个页面，各回答一个问题**：
   - **用例页**（`/case/{id}`）：这道题考什么，默认配置下表现如何。
   - **结果页**（`/case/{id}/results`）：各配置分别表现如何，具体是哪几段对话、各自怎么判的。
   - **配置管理**（`/configs`）：有哪些被测配置，哪个是默认配置，怎么命名。
2. **用例页的主区只放结构**：题面与期望、属性栏，加一行默认配置的结果。不放配置表，也不放对话。
3. **保留 `feat/eval-gaps` 已有的交互**：提问切换、条目详情、权重编辑、并排对照、命名，只改位置和样式。
4. **只新增一张小表**：用来保存配置的名称和默认标记，见 §6.3。其余库表不变，判定和评分口径不变。

## 3. 信息架构与路由

```
侧边栏：用例管理 · 配置管理 · 执行记录 · 复核 · 结果对比 · 判定质量
用例管理 /
└─ ec-0201 /case/{id}                         用例页：结构 + 默认配置一行
   └─ 结果 /case/{id}/results?config=…&variant=…  结果页：配置栏 + 对话列表 + 阅读区
      └─ 复核页 /review/{answer_id}              改判（已有）
配置管理 /configs                               配置列表：默认、命名、分组、对比入口
```

**对话的归属层级**（与库里的字段一一对应）：

```
被测配置  config_key = CONFIG_ATTRS（profile · model · skills_mode · skills_base · evalset_version）
└─ 执行记录  run_id（runs 表；可命名 runs.title；有执行时间；可能标为「技能基底过期」stale_runs）
   └─ 对话  answer_id = {run_id}/{uid}-{mode}-t{trial}
            uid = 用例变体（#0 种子、#1 口语 …）；mode = natural / forced；trial = 本次执行内的第几次采样（runner --trials，默认 3）
```

- **一个配置可以有多次执行**：同一个配置重跑、补跑，都会新增执行记录，现有的配置管理页已经在「关联执行」列里列出多条。
- **用例分怎么算**：先在每个变体内，把该配置**所有执行**里有确定分数的对话取平均；再在非诱导变体之间等权平均。这就是现有 `question_scores` 和 `case_scores` 的做法，本方案不改口径。
- **n 是什么**：参与平均的对话段数，等于执行次数 × 采样次数 × 计分变体数，再去掉待定和无效的对话。
- **「采样 #n」是什么**：执行内部的采样序号，只在同一次执行里有意义。所以页面上一律写成「执行记录名 · 采样 #n」，不单独写「第 n 次」。

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `GET /case/{case_id}` | 用例 | 参数：`judge_fp`、`variant`、`saved`（沿用现有参数）。显示哪组结果由默认配置决定，没有配置参数 |
| `GET /case/{case_id}/results` | 结果 | 参数见 §5.1。默认选中默认配置 |
| `GET /case/{case_id}/results/peek?answer_id=…` | 阅读区片段 | 只读对话的 HTML 片段 |
| `GET /configs` | 配置管理 | 已有页面，扩展内容见 §5.4 |
| `POST /api/config/meta` | — | 新增接口，保存配置的名称和默认标记，见 §6.3 |
| `GET /case/{case_id}?axis=…` 或 `?pair=…`（旧链接） | — | 302 跳转到结果页 |

**默认配置**按下面的顺序确定：

1. 配置管理里设为默认的那个配置，前提是它在当前数据里存在；
2. 否则取 `configs_of` 返回的第一个，与首页现在的行为一致。

首页（用例管理）的用例分也用默认配置计算。首页现有的「被测配置」下拉保留，用来临时查看其他配置，但不改变默认配置。

**进入结果页的入口**：
- 用例页默认配置那一行的「各配置结果与对话 →」（选中默认配置）；
- 「全部配置共 n 段待定 →」（按待定筛选）；
- 复核页的「用例详情」链接（带上该对话所属的配置）。

**返回**：结果页的面包屑和「←」回到用例页；配置栏底部有「配置管理」的链接。

## 4. 用例页（第一层）

### 4.1 布局

```
用例管理 / ec-0201
ec-0201 进单资料审核                                                   期望版本 [权重调整 · a3f9c210 ▾] ✎
错误知识纠正 · 粒度 细节 · 主口径 forced · live 逐轮 · 2 轮 · 3 个变体 · 可回答
┌ 默认配置 ──────────────────┬ 用例分 ────────┬ 通过 ────┬ 待定 ──────────┬ 用例体检 ───────┬──────────────────────┐
│ glm-5.3 · high · base-1024 │ 86.6 临时 n=11 │ 11/12 段 │ 1 段            │ ● forced 前提…  │ [各配置结果与对话 →]  │
│ 在配置管理中更改             │                │          │ 全部配置共 2 段 → │                │  8 个配置 · 99 段     │
└────────────────────────────┴───────────────┴──────────┴────────────────┴────────────────┴──────────────────────┘
题面与期望  计分条目 2 · 权重已分配 100%    [全部|#0 种子 92.0|#1 口语 84.0|#2 诱导 不计分]  │ 权重分配（环图 + 滑杠）
 (1) 第 1 轮 …（时间线：提问气泡、改写行、条目行）                                       │ 条件 · 知识注入 · 证据
 (2) 第 2 轮 …                                                                       │ 备注 · 标签
 › 参考答案
```

- **页头**：与 v3 相同，不套卡片。
- **默认配置一行**（`.rv-cp-def`）：一个横条，格子之间用竖线分隔。
  - 默认配置：配置名，上方小字写「来自 k 次执行」，下面一行「在配置管理中更改」；
  - 用例分：分数，加「临时」标记和 n，下面一根带及格线的细条；
  - 通过：通过段数 / 计分段数；
  - 待定：默认配置下的待定段数，下面一行「全部配置共 n 段 →」；
  - 用例体检；
  - 右端是「各配置结果与对话 →」按钮，注明配置数和对话段数。

  只有一个配置时，按钮文字改为「查看对话 →」。
- **提问切换的分段控件**：每个变体按钮后面附上默认配置下的均分，及格的绿色、不及格的红色。这是用例页上唯一按变体给出的分数。
- **主体**：与 v3 相同，左边是题面与期望的时间线，右边是属性栏。

### 4.2 题面与期望（时间线，含退化规则）

沿用 v3 的写法：提问气泡、改写行、无边框的条目行（左侧用小图形区分类型，右侧是权重、「否决」或「门槛」，整行点击展开），参考答案默认折叠。

以下几种情况要**退化显示**（真实评测集里，单轮、单变体的用例占多数）：

| 情况 | 显示 |
| --- | --- |
| 单轮，或者所有条目都没有标轮次 | 不画编号圆点和竖线，直接显示「提问 + 条目列表」。v20261024-1 的 14 个用例里有 11 个属于这种情况 |
| 多轮，但只有部分条目标了轮次 | 标了轮次的条目归到对应轮次下；没标的放在最后的「整段」块里 |
| 只有种子，没有改写变体 | 不显示提问切换的分段控件 |
| 有不计分的改写方式（如诱导） | 按钮上标「不计分」。真实评测集里目前只有「口语」一种改写方式；原型里的「诱导」只是演示 policy 支持的能力 |

### 4.3 属性栏

与 v3 相同，各段从上到下：权重分配、条件、知识注入、证据、备注、标签。权重分配有两处变化：

- **增加编辑模式**：平时只显示环图和百分比，不能修改。点「编辑权重」后才出现滑杠、可以双击输入，按钮也随之出现：「保存为新期望」和「取消」。这样可以避免浏览时误拖。
- **保存后的状态**：页头的期望版本切换到新版本。由于新版本还没有判定结果，默认配置那一行改为显示「待重判」，并给出 `rejudge` 命令。不再拿旧期望的分数配新权重显示。

### 4.4 属性栏各字段的来源

属性栏里的字段都**不是运行结果**，全部来自用例 md 编译出的那一行：`md2case.py` 生成 `evalset/dist/*.jsonl`，导入后存在 `specs.spec_json` 里。字段随页头所选的期望版本切换。

| 字段 | 用例 md 写法（CASE-STRUCTURE.md） | 编译后的字段 | 说明 |
| --- | --- | --- | --- |
| 权重分配 | 事实行尾 `【权重：N】`（§2.9） | `facts[].weight`；在页面上编辑后写入 `weight_percent` | 不写时按 1。在页面上编辑会生成新的期望版本，原 md 不变 |
| 条件 | `## 关键条件`，每行可带 `【对象】【轮次】【关键词】`（§2.6） | `conditions[]`：`slot / value / object / turn / keywords` | 用于审阅和变体泄露检查，不参与打分 |
| 知识注入 | `## 注入` 写 `@注入点/选项`（§2.7）；注入点定义在 `knowledge/*.yaml`（§3） | `injections[]`：`id / point / option / rev / file / key / value` | 「原文 → 注入后」就是 yaml 里的 `key` → 所选选项的 `value`。每段对话实际有没有注入成功，看复核页里的注入观测，不看这里 |
| 证据 | `## 证据`（§2.11）：写 `@注入点`（原文取 key），或写 `skill:文件 / 章节 ｜ 原文：…` | `evidence[]`：`id / doc{skill,file} / section / quote` | 事实行用 `【证据：Rn】` 引用；写 `【外部】` 表示资料外 |
| 备注 | `## 备注`（§2.14） | `note` | 写给审阅人看，不参与评测 |
| 标签 | frontmatter 的 `tags`，加上所引用注入点的 `tags`，经 `mapping.yaml` 规范化（§4） | `tags[]`：`tag / from` | `from` 记录标签来自用例本身还是某个注入点 |

**唯一来自运行结果的是「用例体检」**，由 `views.case_health` 根据该用例的全部对话计算，所以放在默认配置那一行，不放在属性栏里。

## 5. 结果页（第二层）与配置管理

### 5.1 结果页的 URL 参数（缺省值不写进 URL）

| 参数 | 取值 | 缺省 | 说明 |
| --- | --- | --- | --- |
| `config` | 配置 key，或 `all` | 默认配置 | 左侧配置栏的选中项 |
| `run` | run_id，可重复 | 所选配置下的全部执行 | 执行记录筛选，提供三个快捷项：全部 / 每个配置只看最近一次 / 排除技能基底过期 |
| `group` | `run` / `variant` | `run` | 对话列表按执行记录分组（默认），或按变体分组 |
| `variant` | uid，可重复 | 全部计分变体 | |
| `status` | `undecided` / `fail` / `pass` / `invalid` / `error`，可重复 | 全部 | |
| `human` | `1` | 不限 | 只看有人工改判的对话 |
| `sort` | `pending` / `score` / `time` | `pending` | 待定在前 / 分数低在前 / 执行时间（新的在前） |
| `pair` | answer_id，最多两个 | 无 | 并排对照 |
| `sel` | answer_id | 列表第一段 | 阅读区当前显示的对话 |
| `cmp` | 配置 key，最多两个 | 无 | 配置栏里勾选的两个配置，用于跳转对比 |

### 5.2 结果页布局

```

[←] 结果  ec-0201 · glm-5.3 · high · base-1024 · 2 次执行 · 期望版本 a3f9c210   [对比选中的 2 个配置 →] [复核待定 2 段 →]
┌ 被测配置 290px ────────────────┐ (执行记录 全部2次 ▾)(变体 ▾)(结论 ▾)(人工 ▾)(分组 执行记录 ▾)(排序 ▾)  12/18 段 [并排对照 0/2]
│ [搜索配置，如 qwen high       ] │ ┌ 对话列表 340px ──────────────────┬ 阅读区 ────────────────────────────────┐
│ 共同：v20261024-1 · bundled…   │ │ glm high 复跑 · 10-26 14:03   6 段 │ #1 口语 · 采样 #2 · forced              │
│   全部配置  11 次执行 · 99 段    │ │ ☐ [84 通过]  #0 种子 · 采样 #1      │ glm-5.3·high·base-1024 · 执行记录        │
│ ☐ ★ glm-5.3·high·base-1024 86.6 │ │ ☐ [100 通过] #1 口语 · 采样 #1      │   glm high 基线 · 10-24 09:12           │
│     来自 2 次执行 · 18 段        │ │ glm high 基线 · 10-24 09:12   6 段 │ [67–100 待定 · 原因]                    │
│     n=11 · 临时                  │ │ ☐ [67–100 待定] #1 口语 · 采样 #2   │ 第 1 轮 … / 第 2 轮 …                   │
│     #0 89  #1 84  #2 58         │ │ ☐ [84 通过]  #0 种子 · 采样 #1      │                                         │
│ ☐ qwen-max·high·base-1024 90.7  │ │ #2 诱导 · 6 段未显示 · 显示          │                                         │
│     来自 2 次执行 · 18 段 · 含过期 │ └───────────────────────────────────┴─────────────────────────────────────────┘
│ 配置的名称与默认在「配置管理」设置 │
└────────────────────────────────┘
```

- **配置栏**（`.rv-rs-rail`，固定不随页面滚动）：
  - 顶部有排序（按用例分或按名称）、搜索框（可以输入多个词），以及「共同属性」一行。
  - 第一项是「全部配置」，其后是各配置，默认配置置顶并标 ★。
  - 每个配置一张卡片，内容是：配置名（只写差异属性，或者在配置管理里起的名字）；「来自 k 次执行 · m 段」，其中有技能基底过期的执行时加注「含过期」；用例分、n 和「临时」标记；最下面一行是各变体的均分小标签（及格绿、不及格红，诱导淡显）。
  - n < 3 时，n 下面加虚线，悬停提示「样本少于 3 段，分数仅供参考」。
  - 点卡片切换选中的配置，列表只显示该配置的对话。
  - 每张卡片前有勾选框，勾选两个后「对比选中的 2 个配置 →」变为可用，跳转到 `/compare?base=…&target=…`，并限定在这个用例上。
- **只统计当前期望版本**：配置栏的分数和对话列表都只包含页头所选期望版本下的对话。其他期望版本的对话在配置栏底部注明「另有 n 段属于其他期望版本」，点击可以切换期望版本。原因是评测集版本也是配置属性的一部分，不同期望下的分数不能排在一起比较。
- **对话区**：
  - 筛选、列表、阅读区、并排对照都沿用 v3。
  - 「被测配置」不再放在筛选下拉里，由左侧配置栏承担。新增「执行记录」下拉：列出所选配置下的各次执行，写明执行名、时间、段数和过期标记；切换配置时，执行记录筛选重置为全部。
  - 列表默认**按执行记录分组**，新的在前。组头写执行记录名、时间、段数（选「全部配置」时再加配置名），过期的执行加「技能基底过期」标记。行标题写「#1 口语 · 采样 #2」。改为按变体分组时，行标题写「执行记录名 · 采样 #2」。
  - 阅读区的标题写「#1 口语 · 采样 #2 · forced」，副标题写配置名、执行记录名（悬停显示 run_id）和执行时间；并排对照两栏的栏头写法相同。
  - 选中单个配置时，列表行不再重复写配置名；选「全部配置」时，每行写出配置名。
  - 筛选下拉的改动在关闭菜单时统一提交一次，不再每勾一个复选框就刷新一次。
- 宽度 < 1100px 时，配置栏排到对话区上方。

### 5.3 取数

- 配置栏：用 `views.case_scores` 和 `question_scores` 按配置分组计算，同时返回 n、各变体的均分，以及该配置的执行记录列表（`run_id`、命名、时间、是否过期）。只用 `answer_view_rows`，按页头所选期望版本（`current_judge_fp == judge_fp`）过滤。
- 对话区：与 v3 相同；另外按 `run` 参数过滤，按 `run_id` 分组。分组顺序取执行时间，即 `runs.started_at`，没有时取 `imported_at`。条目判定用批量查询 `effective_rows_many`，每页 50 段；阅读区复用 `_review_ctx`；并排对照沿用现有的 `pair_data` 和 `pair_rows`。

### 5.4 配置管理（`/configs`，扩展现有页面）

现有的页面只有一张跨用例的配置汇总表：profile、模型、技能方式、知识基底、期望版本、对话、待定、综合分、关联执行。扩展后：

| 区域 | 内容 |
| --- | --- |
| 工具条 | 搜索框（匹配配置名、模型、执行记录）；按差异属性分组（模型 / 努力 / 知识基底）；所有配置取值相同的属性不单独成列，写成一行「所有配置相同：…」 |
| 默认列 | 默认配置显示「★ 默认」，整行用强调底色；其余行显示「设为默认」按钮。全局只能有一个默认配置 |
| 名称列 | 可以命名，交互沿用 `rename.js`。没有命名时显示只含差异属性的名称；命名后，在名称下面用小字写出原属性名 |
| 属性列 | 只列差异属性。「努力」取自 profile content 的 `reasoning_effort`，与执行记录页（`_run_table`）的取法相同 |
| 统计列 | 对话、待定、综合分（带及格线的细条，口径与现在相同） |
| 执行记录列 | 列出该配置下的全部执行，每行一条：执行记录名 · 日期（悬停显示 run_id 和时间），过期的加「技能基底过期」标记。点击进入执行记录页 |
| 对比 | 每行有勾选框，勾选两个后「对比选中的 2 个配置 →」跳转到 `/compare`，范围是全部用例 |
| 分组时 | 组头写组内配置数和平均综合分 |

### 5.5 配置名

配置名按以下顺序取：

1. 在配置管理里起的名字；
2. 否则由**差异属性**拼成，用 · 连接。

差异属性的取法：
- 候选属性是模型（`models`）、努力（profile content 的 `reasoning_effort`）、技能方式、知识基底、评测集版本。不用 profile id，因为努力程度已经合进 profile id 里，直接显示是一长串字符。
- 在当前范围内（结果页是这个用例的全部配置，配置管理是全部配置），所有配置取值都相同的属性不写进名称，提到表头作为「共同属性」。
- 如果所有候选属性都相同、但 profile 不同，就用 profile id 兜底。

## 11. 可交互原型说明（`13-用例页原型.html`）

| 页面 | 可以操作 |
| --- | --- |
| 用例页 | 分段控件切换提问（按钮上是默认配置下的均分）；点条目行展开或收起；拖动或双击修改权重，再保存为新期望；「各配置结果与对话 →」进入结果页并选中默认配置；「全部配置共 2 段 →」进入结果页并按待定筛选；「在配置管理中更改」跳到配置管理 |
| 结果页 | 配置栏：点击切换配置、选「全部配置」、搜索（可输入多个词）、排序、勾选两个配置后对比（弹出提示）。对话区：「执行记录」下拉（快捷项：全部 / 每个配置只看最近一次 / 排除技能基底过期）、分组（执行记录 / 变体）、其他下拉筛选、「显示」被隐藏的变体、单击一行查看、勾选两段后并排对照、键盘 ↑↓ / 空格 / Enter。面包屑或「←」返回用例页 |
| 配置管理 | 侧边栏「配置管理」进入；搜索；按模型 / 努力 / 知识基底分组；「设为默认」（回到用例页可以看到默认配置那一行随之变化）；✎ 命名（命名后结果页和用例页同步显示新名称）；勾选两个配置后对比（弹出提示） |

**示例数据**：
- 8 个被测配置：2 个模型 × 3 档努力程度（知识基底 base-1024），另加 2 个用旧基底 base-1020 的配置。
- 共 11 次执行：3 个配置各有 2 次执行，其中 qwen-max · high · base-1024 的首跑标为技能基底过期；其余 5 个配置各 1 次。
- 每次执行 × 3 个变体 × 3 次采样（forced），共 99 段对话。
- F1 权重 67%，E1 权重 33%，命中否决项的会话分记 0。
- 配置管理里的综合分和对话段数是全局示例值；其余数字都由同一份对话数据计算得出。

原型里没有演示两项：权重的「编辑模式」（原型里滑杠一直可以拖动），以及单轮、单变体用例的退化显示。这两项按 §4.2、§4.3 实施。
