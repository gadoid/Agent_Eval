# 评测配置重构 · 变更设计（实施级）

版本：v1.1（2026-10-28）· 基线：`feat/eval-gaps` d3c9310 · 前置：[`14-评测配置重构方案.md`](14-评测配置重构方案.md)

14 号方案回答的是：六份配置怎么分，现有 73 项配置各归哪里，这样改值不值得。本文回答**具体怎么改**：

- 每张表的 DDL；
- 每个模块改哪个函数；
- 每个页面改哪一块；
- 每条命令怎么变；
- 迁移完怎么对拍。

分两期实施：**P1 指纹与计分**（先做），**P2 测法与执行**。

14 号方案 §11 的四个待定项，按评估结论采纳：

1. 模式由测法决定，手工指定模式的执行算诊断执行；
2. 改权重后，人工总分（`@total`）仍然有效，页面上加提示；
3. 被测指纹计入 agent（名称即 adapter）和版本；
4. 常规执行默认不跑诱导变体。

## 1. 目标状态：键与身份

| 对象 | 键（P1 后） | 怎么算 | 与现状相比 |
| --- | --- | --- | --- |
| 题目 | `qkey = uid \| input_fp` | `items.input_fp_of`，不变 | 不变 |
| 标准 | `standard_fp` | `items.standard_fp_of`：即现在的 `judge_fp_of` 去掉事实和路径里的 `weight` | 改名，并去掉权重 |
| 快照 | `evalset_version` + `snapshot_sha` | 见下文 | 新增 `snapshot_sha` |
| 测法 | `method_sha` | `method.yaml` 规范化后的哈希 | P1 由导入写入；P2 起 runner 也读取 |
| 被测配置 | `subject_fp` | 按 §3.1 的字段表计算规范化哈希，Python 和 TS 各实现一份 | 新增 |
| 条目计分口径 | `scoring_fp`（**按用例**；doc/17 §5.2） | md 口径 = canonical({uses, weights})，临时权重口径 = canonical({uses, temp}) | v9 起取代 weight_fp |
| 判定配置 | `chain_sha` | 不变 | 不变 |
| 计分规则 | `rules_sha` | `rules.yaml` 规范化后的哈希，注释和空白不影响结果 | 取代 `policy_sha` |
| 会话结论 | (`answer_id`, `standard_fp`, `chain_sha`, `rules_sha`, `scoring_fp`) | — | 键由 4 段变为 5 段（v9 起第五段为 scoring_fp） |

**规范化哈希**：统一取 `json.dumps(obj, sort_keys=True, ensure_ascii=False, separators=(",", ":"))` 的 sha256 前 16 位，风格同现有的 `_sha16`。Python 和 TS 各实现一份，用同一组测试数据对拍（§7.4）。

**`snapshot_sha` 只有一种算法**，导入和迁移两条路径都按它算：

```
canonical({
  "rows":    sorted([uid, input_fp, standard_fp] for 快照内每个题目),
  "scoring": {case_id: dist 行的 scoring 块}（doc/17 §3.2，编译时已归一）,
  "method_sha": method_sha
})
```

需要的数据，库里的 `spec_versions` 和 `snapshots` 表都有，所以迁移时能算出和导入时相同的值。

### 1.1 当前快照的解析

- **当前快照存在** `meta.current_snapshot`。
  - `specs import` 导入完成后，把它设为刚导入的版本，与现在「导入即设为当前」的行为一致。
  - `snapshot use <version>` 可以把它改成别的版本。
- **每个请求所用的快照 S**：URL 里有 `?snapshot=` 就用它，否则用 `meta.current_snapshot`。
- **某题在 S 下的标准**：
  1. S 等于当前快照，且这一题 `questions.off_snapshot = 1` 时，取 `questions.current_standard_fp`。这是逐题偏离快照的实验。
  2. 其他情况，取 `spec_versions` 中 (`qkey`, S) 对应的 `standard_fp`。
  3. 这一题不在 S 里：视为不活跃，不参与统计。
- **`specs set-current`**：只用于逐题偏离的实验，会把这一题的 `off_snapshot` 置 1。要恢复对齐，执行 `snapshot use`，它会把所有题目的 `off_snapshot` 清零。

### 2.4 权重的单位与有效权重（B2、S6）

- **单位**：`item_weights.weight` 一律用百分制。
- **未分配的部分不影响分数**：会话分 = Σ(权重 × 条目分) / Σ权重，会按权重总和归一化。页面上「未分配」只是显示，与现在的行为一致。
- **用例里权重的两种状态**：
  - **有权重**：这个用例的每个可计分条目都有有效行；
  - **无权重**：一行都没有，所有条目按 `rules.default_weight` 等权计分。

  不允许只有一部分条目有权重。
- **导入时换算**：
  - md 里写了【权重】的用例，在可计分条目（必要、期望）之间换算成百分制：`w_i / Σw × 100`，没写权重的条目先按 `default_weight` 参与这次换算；
  - 条目用途、权重换算与归一、未分配（合计 0% 跳过）、临时权重双口径：**全部按 doc/17 §2/§3/§5 执行**（md 是唯一数据源，dist 顶层 scoring 块，库内 case_scoring + temp_weights）。

- **启动参数**：`create_app(db, rules_path=None, operators_path=None, cases_dir=None)`。`--policy` 保留一个版本的别名，打警告后按计分规则加载。

- **`render()` 的上下文**：新增当前快照（版本号加测法摘要）和当前 `rules_sha` 的短码。`compare_delta` 不再从计分规则注入，对比页自己读页面参数（S7）。
- **`POST /api/case/weights`**：请求体改为 `{case_id, weights, label}`，**不再有 `qkey` 和 `judge_fp`**（B1）。保存后返回 `{weight_fp, conclusions}`，没有「待重判」这一步。

### 3.9 `evalset/method.yaml` 与 `evalset/md2case.py`（B5）

## 6. 迁移设计（v8，一个事务）

前置：先执行 `scoring backup`（命令已有）。

1. **建表**：新建 `snapshots`、`item_weights`、`rules` 和新的 `conclusions`；旧的 `conclusions` 改名为 `conclusions_legacy`。
2. **改写标准指纹**：
   - **`specs`**：逐行去掉 `spec_json` 里的权重，重算 `standard_fp`，按 (`qkey`, `standard_fp`) 合并。
   - **权重**：
     - 当前期望那份的权重写成有效行：`source = 'legacy'`，按 §2.4 换算成百分制；带 `weight_percent` 标记的，原值就是百分制，直接使用。
     - 被合并的其他行的权重写成无效行。
     - 同一用例的各变体，以**种子那一题当前期望**的权重为准，因为现在页面上只改种子；各变体权重不一致的用例写进对拍报告。
   - **`verdicts`**（B7）：多个旧版本合成一个时，**优先保留当前期望那一份**，其余丢弃；丢弃的行里结论或分数与保留行不同的，计数后写进对拍报告。
   - **`spec_versions`**：同步改写；**删除 `evalset_version = '权重调整'` 的行**（S3）。
   - 同步改写 `questions.current_standard_fp` 和 `reviews` 里 `@total` 行的 `item_sha`。
   - 把每个用例的 `weight_fp` 回填到 `questions.current_weight_fp`。
3. **回填被测指纹**：逐个执行记录调用 `subject_fp_of_manifest(snapshot_json)`，写入 `runs.subject_fp`、`subject_json`、`subject_incomplete`；再按执行记录给 `answers` 回填 `subject_fp` 和 `model`、`reasoning_effort`、`agent`。
4. **生成测法和快照**：
   - 由当前 `policy.yaml` 的 `headline_mode` 和 `exclude_rewrites`，加上 `runner/anchors.txt`，生成 `evalset/method.yaml`。格式为 `{"modes": {...}, "run_rewrites": [...], "anchors": [...]}`；其中 `run_rewrites` 取改写词表减去 `exclude_rewrites`，`anchors` 只保留各快照里确实存在的 uid。
   - 对库里每一个真实的评测集版本（**不包括「权重调整」**），按 §1 的算法计算 `snapshot_sha`，写进 `snapshots`。
   - 把最近一次导入的版本设为 `meta.current_snapshot`；当前指针和这个快照不一致的题目，`off_snapshot` 置 1。
5. **生成计分规则**：由 `policy.yaml` 生成 `rules.yaml`，在 `rules` 表里插入一行，`name = '迁移生成'`。
6. **全量重算**：执行 `rescore`，用新的 5 段键写入 `conclusions`。
7. **对拍（`migrate-verify`）**：
   - **逐段会话**比对新表和 `conclusions_legacy`：结论状态、分数、最低分、最高分、否决项、分数来源。
   - **全部聚合口径**都要比对：综合分、维度分、用例分、题目统计。
   - **允许的差异只有两类**，都要逐条列出原因：
     - B7 中被丢弃的、结论不同的判定行，只在用了模型算子时可能出现；
     - 第 2 步中「变体权重不一致」的用例，只在用户以前单独改过某个变体的权重时出现。
   - 其余差异，P1 必须为零。由于分数按 Σ权重 归一化，换算成百分制前后的分数相同。
   - 有差异时逐条列出，人工判断后重新验证。

**回滚**：SQLite 是单文件，用迁移前的备份整库还原即可。

## 7. 测试设计

1. **迁移对拍**（新文件 `tests/test_migration.py`），合成库里包含以下情况：
   - 同一题有几份只差权重的期望（断言合并正确）；
   - 带 `weight_percent` 标记的权重调整期望（断言有效权重正确承接）；
   - md 相对权重（断言换算成百分制后分数不变）；
   - 种子和变体权重不一致（断言出现在报告里）；
   - `@total` 人工总分（断言改权重后仍然有效，且提示的条件成立）；
   - 多个执行记录，profile、努力程度、技能基底、agent 版本各不相同（断言被测配置的分组数）；
   - 新旧 `run.json` 格式各一份（断言缺省值补齐后指纹相同，B6）；
   - 伪版本「权重调整」（断言没有为它生成快照）；
   - 机器结论合并时，当前期望那份优先（B7）。

   断言迁移前后的逐段结论和聚合结果完全一致，允许的差异除外。
2. **17 个场景的回归测试**：14 号方案 §3.4 表中每个场景一条，分别放在 `test_store`、`test_serve`、`test_cli` 中。重点场景：
   - #3：在用例页改权重后，**所有变体**都按新权重计分，机器结论不变；
   - #6、#7：profile 内容改了、agent 版本变了，被测指纹都会变；
   - #12：`operator_score = ignore` 时，不采信模型算子给的分；
   - #15：同一题、同一标准跨快照时，直接复用结论。
3. **导入时的权重**（B3）：初始值没变时，不覆盖手工修改；初始值变了时，覆盖并出现在报告里；加 `--keep-weights` 时不覆盖。条目删除、新增条目导致「权重不完整」、条目文字变但 id 不变，各写一条（S6）。
4. **当前快照的解析**（B4）：URL 参数、`meta` 和逐题偏离三者的优先顺序；`snapshot use` 会清除偏离标记。
5. **指纹稳定性**：
   - 标准指纹不含权重；
   - 无关字段（描述、超时）变了，被测指纹不变；
   - 只差 `approx` 或过期标记时，被测指纹不变。
6. **两端实现对拍**：用固定的测试数据 `fixtures/subject_manifest.json`，`scoring.subject.subject_fp_of_manifest` 和 runner 的 TS 实现（在 `runner/tests/` 下新增）必须算出相同的指纹。
7. **现有 202 个测试**：键名改动（`judge_fp` 改为 `standard_fp`，`policy_sha` 改为 `rules_sha`）影响到的断言集中改造；`compare` 改为传入 `delta` 参数后，相关的对比断言同步更新。

| 人工总分在改权重后仍然有效，可能被误读 | 页面固定显示提示文字；判定质量页列出「权重改在人工总分之后」的清单 |
| `policy.yaml` 别名期间，存在两处配置来源 | 别名只做转发，不单独解析；`rules` 表是唯一的事实来源 |
| 新导入的快照覆盖了手工改的权重 | 按 §3.5 的冲突规则处理，报告逐个用例列出；需要时加 `--keep-weights` |
| 历史上单独改过某个变体的权重 | 迁移时以种子那一题为准，差异写进对拍报告，由人确认 |

1. `item_weights.set_by` 记录评审人，和 `reviews.reviewer` 同一来源；
2. 对比页的变化阈值记在浏览器本地，不进入任何配置。
