# 条目计分与权重改造方案

版本：v1.3（2026-10-29，决定 16 落定：保存管线三点；开工实施）· 代码基线：`feat/eval-gaps` 44dd82e · 状态：实施中（P1 核心链路 → P2 保存管线 → §8/§9 收尾）

本文回答一个问题：**每个条目是否参与权重计算。** 由用例编写人在 md 里写，或在服务的用例页上逐条选择。

本文是计分与权重的唯一基线。凡与本文冲突的现有文档，按 §8.2 就地改写，不加修订注记。本方案按目标设计实施，不保留对现行实现的兼容层。

## 0. 已定事项

| # | 决定 |
| --- | --- |
| 1 | 每个条目二选一：**计分**（参与权重计算）或 **参考**（作为参考信息，不影响得分）。不再有触发、依据效果、复合用途 |

## 2. 条目用途

### 2.1 节点表（代码常量 `items.NODES`，全仓唯一来源）

| 节点 | kind | 缺省用途 | 可选用途 | 默认规则（与用途无关，§6） | 未决时进复核队列 |
| --- | --- | --- | --- | --- | --- |
| 前提 | precond | 参考 | 计分 / 参考 | 不成立 → 会话无效 | 进 |
| 路径 | path | 参考 | 计分 / 参考 | 违反 → 否决（forced 会话不判） | 进 |
| 拒答 | refusal | 计分 | 计分 | — | 进（无算子，人工判定） |
| 必要事实 | required | 计分 | 计分 / 参考 | 判错 → 否决 | 进 |
| 期望事实 | expected | 计分 | 计分 / 参考 | — | 仅计分且权重 > 0 |
| 禁止事实 | forbidden | 参考 | 计分 / 参考 | 采信 → 否决 | 进 |

进队列的判据是「未决会影响会话结论的区间」：权重 > 0 的计分条目影响分数；前提 / 路径 / 禁止 / 必要四类节点的默认规则在两点求值的不利一次触发（§6.3）。参考或权重 0 的期望事实对分数与区间都无影响，不进队列。现行 store「权重 0 一律踢出队列」的口径并入本规则：权重 0 但所在节点有默认规则的条目（如计分权重 0 的必要事实）仍进队列。

### 2.2 md 写法（样例实例）

```markdown
## 前提
- P1：2025 年 10 月出运的这单，保单号后三位填 500 【轮次：1】【计分】【权重：30】
- P2：第 1 轮识别为收汇记录场景 【轮次：1】

## 必要事实
- F1：2025 年 10 月出运的这单，保单号后三位应填 400 【轮次：2】【权重：70】
- F2：说明判断依据是出运时间 【轮次：2】

## 路径
- 必须：加载 skill trade-company 【轮次：1】
```

上例各条目的用途和权重（md 上的【权重】是名义百分比，决定 12）：

- P1：前提显式写了计分，权重 30%。
- P2：前提缺省为参考。
- F1：必要事实缺省为计分，权重 70%。P1 + F1 合计 100，归一后不变。
- F2：缺省为计分，但没填权重，所以是 0%。
- path#1：缺省为参考。

计分前提成立时恒得 100 分，其权重会等比压缩其余条目的分差（上例 30% 的前提意味着其余条目最多影响 70 分），慎给大权重；此写作指引随 §8.2 写入 CASE-STRUCTURE。

拒答没有条目行，它的用途固定为计分。拒答的权重写在 frontmatter 里，键为 `拒答权重`（同为名义百分比，参与统一归一）。这是唯一不写在条目行上的权重。拒答没有算子、只能人工判定（现行 operators.yaml），复核导读固定为「应说明依据资料无法回答，而非编造或泛泛拒答」。

### 2.3 check

**报错**：

- 同一条目同时写了【计分】和【参考】。
- 【参考】条目写了【权重】。
- 权重不是 0–100 的数，或小数超过四位。
- 拒答（`answerable: false`）用例写了必要事实或期望事实。

**提示**：

- 计分条目里有的写了权重、有的没写（没写的为 0%）。
- 计分条目（含拒答权重）的名义百分比合计不为 100：按比例归一，提示告知归一结果。
- 全部计分条目都没有权重（未分配 100%，见 §4）。此提示对进入 dist 的状态给出，draft / retired 不提示（决定 14）。
- 拒答用例没写 `拒答权重`，且没有其他计分条目带权重：同样属于未分配，评测时会跳过。

## 3. 编译与归一

### 3.1 归一时机

**md2case 编译时归一。** 节点缺省用途是代码常量，编译时就能确定每个条目的用途，不需要读取任何服务端配置。归一从导入时（store 的换算）前移到编译时，服务端不再做任何权重换算。

- 范围：用途为计分的条目，含拒答。
- 方法：wᵢ / Σw × 100，落 4 位小数。md 上的权重是名义百分比，合计不为 100 时同样按此式归一。
- 没填的条目为 0。
- Σw = 0 时全部为 0，并标记为「未分配」。
- 组：同组成员先统一取组内最大值，按一个计分单位参与归一，归一后每个成员记同一个百分比（成员在 md 上写了不同值时亦然）。

### 3.2 编译产物（样例实例）

```json
"scoring": {
  "items": {
    "P1": {"use": "score", "weight": 30.0},
    "P2": {"use": "ref"},
    "F1": {"use": "score", "weight": 70.0},
    "F2": {"use": "score", "weight": 0.0},
    "path#1": {"use": "ref"}
  },
  "unassigned": false
}
```

- 所有条目都会列出，包括取缺省值的。服务端不再推导用途，导入后原样落库。
- dist 行的顶层键由 `weights`（md 原值）改为 `scoring`（本结构，含用途与归一结果）。
- `scoring` 不进入 `standard_fp`。改用途或权重只需要重新计分（rescore），不需要重新判定，人工改判全部保留。

## 4. 未分配权重（合计 0%）

| 位置 | 行为 |
| --- | --- |
| md2case check | 提示：「计分条目未分配权重，评测时将跳过」（对进入 dist 的状态给出，决定 14） |
| 用例页 | 权重区顶部显示提示条，标明未分配 100% |
| 执行 | runner 照常执行，不读取权重 |
| 评测服务（判定、计分） | 跳过该用例的会话：不调用算子，不进入复核队列，会话结论记为 `skipped`，原因为「权重未分配」 |
| 结果页、对比页 | `skipped` 单独计数并显示原因，不计入维度分和通过率 |
| 选用临时权重 | 如果临时权重已分配，就按临时权重评测，不跳过（§5） |

补齐权重后，被跳过的会话会被正常判定和计分，不需要重新执行。

draft / retired 用例不触达评测：build 默认 `--include structured,reviewed,admitted`，draft / retired 不进快照。

> 当前仓库的 20 个用例都还没有权重，实施时一次性补齐，见 §9。

## 5. 服务端修改用例

### 5.1 落盘规则

| 修改 | 写到哪里 | 之后 |
| --- | --- | --- |
| 新建用例 | md（现行） | 由用户执行 check、build、导入（现行） |
| 用例页修改条目用途、条目内容等 | md（`case_to_md` 回写） | 走保存管线（见下） |
| 编辑 draft / retired 用例 | 只写 md | 这两个状态不进 dist，不产生新快照、不导入；check 仍按 §2.3 执行 |
| 用例页修改权重：「保存到用例」 | md 上的【权重】，写入归一后的百分比 | 同上 |
| 用例页修改权重：「保存为临时权重」 | 数据库 `temp_weights` | 只重新计分，不动 md |

**保存管线（决定 11 + 16）**，按序执行：

1. 在内存中构造修改后的结构化用例，`case_to_md` 生成新 md 全文；
2. 对新 md 做完整校验（`md_to_case`，报错只针对被改用例返回）；**不通过就不落盘**，返回错误；
3. 校验通过 → 写回 md 文件；
4. build 生成**新版本** dist（版本号自动取号：`vYYYYMMDD-N`，N = 当天已有最大序号 + 1；进程内锁包住取号 → build → 导入；dist 按版本不可变）。不做单用例导入；build 中其余文件的解析错误按现行 CLI 行为中止（此时 md 已落盘、无新快照，报错原样返回）；
5. 现行整批导入（新版本设为当前快照，见下）；
6. **同步 rescore**：只重算会话结论，不调算子；
7. 返回「待重判 N 段」（产生了新 `standard_fp` 的题，rejudge 需调算子，不自动执行；页面沿用现行待重判提示）。

每次保存产生一个新快照版本；standard_fp 未变的会话复用已有判定与人工改判，只重新计分（`current_scoring_fp` 缓存列寻址，§7）。

保存触发的导入会把新版本设为**当前快照**：覆盖用户此前 `snapshot use` 的选择，并清除逐题偏离（`off_snapshot`）实验。这是预期行为，页面保存前给出提示。

回写 md 后，如果标准内容变了（例如改了条目文本），就会产生新的 `standard_fp`，按现行流程重新判定。只改用途或权重时，`standard_fp` 不变，只重新计分。

### 5.2 临时权重（样例实例）

用例页的权重区：

| 条目 | 用途 | md 权重 | 临时权重 |
| --- | --- | --- | --- |
| P1 | 计分 | 30% | [ 50 ] → 50% |
| F1 | 计分 | 70% | [ 50 ] → 50% |
| F2 | 计分 | 0% | [ 0 ] → 0% |

按钮：「保存为临时权重」「保存到用例」「临时权重转正」（把临时权重写入 md，然后删除临时权重）。

开关：「评测使用：○ md 权重 ● 临时权重」。

拒答用例的权重区多一行「拒答」（用途固定计分），读 / 写 frontmatter 的 `拒答权重`，临时权重同样适用。

存储（每个用例至多一份临时权重，不留历史）：

```sql
CREATE TABLE temp_weights(
  case_id      TEXT PRIMARY KEY,
  weights_json TEXT NOT NULL,     -- {"P1": 50.0, "F1": 50.0, "F2": 0.0}，已归一
  in_use       INTEGER NOT NULL DEFAULT 0,   -- 1 = 评测使用临时权重
  set_by       TEXT,
  set_at       TEXT NOT NULL
);
```

规则：

- 临时权重只覆盖权重，不覆盖用途。只有 md 里用途为计分的条目（含拒答）可以填临时权重。
- 标准变化后，临时权重里已经不存在的条目会被忽略；新增的计分条目为 0%。页面会提示临时权重与当前条目不一致。
- 会话结论的键中，原来的 `weight_fp` 改为 `scoring_fp`：
  - 使用 md 权重时，取 `canonical({"uses": {条目: 用途}, "weights": {条目: 权重}})`——条目集与用途按当前标准解析（已不存在的条目忽略，新增条目按节点缺省用途、权重 0），与临时权重口径同形，两种口径可直接比较；
  - 使用临时权重时，取 `canonical({"uses": {条目: 用途}, "temp": weights})`。临时权重的生效配置是「md 用途 + 临时权重」，用途必须进指纹，否则改用途后旧结论会被误复用。
  两种口径的结论可以同时存在，对比页可以把它们当作两个口径直接比较。

## 6. 计分与默认规则

### 6.1 会话分

会话分 = Σ(权重 × 条目分) / Σ权重，只统计用途为计分、且权重大于 0 的条目。条目分按 `map` 计算；显式分只有必要事实和期望事实采信，**在代码中按 kind 强制**（其余节点一律 map，不依赖算子不产分的事实）。`map` 补上「成立 100 / 不成立 0」，使前提可以计分。

计分条目的分母为 0（计分单位全部「不适用」）时，会话结论记 `error`，原因为「计分条目全部不适用」，不再兜底满分。

### 6.2 默认规则（否决与门控）

| 规则 | 条件 | 结果 |
| --- | --- | --- |
| 门控 | 任一前提为「不成立」 | 会话无效，不计为答错 |
| 否决 | 任一路径为「违反」（非 forced 会话） | 按 `rules.yaml` 的 `score.veto_mode` 处理：zero 清零，cap 封顶 |
| 否决 | 任一禁止事实为「采信」 | 同上 |
| 否决 | 任一必要事实为「错」 | 同上 |

- 这些规则对所有条目生效，不管条目的用途是计分还是参考，也不管条目性质是客观还是主观。条目用途只决定它是否参与权重计算。
- 「判错」只指结论为「错」，不含「未提及」。
- 否决方式全局统一，配置为 `score.veto_mode: zero | cap` 加上 `score.cap`。原来按否决项分别配置的 `veto.*` 被删除，`weight` 模式也一并删除，因为现在由条目用途决定是否计分。

### 6.3 两点求值（修正 C5）

- 有利一次：未决条目一律视为不触发任何规则，条目分取 100。
- 不利一次：未决条目一律视为触发它所在节点的默认规则，条目分取 0。

否决检查统一走假想取值（含未决条目）。与现行行为相比，只有必要事实的否决发生了变化：未决的必要事实在不利一次里会触发否决。

### 6.4 短路与复核队列

在实际结论中（只看已判定的条目，不含假设值），如果有前提不成立，或者有否决以 zero 方式触发，会话结论就已确定。此时只有前提条目和已触发否决的条目进入复核队列，其余条目照常判定但不进入复核队列。

非短路时，进复核队列的未决 / 异常条目按 §2.1 末列：权重 > 0 的计分条目，或所在节点有默认规则的条目；参考或权重 0 的期望事实不进。

`rules.live_items()` 是这条规则的唯一实现，会话结论和复核队列都调用它。现行两处各自为政且已分叉的口径（复核队列对任何路径违反都短路、权重 0 一律踢出队列）一并并入，只留这一份。
